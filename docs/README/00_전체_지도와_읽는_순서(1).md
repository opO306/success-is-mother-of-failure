# 00. 전체 지도와 읽는 순서

*프로젝트가 복잡해진 지점부터 B의 새 구조까지 한눈에 보는 안내서*

| **\[문서 목적\]** 이 묶음은 “내가 만들고 있는데 내가 이해하기 어렵다”는 문제 제기 이후의 대화를 주제별로 다시 정리한 것이다. 물리 세계 자체를 단순화하는 것이 아니라, 목표와 구조를 사람이 이해할 수 있게 분리하는 데 초점을 둔다. |
|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|

# 이 문서 묶음의 핵심 결론

세계의 자유도와 표현력은 줄이면 안 된다. 줄여야 하는 것은 사람이 외워야 하는 관리 복잡도다. A는 세계 언어를 실행하는 엔진, B는 세계 언어를 읽고 쓰며 관찰·가설·실험·반례·우연을 다루는 연구 시스템으로 재정의한다.

```text
자연어 입력

↓

B 연구 시스템

↓ World Language

검증기 / 컴파일러

↓

A 세계 엔진

↓ State + Event Language

B 관찰·가설·실험

↺
```

# 권장 읽는 순서

| **문서** | **주제**                            | **읽으면 얻는 것**                                             |
|----------|-------------------------------------|----------------------------------------------------------------|
| 01       | 왜 프로젝트가 이해하기 어려워졌는가 | 복잡해진 원인과 “세계는 줄이지 말고 관리 구조를 줄인다”는 기준 |
| 02       | 원래 목표와 세계 언어               | 결과를 하드코딩하지 않고 법칙·상태·사건을 언어로 표현하는 방향 |
| 03       | A와 B의 역할 재설계                 | A는 실행기, B는 연구자·세계 설계자. 코드 직접 수정 권한은 분리 |
| 04       | B의 CPU/GPU 이중 탐색 구조          | 넓은 탐색과 깊은 분석을 분리하고 서로 결과를 주고받는 방식     |
| 05       | 가설·실패·우연을 다루는 연구 방법   | 틀린 가설을 버리지 않고 조건부 지식과 anomaly로 보존           |
| 06       | 기억 구조                           | 파라미터, SSD/HDD, RAM, VRAM을 서로 다른 기억 층으로 사용      |
| 07       | 자연어 없는 사고와 자모 수준 학습   | 생각을 자연어로 하지 않고 내부 세계 표현으로 처리하는 방향     |
| 08       | B0 구현·학습 로드맵                 | 기존 LLM을 한 기관으로 쓰며 실제로 무엇부터 만들어볼지         |

# 문서에서 사용하는 상태 표시

- 확정된 방향: 대화에서 현재 구조의 기준으로 삼기로 한 것.

- 설계 제안: 논리적으로 유망하지만 아직 구현·실험이 필요한 것.

- 검증 필요: 실제 코드·실험·학습으로 확인해야 하는 가설.

| **\[중요\]** 이 문서 묶음은 “완성된 이론”이 아니다. 앞으로 구현하면서 틀린 부분이 발견되면 수정하는 살아 있는 설계 기록이다. |

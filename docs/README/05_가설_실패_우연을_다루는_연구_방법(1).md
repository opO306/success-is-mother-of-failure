# 05. 가설·실패·우연을 다루는 연구 방법

*가설을 빨리 버리는 시스템이 아니라, 조건과 반례를 오래 보존하는 탐구 시스템*

| **\[핵심 수정\]** “잘못된 가설을 얼마나 빨리 버렸는가”보다 “어디에서 성립하고 어디에서 깨지는지, 깨진 사례가 새로운 조건이나 법칙으로 이어지는지”가 더 중요하다는 방향으로 바뀌었다. |
|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|

# 1. 가설을 True/False 하나로 압축하지 않는다

| **상태**               | **뜻**                                  |
|------------------------|-----------------------------------------|
| supported              | 현재 검사한 영역에서 관측이 가설을 지지 |
| contradicted_in_domain | 특정 검사 범위에서 예측과 충돌          |
| conditional            | 일부 조건에서만 성립                    |
| underspecified         | 현재 변수·언어가 부족해 판단 불가       |
| untested               | 제대로 검사되지 않음                    |
| superseded             | 더 넓은 가설이 이 가설을 포함           |
| incompatible           | 현재 세계의 절대 제약과 양립할 수 없음  |
| anomalous              | 기존 설명과 충돌하지만 반복 관측됨      |

특히 contradicted는 삭제와 다르다. “현재 이 조건에서는 틀렸다”는 기록은 나중에 새로운 변수나 조건과 만났을 때 다시 살아날 수 있다.

# 2. 불가능, 미관측, 반박을 구분한다

- locally impossible: 현재 상태와 절대 제약에서 불가능.

- globally impossible: 가능한 모든 관련 상태에서 불가능하다는 매우 강한 주장. 쉽게 붙이면 안 된다.

- not observed: 아직 관측하지 못했을 뿐.

- contradicted in tested domain: 검사한 범위에서 현재 가설 예측과 충돌.

- unsupported: 지지할 증거가 아직 부족.

| **\[이유\]** 현재 300번 실패했다는 사실은 “우주 어디에서도 불가능”과 같지 않다. 조건을 바꾸면 성립할 가능성을 연구 기억에 남겨야 한다. |
|----------------------------------------------------------------------------------------------------------------------------------------|

# 3. 연구 방법도 하나로 고정하지 않는다

| **연구 모드**      | **사용 방식**                                            |
|--------------------|----------------------------------------------------------|
| 가설 주도형        | 설명을 먼저 만들고 예측·반증 실험을 설계                 |
| 탐색형             | 설명 없이 넓게 돌려 이상치와 경계를 찾음                 |
| 반례형             | 현재 법칙이 깨질 수 있는 조건을 적극 탐색                |
| 재조합형           | 서로 무관해 보이는 실패·가설·조건을 조합                 |
| 실수/이상치 추적형 | 의도와 실제 실행이 달랐던 사례를 별도 연구               |
| 관찰형             | 개입 없이 장기간 패턴과 자연 발생 사건 관찰              |
| 역문제형           | 원하는/특이 결과가 나온 사례들의 공통 조건을 역으로 추적 |

# 4. 실수를 “학습”시키는 방법

실수를 의도적으로 만들도록 학습시키는 순간 그것은 실수가 아니라 랜덤 탐색이 된다. 대신 B에게 “의도와 실제 실행이 달랐을 때 그 차이를 기록하고, 예상 밖 결과를 자동 폐기하지 않는 태도”를 학습시킨다.

```text
ACCIDENT / ANOMALY RECORD


intended:

A + B, temperature=50


actually executed:

A + B + X, temperature=51


expected:

no stable structure


observed:

stable closure


next:

원래 조건 재현

오류 조건 재현

X 제거

X 양 변화

온도 오차만 재현
```

실험 조건 오류가 확인되면 원래 가설 검증 데이터로 쓰지는 않는다. 그러나 그 오류에서 나온 독특한 현상은 별도의 anomaly로 보존하고, 재현되면 새로운 가설 후보로 승격할 수 있다.

# 5. 현실 법칙과 충돌하는 결과를 다루는 층

기존 이론과 다르면 즉시 삭제하면 새로운 발견 가능성을 죽인다. 대신 논리·회계 같은 강한 제약과, 현재 알려진 모델을 구분한다.

| **층**                     | **취급**                                        |
|----------------------------|-------------------------------------------------|
| 논리·수학적 일관성         | 위반 시 먼저 상태/구현 오류 의심                |
| 세계의 강한 회계·인과 제약 | 위반 시 외부 유입·누락 변수·버그를 우선 검사    |
| 현재 알려진 물리 모델      | 충돌해도 즉시 폐기하지 않고 anomaly로 보존 가능 |
| B의 가설                   | 다양한 조건에서 지지·반박·조건부 상태로 갱신    |

| **\[중요\]** 가장 값진 데이터가 “99번 맞고 1번 틀린 사례”일 수 있다. 그 한 번이 새로운 자유도, 숨은 변수, WSL 누락, 구현 버그, 새로운 관계 중 무엇인지 조사하는 것이 B의 중요한 역할이다. |
|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|

*결과를 하드코딩하지 않고 세계의 법칙·상태·사건을 언어로 표현한다*

| **\[핵심 질문\]** “결과도 만든 언어로 나오게 할 수 있는가?”에 대한 답은 가능하다는 방향이다. 입력 명세만 언어로 만들고 결과는 Python 내부 상태로 끝내는 것이 아니라, 법칙·상태·사건을 모두 같은 세계 어휘 체계로 표현하는 구조를 목표로 한다. |

# 1. 결과표가 아니라 세계를 기술하는 언어

문제는 다음처럼 특정 결과를 언어에 직접 적는 방식이다.

```text
collision:

equal_energy: turn_right

unequal_energy: pass
```

이 방식은 간단하지만 세계가 미리 준비된 결과표 안에서만 움직인다. 반대로 목표는 질량, 운동량, 접촉, 에너지, 재료 성질, 공간 기하, 결합 상태처럼 결과를 만들어내는 조건을 표현하는 것이다.

```text
material:

mass

elasticity

bond_properties


space:

geometry

boundary


interaction:

contact

momentum_transfer

energy_transfer

conservation
```

# 2. World Language를 세 부분으로 나누는 제안

| **층**         | **역할**                         | **예시**                            |
|----------------|----------------------------------|-------------------------------------|
| Law Language   | 세계의 법칙과 허용 관계          | 질량, 접촉, 보존, 결합, 에너지 전달 |
| State Language | 현재 세계가 어떤 상태인지 표현   | 위치, 운동량, 구조, 온도, 점유 포트 |
| Event Language | 방금 무슨 변화가 일어났는지 표현 | 접촉, 전달, 결합, 절단, 상태 변화   |

```text
Law + StateBefore

↓

A 실행

↓

Event + StateAfter
```

이렇게 하면 B가 A의 Python 객체를 읽을 필요 없이 세계 언어만으로 관찰할 수 있고, 다른 세계나 다른 B와의 소통도 같은 어휘 체계를 사용할 수 있다.

# 3. 단단한 틀과 자유로운 내부 법칙

“틀을 단단하게 한다”는 것은 결과를 몇 가지로 제한한다는 뜻이 아니다. 오히려 커널이 절대 지켜야 할 외곽 제약을 강하게 만들고, 그 안에서 구체적인 물리 법칙은 언어로 다양하게 정의하도록 하는 방향이다.

- 선언되지 않은 상태나 자원은 갑자기 생길 수 없다.

- 같은 완전 상태는 같은 결과를 낸다. 결정론 라인에서는 숨은 난수를 허용하지 않는다.

- 공간적으로 접촉하지 않은 객체가 이유 없이 상호작용하지 않는다.

- 에너지·운동량·물질 회계는 선언된 외부 유입·유출을 제외하고 일관돼야 한다.

- ID, 배열 순서, thread 순서 같은 비물리 정보가 결과를 정하면 안 된다.

- 같은 자원·포트·에너지를 동시에 중복 소비하면 안 된다.

| **\[설계 제안\]** A는 “정답 결과를 아는 엔진”이 아니라 “World Language로 쓰인 세계 프로그램을 실행하는 엔진”이 되어야 한다. |

# 4. 현실 법칙을 구현한다는 목표와 단계적 확장

현실 전체를 처음부터 한 번에 구현하는 것은 현실적이지 않다. 대신 세계의 기본 상태와 관계를 일반적으로 두고, 필요한 자유도가 실제 모호성이나 한계로 드러날 때 하나씩 확장한다.

```text
초기 일반 상태

공간 / 위치 / 질량 / 운동량 / 에너지 / 접촉 / 결합


필요가 생기면 확장

회전 / 각운동량 / 탄성 / 변형 / 열 / 화학 퍼텐셜 / 전자기 ...
```

중요한 것은 각 확장이 특정 결과를 만들기 위한 편법이 아니라, 이전 언어로는 구분할 수 없었던 실제 물리 상태 차이를 표현하도록 만드는 것이다.

# 5. 기존 HPP 같은 규칙의 위치

정면충돌 시 90도 산란 같은 옛 격자 규칙은 “우주의 보편 법칙”으로 계속 확장할 필요가 없다. 특정 세계가 선택한 하나의 collision law로 남기고, 장기적으로는 더 일반적인 contact mechanics를 별도 세계 법칙으로 표현할 수 있게 만드는 편이 자연스럽다.

| **\[검증 필요\]** World Language가 실제로 “언어”인지 확인하려면 사람 대신 B에게 언어만 주고 세계를 만들게 했을 때, Python 코드를 건드리지 않고 충분한 상황을 표현할 수 있는지 시험해야 한다. |

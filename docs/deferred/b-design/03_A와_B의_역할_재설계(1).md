# 03. A와 B의 역할 재설계

**문서 분류: 후기 B 연구 자산 / 보존.** B는 취소·폐기하지 않았으며, A·L 기반의 작은 세계가 돌아가는 후기 단계에서 본격 개발한다. 기존 설계·구현·시험은 비교군/연구 자산으로 보존한다.
현재 상태는 [CURRENT_STATE.md](../../../CURRENT_STATE.md)를 본다.


*A는 세계 실행기, B는 세계 연구자·설계자*

| **\[핵심\]** B를 먼저 만들어보자는 아이디어는 “완성형 지능을 먼저 만든다”가 아니라, World Language를 실제로 사용하는 독립 연구자·세계 설계자를 먼저 만들어 언어의 구멍을 찾아내자는 의미로 정리됐다. |
|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|

# 1. A와 B의 기본 경계

```text
B

세계 설계 / 가설 / 실험 / 반례 / 해석

↓ World Language

Validator / Compiler

↓

A

상태 + 법칙 → 실제 상태 전이

↓ State / Event Language

B

관찰 / 해석 / 다음 제안
```

B가 A 커널을 직접 수정할 수 있게 하면, B가 자기 가설을 증명하기 위해 세계 자체를 바꾸는 문제가 생긴다. 따라서 B는 세계 언어를 제안할 수 있지만, A의 절대 제약과 실행 코드는 별도 경계로 보호한다.

# 2. B가 할 수 있는 것과 할 수 없는 것

| **가능**                   | **불가능/제한**                    |
|----------------------------|------------------------------------|
| 새 세계 명세 제안          | A 커널 직접 수정                   |
| 새 물질·법칙·초기조건 제안 | 보존 검사 임의 해제                |
| 실험 설계와 반례 생성      | 자기 제안을 자동 승인              |
| WSL 표현 한계 보고         | 검증기 우회                        |
| 가설 조합·수정·보존        | 결과를 본 뒤 과거 예측을 몰래 수정 |

# 4. 기존 LLM은 B 전체가 아니라 하나의 기관

초기 B에서 Qwen 같은 기존 LLM을 완전히 버릴 필요는 없다. 논문 읽기, 가설 생성, 설명, WSL 초안 작성처럼 언어·추론 능력이 필요한 부분에 사용하고, 물리적 판정은 Validator와 A 실행에 맡긴다.

```text
LLM: "이 법칙이면 가능할 것 같다"

↓

World Language로 구조화

↓

Validator: 보존/기하/권한 검사

↓

A: 실제 실행

↓

관측 결과로 다시 평가
```

이 구조에서는 LLM이 그럴듯하지만 틀린 말을 해도 그것이 곧 세계의 진실이 되지 않는다. LLM은 아이디어 생성기·번역기·설명기로 사용되고, 세계 가능성 판정은 별도 시스템이 담당한다.

# 5. B를 먼저 만드는 이유

- 사람은 문법의 빈틈을 머릿속 상식으로 자동 보완하지만, B는 WSL에 없는 것을 표현하지 못하므로 언어의 구멍이 드러난다.

- B가 “이 상황을 표현하려면 Python을 수정해야 한다”고 말하는 순간이 World Language의 확장 후보가 된다.

- A가 너무 단순해 연구할 문제가 없다면 B의 한계와 A의 한계를 구분하기 어렵다. 따라서 B와 A는 서로 발전을 밀어주는 관계가 된다.

| **\[B의 첫 시험\]** 새 생명을 만들어보라고 시키기보다, “이 World Language만 보고 표현할 수 없는 물리 상황을 찾아라”를 먼저 시키는 것이 언어의 독립성과 표현력을 검증하기 좋다. |

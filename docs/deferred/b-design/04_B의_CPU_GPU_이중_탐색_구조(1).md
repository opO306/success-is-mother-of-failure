# 04. B의 CPU/GPU 이중 탐색 구조

**문서 분류: 후기 B 연구 자산 / 보존.** B는 취소·폐기하지 않았으며, A·L 기반의 작은 세계가 돌아가는 후기 단계에서 본격 개발한다. 기존 설계·구현·시험은 비교군/연구 자산으로 보존한다.
현재 상태는 [CURRENT_STATE.md](../../../CURRENT_STATE.md)를 본다.


*넓은 조건 탐색과 깊은 인과 분석을 서로 다른 연구 방식으로 분리한다*

| **\[주의\]** CPU=직렬, GPU=병렬로 완전히 고정되는 것은 아니다. 여기서 CPU식/GPU식은 먼저 “깊은 탐색 / 넓은 탐색”이라는 연구 전략 이름으로 사용하고, 실제 하드웨어 배치는 나중에 최적화한다. |
|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|

# 1. Broad Explorer: 넓게 보는 연구

GPU에 잘 맞는 역할은 온도, 압력, 에너지, 재료, 기하, 구조 크기처럼 많은 조건 조합을 대량으로 실행해 경계와 이상치를 찾는 것이다.

```text
가설 H

├─ 조건 000001

├─ 조건 000002

├─ 조건 000003

├─ ...

└─ 조건 800000


찾는 것:

성공 영역 / 실패 영역 / 경계 / 희귀 anomaly / 반복 패턴
```

목표는 평균적인 성공률 하나를 얻는 것이 아니라, “어디에서 갑자기 행동이 달라지는가”와 “대부분과 다른 소수 사례는 무엇인가”를 보존하는 것이다.

# 2. Deep Investigator: 깊게 보는 연구

CPU식 심층 분석은 넓은 탐색이 발견한 특이점 하나를 가져와 조건을 하나씩 제거하거나 추가하고, 시간적 역사와 인과관계를 길게 추적한다.

```text
GPU 발견:

온도 83 / 재료 X / 길이 ≥ 7에서만 구조 closure


CPU 조사:

X 제거?

온도만 변화?

길이만 변화?

과거 충돌 역사 제거?

동일 조건 반복?

반사실 세계 비교?
```

# 3. 두 연구 뇌가 서로 먹이를 주는 순환

```text
Broad Explorer

↓ 이상치/경계

Deep Investigator

↓ 원인 후보

Broad Explorer

↓ 대규모 반증/범위 탐색

Deep Investigator

↓ 희귀 반례 확대

↺
```

이 순환을 Meta Controller가 관리한다. 아직 범위를 모르면 넓게 탐색하고, 반복되지만 이유를 모르는 현상이 생기면 깊게 분석하고, 원인 후보가 생기면 다시 넓게 반증하는 방식이다.

# 4. “적은 실험”이 목표가 아닌 이유

B의 목표는 실험 횟수를 최소화하는 것이 아니라, 충분히 다양한 조건에서 가설의 적용 범위와 깨지는 경계를 찾는 것이다. 1,000번이 필요하다면 1,000번 해도 되지만, 같은 조건을 1,000번 반복하는 것과 서로 다른 조건 축을 탐색하는 것은 가치가 다르다.

| **좋은 평가 기준** | **의미**                                          |
|--------------------|---------------------------------------------------|
| 탐색 범위          | 서로 다른 물리 상태를 얼마나 넓게 실제 시험했는가 |
| 경계 발견          | 성공↔실패가 갈리는 조건을 찾았는가                |
| 이상치 보존        | 희귀 결과를 noise로 버리지 않았는가               |
| 원인 분리          | 여러 조건 중 실제 원인 후보를 좁혔는가            |
| 재현성             | 같은 완전 상태에서 같은 현상이 반복되는가         |
| 전이성             | 다른 세계·배치에서도 관계가 유지되는가            |

# 5. 실제 하드웨어와의 연결

개념적으로는 Broad/Deep을 먼저 정의하고, 실제 실행에서는 Broad를 GPU·멀티코어·클러스터에 배치하고 Deep은 CPU 또는 긴 단일/소수 시뮬레이션에 배치할 수 있다. 일부 깊은 연산이 GPU에 적합할 수도 있으므로 역할과 하드웨어를 완전히 묶지는 않는다.

| **\[설계 제안\]** CPU뇌/GPU뇌는 “서로 다른 칩”이 아니라 “서로 다른 연구 인지 전략”으로 정의하고, 실행기만 상황에 맞는 하드웨어를 선택하도록 한다. |

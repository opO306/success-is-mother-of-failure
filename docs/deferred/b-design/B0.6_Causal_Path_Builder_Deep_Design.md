# B0.6 심화 설계 문서

**문서 분류: 후기 B 연구 자산 / 보존.** B는 취소·폐기하지 않았으며, A·L 기반의 작은 세계가 돌아가는 후기 단계에서 본격 개발한다. 기존 설계·구현·시험은 비교군/연구 자산으로 보존한다.
현재 상태는 [CURRENT_STATE.md](../../../CURRENT_STATE.md)를 본다.

## Causal Path Builder — 관찰과 개입 증거를 연결해 인과 지도를 만드는 단계

**문서 상태:** 구현 직전 심화 설계  
**선행 단계:** B0.4 Deep Investigator, B0.5 Mechanism Tester  
**목적:** B0.4의 관찰 결과와 B0.5의 개입 실험 결과를 연결하여, 근거를 추적할 수 있는 인과 관계와 인과 경로를 만든다.

---

# 1. B0.6을 한 문장으로 정의

> **B0.6은 이미 관찰하고 실험한 결과들을 연결해서 인과 지도를 만들되, 직접 확인하지 못한 순서는 만들지 않고, 모든 연결에 실제 근거와 성립 조건을 붙이는 단계다.**

B0.6은 새로운 세계를 만들지 않는다.

B0.6은 새로운 물리 법칙을 만들지 않는다.

B0.6은 아직 모르는 부분을 추측으로 채우지 않는다.

B0.6의 역할은 오직 다음이다.

```text
관찰된 변화
+
개입 실험 결과
+
시간 순서
+
성립 조건
+
반대 증거
        ↓
근거가 붙은 인과 연결
        ↓
여러 연결을 이어 만든 인과 경로
```

---

# 2. 이전 단계와의 관계

## B0.4

질문:

```text
두 세계가 어디서부터 달라졌는가?
```

하는 일:

- Trace 수집
- intervention이 만든 차이와 세계 반응 구분
- FirstResponseDivergence 발견
- 같은 phase 안에서 어떤 변화가 함께 일어났는지 기록
- MechanismCandidate 생성

B0.4가 주는 것은 주로 **관찰 증거**다.

## B0.5

질문:

```text
그 차이를 직접 조작하면 결과도 달라지는가?
```

하는 일:

- 실제 A에서 가능한 intervention인지 확인
- 경쟁 메커니즘의 예측이 갈리는 실험 설계
- 실험 실행
- SUPPORTS / CONTRADICTS / INCONCLUSIVE 증거 생성

B0.5가 주는 것은 주로 **개입 증거**다.

## B0.6

질문:

```text
그 관찰과 실험 결과들을 어떤 인과 구조로 연결할 수 있는가?
```

즉:

```text
B0.4
"이 순서로 변화가 관찰됐다."

+

B0.5
"이 부분을 바꾸니 결과도 달라졌다."

↓

B0.6
"그러면 여기까지는 인과 연결로 지지할 수 있다."
```

# 3. B0.6의 핵심 원칙

## 원칙 1 — 먼저 일어났다는 이유만으로 원인이라고 하지 않는다

```text
A
그 다음
B
```

가 관찰되었다고 해서 바로:

```text
A → B
```

라고 확정하지 않는다.

시간 순서는 인과 후보를 만드는 근거일 뿐이다.

## 원칙 2 — 직접 바꾸었을 때 결과가 달라지면 더 강한 근거다

예:

```text
heat = 2
break_heat = 2
→ bond break
```

그리고:

```text
heat = 2
break_heat = 4
→ bond 유지
```

가 실제로 관찰되었다면,

단순히:

```text
heat가 높아서 bond가 깨졌다
```

보다:

```text
heat와 break_heat의 관계가
bond break 여부에 영향을 준다
```

는 설명이 더 강한 근거를 가진다.

## 원칙 3 — 모르는 것은 모른다고 남긴다

B가:

```text
A
↓
???
↓
C
```

까지만 안다면 그대로 저장한다.

B0.6은:

```text
아마 B겠지
```

라고 중간을 채우지 않는다.

## 원칙 4 — 같은 순간에 일어난 것을 임의로 순서화하지 않는다

같은 engine phase 안에서 다음 세 변화가 함께 발생했다고 하자.

```text
heat 소비
bond 제거
particle 방출
```

현재 관찰 해상도로 이 세 사건의 내부 순서를 알 수 없다면:

```text
heat 소비
↓
bond 제거
↓
particle 방출
```

처럼 직렬화하지 않는다.

대신:

```text
        [bond-break phase event]
          /       |        \
         /        |         \
 heat 소비    bond 제거   particle 방출
```

처럼 하나의 공통 사건에서 함께 나온 결과로 표현한다.

## 원칙 5 — 모든 연결에는 근거가 있어야 한다

B가:

```text
A → B
```

를 저장했다면 반드시 다음 질문에 답할 수 있어야 한다.

```text
왜 그렇게 판단했는가?
어떤 관찰이 있었는가?
어떤 intervention 실험이 있었는가?
반대 결과는 없었는가?
어떤 조건에서만 성립하는가?
```

---

# 4. B0.6이 연결할 수 있는 대상

B0.6은 우선 다섯 종류만 연결한다.

```text
1. 조작한 것
2. 세계의 상태
3. 조건
4. 발생한 사건
5. 결과
```

## 4.1 조작한 것

사람 또는 B가 실험을 위해 바꾼 값.

예:

```text
break_heat = 4
heat_energy = 2
```

## 4.2 세계의 상태

A 안에 실제로 존재하는 상태.

예:

```text
heated_cell.energy = 2
target_bond.exists = true
particle.kinetic_energy = 3
```

## 4.3 조건

두 값 또는 여러 상태 사이의 관계.

예:

```text
heat >= break_heat
```

또는:

```text
local_density > threshold
```

조건은 A에 실제로 존재하거나, 기존 값들로 결정적으로 계산 가능한 관계여야 한다.

## 4.4 사건

A에서 실제로 발생한 변화.

예:

```text
bond_break
particle_release
energy_consumption
```

## 4.5 결과

연구가 관심을 두는 최종 상태.

예:

```text
bond survives
bond absent
division occurred
organism survived
```

---

# 5. 하나의 연결이 만들어지는 과정

B0.6은 바로 화살표를 확정하지 않는다.

다음 단계로 올라간다.

```text
후보
↓
지지됨
↓
강하게 지지됨
```

반대 증거가 나오면:

```text
반박됨
```

결과가 섞이면:

```text
아직 모름
```

으로 둔다.

---

# 6. 연결 상태

구현 이름은 개발자가 정할 수 있지만 의미는 다음처럼 고정한다.

## 후보

```text
시간 순서 또는 반복 관찰 때문에
인과 가능성이 있어 보임
```

하지만 intervention 근거가 아직 부족하다.

## 지지됨

```text
관찰 근거가 있고,
관련 변수를 직접 바꾼 실험에서도
예상 방향으로 결과가 변함
```

## 강하게 지지됨

```text
여러 독립 실험 또는 여러 조건에서
같은 관계가 반복적으로 지지됨
```

단, 절대적 진실이라는 뜻은 아니다.

## 반박됨

```text
관계를 검증하기 위해 설계한 실험에서
예측과 반대되는 결과가 반복적으로 나타남
```

과거 기록은 삭제하지 않는다.

## 아직 모름

```text
지지와 반대 증거가 섞여 있거나,
현재 실험으로 구분이 불가능함
```

---

# 7. 절대로 만들지 않는 상태

다음과 같은 상태는 만들지 않는다.

```text
PROVEN_FOREVER
ABSOLUTE_TRUTH
CERTAIN_CAUSE
```

새로운 조건이나 새로운 세계에서 기존 관계가 깨질 수 있기 때문이다.

---

# 8. 연결 생성 최소 조건

B0.6이 A → B 연결 후보를 만들기 위해서는 최소한 다음을 확인한다.

```text
1. A와 B가 실제 기록에 존재하는가?
2. A가 B보다 먼저이거나,
   적어도 A가 B와 독립적으로 조작 가능한가?
3. 같은 phase의 동시 결과를
   억지로 순서화하고 있지 않은가?
4. A와 B의 역할/대상이 일관되는가?
5. 이 연결을 뒷받침하는 evidence가 존재하는가?
```

하나라도 확인할 수 없으면 강한 인과 연결로 올리지 않는다.

---

# 9. 관찰 증거만 있는 경우

예:

```text
A가 항상 먼저 나타남
그 뒤 B가 반복적으로 나타남
```

그러면:

```text
A → B 후보
```

는 만들 수 있다.

하지만 상태는 후보에 머문다.

---

# 10. intervention 증거가 있는 경우

예:

```text
A 값을 직접 바꿈
↓
B 결과가 예상대로 변함
```

그리고 관찰 순서도 모순되지 않는다면:

```text
A → B
```

를 지지됨으로 올릴 수 있다.

---

# 11. 여러 번 반복해서 확인된 경우

예:

```text
Experiment 1 → 지지
Experiment 2 → 지지
Experiment 3 → 지지
Experiment 4 → 지지
```

그리고 조건도 서로 충분히 다르다면 강하게 지지됨으로 올릴 수 있다.

단순히 같은 world를 같은 seed로 네 번 반복한 것만으로는 독립적인 반복 증거로 과대평가하지 않는다.

---

# 12. 반대 증거가 생겼을 때

기존:

```text
A → B
지지됨
```

이었는데 새로운 실험에서:

```text
A를 바꿨지만 B가 변하지 않음
```

이 나왔다고 하자.

기존 연결을 삭제하지 않는다.

대신:

```text
support evidence += 기존 실험
contradiction evidence += 새 실험
```

을 기록한다.

그리고 상태를 필요하면 아직 모름 또는 반박됨으로 변경한다.

---

# 13. 모순은 오류가 아니라 연구 대상이다

두 실험이 충돌하면:

```text
Experiment 1:
A → B처럼 보임

Experiment 2:
A → B가 아님
```

B는 다음을 질문할 수 있어야 한다.

```text
두 실험에서 다른 조건은 무엇인가?
```

그 결과 나중에:

```text
C가 있을 때만
A → B
```

라는 더 정확한 조건부 인과관계를 찾을 수 있다.

---

# 14. 조건부 인과관계

B0.6은 다음 표현을 정식으로 지원해야 한다.

```text
A
↓
[조건 C일 때]
↓
B
```

예:

```text
heat
↓
[heat >= break_heat]
↓
bond break
```

이 구조가 중요하다.

---

# 15. 현재 heat 실험의 해석

실험 1:

```text
heat = 2
break_heat = 2

→ bond break
```

실험 2:

```text
heat = 2
break_heat = 4

→ bond 유지
```

B0.6이 만들면 안 되는 설명:

```text
heat = 2
→ bond break
```

더 적절한 설명:

```text
heat와 break_heat의 관계
        ↓
break 조건 만족 여부
        ↓
bond break 여부
```

---

# 16. 같은 phase 안의 원자적 사건

현재 B0.4에서는 같은 phase 안에서:

```text
heat 소비
bond 제거
particle 방출
```

이 함께 발생했다.

현재 관찰 수준에서는 세 내부 사건 중 무엇이 먼저인지 확정할 수 없다.

따라서 B0.6은 다음처럼 저장해야 한다.

```text
AtomicPhaseEvent:
    phase = AFTER_BOND_BREAK_PHASE

effects:
    - heat consumed
    - bond removed
    - particles released
```

그리고 근거 없는 내부 순서를 생성하지 않는다.

---

# 17. 공통 원인/공통 사건 표현

여러 변화가 같은 원자적 event에서 나온다면:

```text
        E
      / | \
     A  B  C
```

형태로 표현한다.

즉:

```text
E → A
E → B
E → C
```

는 가능하지만, 근거 없이:

```text
A → B → C
```

로 바꾸지 않는다.

---

# 18. 연결마다 붙여야 하는 근거

각 연결에는 최소한 다음 정보를 연결한다.

```text
관찰 evidence
intervention evidence
반대 evidence
반복 evidence
적용 조건
적용 domain
```

예:

```text
관계:
heat/break_heat condition
→ bond break

관찰:
B0.4 trace

개입:
B0.5 break_heat 2→4

반대:
없음

조건:
heat >= break_heat

domain:
현재 causal world / 해당 bond rule
```

---

# 19. 근거는 복사하지 말고 참조한다

B0.6은 B0.4/B0.5 데이터를 새로 복제하지 않는다.

다음처럼 기존 기록의 ID를 참조한다.

```text
trace_evidence_ids
mechanism_evidence_ids
experiment_ids
journal_entry_ids
```

목적:

- 중복 방지
- provenance 유지
- 나중에 원본 실험으로 역추적 가능
- 기록 불일치 방지

---

# 20. 경로 만들기

여러 연결이 이어질 수 있으면 하나의 경로를 만든다.

예:

```text
A → B
B → C
C → D
```

그러면:

```text
A → B → C → D
```

라는 경로 후보를 만들 수 있다.

단, 각 연결이 실제로 이어지는지 확인한다.

---

# 21. 경로를 이어도 되는 조건

A → B와 B → C를 연결하려면 최소한:

```text
1. 중간 B가 같은 의미인가?
2. 같은 대상/role을 가리키는가?
3. domain이 서로 호환되는가?
4. 시간 순서가 모순되지 않는가?
5. 조건이 서로 충돌하지 않는가?
```

를 확인한다.

---

# 22. 이름만 같은 상태를 같은 것으로 보지 않는다

예:

```text
World 1의 particle.energy

World 2의 particle.energy
```

라고 이름이 같아도 대상 role, domain, 조건이 다르면 같은 대상으로 합치지 않는다.

이름보다 의미와 적용 범위가 중요하다.

---

# 23. 경로 전체 상태

경로 전체가 각 연결보다 더 강한 상태를 가질 수 없다.

예:

```text
A → B = 강하게 지지됨
B → C = 지지됨
C → D = 아직 모름
```

그러면 전체:

```text
A → B → C → D
```

는 부분적으로만 지지됨이어야 한다.

> 사슬은 가장 약한 고리보다 강할 수 없다.

---

# 24. 부분 경로 허용

B0.6은 완전한 경로만 저장하지 않는다.

예:

```text
A → B → ?
```

또는:

```text
A → ? → D
```

도 저장할 수 있다.

이것은 실패가 아니다.

---

# 25. Missing Link

경로 사이가 비어 있다면:

```text
A → ? → C
```

형태로 명시한다.

여기서 `?`는 숨은 변수가 반드시 존재한다는 뜻이 아니다.

정확한 의미:

```text
현재 evidence만으로
A와 C 사이의 중간 경로를 설명할 수 없음
```

이다.

이 정보는 B0.7의 입력이 된다.

---

# 26. 순환 관계 처리

세계에서는 다음과 같은 관계가 실제로 존재할 수 있다.

```text
A → B → A
```

예:

```text
생명 행동
→ 환경 변화
→ 생명 행동 변화
```

따라서 B0.6은 원칙적으로 순환 구조 자체를 금지하지 않는다.

하지만 같은 순간의 동시 변화를 보고 순환 관계를 만들어서는 안 된다.

순환 관계를 허용하려면 각 방향에 별도의 시간적 또는 intervention evidence가 필요하다.

---

# 27. 반복 evidence 누적

같은 관계가 여러 번 나타난다고 매번 새 연결을 만들지 않는다.

예:

```text
heat condition → bond break
```

하나를 유지하고:

```text
support:
E1
E2
E3

contradiction:
E4
```

처럼 evidence를 누적한다.

---

# 28. 단순 횟수 투표 금지

다음처럼만 판단하지 않는다.

```text
지지 10회
반대 2회

→ 83% 진실
```

실험마다 조건과 질이 다르기 때문이다.

예:

- 같은 seed 반복
- 서로 다른 world 반복
- 직접 intervention
- 단순 관찰

은 같은 무게로 취급할 필요가 없다.

B0.6에서는 우선 evidence 종류를 구분해서 보존하고, 정교한 가중치는 후속 단계로 넘긴다.

---

# 29. Domain

모든 인과 관계는 어디에서 확인됐는지 저장한다.

예:

```text
현재 causal world
특정 material
특정 bond rule
특정 energy 범위
```

한 domain에서 확인된 관계를 모든 세계의 법칙처럼 일반화하지 않는다.

---

# 30. Domain이 다르면 관계도 분리 가능

예:

```text
Domain A:
heat >= break_heat → break

Domain B:
같은 조건에서도 break 안 됨
```

이면 기존 관계를 무조건 삭제하지 않는다.

대신:

```text
Domain A에서는 지지
Domain B에서는 반박
```

으로 기록한다.

이는 나중에 더 상위 조건을 찾는 근거가 된다.

---

# 31. 같은 연결의 조건 확장

처음에는:

```text
A → B
```

라고 생각했지만 새로운 실험에서 일부 조건에서만 작동한다고 밝혀질 수 있다.

그러면 관계를:

```text
A
↓
[조건 C]
↓
B
```

로 좁힌다.

과거 evidence는 버리지 않는다.

---

# 32. 경로 생성 시 금지사항

B0.6은 다음 행동을 하지 않는다.

```text
1. 시간 순서만으로 원인 확정
2. 같은 phase의 동시 사건을 임의 직렬화
3. evidence 없는 중간 대상 생성
4. 다른 domain의 결과를 자동 일반화
5. 반대 evidence 삭제
6. 이름만 같다고 대상 통합
7. 자연어 설명만 저장하고 원본 evidence를 잃음
8. observation을 intervention evidence처럼 취급
9. B0.6 편의를 위해 A에 새로운 물리 상태 추가
```

---

# 33. B0.6 데이터 구조의 의미적 요구사항

구현 이름은 개발자가 정한다.

하지만 최소한 다음 개념을 표현할 수 있어야 한다.

```text
인과 대상
인과 연결
인과 경로
조건
원자적 동시 사건
근거 묶음
경로 상태
비어 있는 연결
```

예상 구현 이름은 다음과 같을 수 있다.

```text
CausalNode
CausalEdge
CausalPath
CausalCondition
AtomicPhaseEvent
PathEvidenceBundle
PathStatus
MissingLink
```

이 이름 자체는 고정 계약이 아니다.

의미가 더 중요하다.

---

# 34. 인과 대상의 식별

각 대상은 결정적으로 식별 가능해야 한다.

동일 입력에서 동일 ID가 생성되어야 한다.

ID를 만들 때 최소한 다음 의미를 고려한다.

```text
type
role/subject
field/event
domain
condition context
```

실제 object ID 같은 실행별 임시 값에 지나치게 묶이지 않는다.

---

# 35. role 기반 의미 유지

B0.3/B0.4에서 확정한 role 기반 설계를 계속 유지한다.

예:

```text
heated_cell
target_bond
particle_a
particle_b
```

실제 ID가 world마다 달라도 연구 의미가 같다면 role을 통해 연결할 수 있어야 한다.

---

# 36. 결정론

B0.6 결과는 동일 evidence 입력에 대해 항상 동일해야 한다.

즉:

```text
same evidence
→ same nodes
→ same edges
→ same path
→ same canonical representation
→ same digest
```

이어야 한다.

---

# 37. canonical / digest

현재 deterministic 모듈 규칙을 유지한다.

B0.6에서 생성되는 주요 구조는:

```text
canonical()
digest
```

를 제공하는 방향이 좋다.

목적:

- 재현성
- journal 비교
- restart 후 동일 재구성
- evidence provenance

---

# 38. Journal

B0.6의 중요한 변화는 Research Journal에 남긴다.

예상 event:

```text
CAUSAL_EDGE_PROPOSED
CAUSAL_EDGE_UPDATED
CAUSAL_EDGE_CONTRADICTED
CAUSAL_PATH_CREATED
CAUSAL_PATH_UPDATED
MISSING_LINK_RECORDED
ATOMIC_EVENT_RECORDED
```

실제 이름은 기존 journal 스타일에 맞춘다.

---

# 39. Journal 재시작 후 재구성

B0.6의 첫 완성 기준 중 하나는:

```text
journal 저장
↓
프로세스 종료
↓
다시 로드
↓
동일 causal path 재구성
```

이 가능해야 한다.

재구성 후 digest도 동일해야 한다.

---

# 40. 첫 B0.6 검증 시나리오

기존 heat 실험을 그대로 사용한다.

## Baseline

```text
heat = 2
break_heat = 2
```

결과:

```text
bond break
```

## Intervention

```text
heat = 2
break_heat = 4
```

결과:

```text
bond 유지
```

---

# 41. 첫 시나리오에서 B0.6이 만들어야 하는 핵심 관계

B0.6은 최소한 다음 의미를 표현해야 한다.

```text
heat와 break_heat 사이의 조건
        ↓
bond break 여부
```

그리고 조건:

```text
heat >= break_heat
```

가 실제 evidence와 연결되어 있어야 한다.

---

# 42. 첫 시나리오에서 만들면 안 되는 관계

금지:

```text
heat=2 → bond break
```

를 모든 조건에서 성립하는 일반 법칙으로 저장.

왜냐하면:

```text
heat=2
break_heat=4
→ bond 유지
```

가 이미 존재하기 때문이다.

---

# 43. 같은 phase 사건에 대한 첫 시나리오 규칙

B0.4에서 확인된:

```text
heat 소비
bond 제거
particle 방출
```

은 같은 phase 안에서 발생한다.

따라서 B0.6 테스트는 이 세 사건을 임의로:

```text
heat 소비 → bond 제거 → particle 방출
```

순서로 저장하면 실패해야 한다.

대신 공통 phase event의 결과로 표현해야 한다.

---

# 44. 첫 시나리오 성공 조건

B0.6 첫 end-to-end 테스트는 최소 다음을 만족해야 한다.

```text
1. B0.4 observation evidence를 읽는다.
2. B0.5 intervention evidence를 읽는다.
3. 조건부 인과 연결을 만든다.
4. 연결이 기존 evidence ID를 참조한다.
5. heat=2 자체를 무조건 원인으로 일반화하지 않는다.
6. 같은 phase의 동시 사건을 임의 순서화하지 않는다.
7. canonical/digest가 결정적이다.
8. journal restart 후 동일 구조가 재구성된다.
```

---

# 45. 반대 evidence 테스트

추가 테스트에서는 기존 연결에 반대 evidence를 넣는다.

B0.6이 해야 할 것:

```text
기존 relation 삭제 X

support evidence 유지
contradiction evidence 추가
status 갱신
```

이 과정을 검증한다.

---

# 46. 조건 좁히기 테스트

처음:

```text
A → B
```

후보가 있었는데,

새 evidence에서 특정 조건에서만 작동함이 발견되면:

```text
A
↓
[조건 C]
↓
B
```

로 좁힐 수 있어야 한다.

과거 evidence는 그대로 연결한다.

---

# 47. 모르는 경로 테스트

예:

```text
A와 C 사이에 관계는 보이지만
중간 B를 확인할 수 없음
```

B0.6은:

```text
A → ? → C
```

또는 이에 대응하는 missing-link 구조를 만들 수 있어야 한다.

가짜 중간 대상을 만들면 실패다.

---

# 48. B0.6에서 하지 않는 것

다음은 아직 B0.6 범위가 아니다.

```text
숨은 변수 자동 발견
새로운 관측 센서 자동 생성
장기 나비효과 탐색
복수 세계의 고급 일반화
정보가치 기반 자동 연구 전략
생명체 진화 해석 전체
완전한 causal graph optimization
```

---

# 49. B0.6 종료 조건

다음이 가능하면 B0.6은 완료로 본다.

> B0.4와 B0.5가 만든 실제 evidence를 사용해,
> 조건과 적용 범위를 가진 인과 연결을 만들고,
> 여러 연결을 인과 경로로 조립하며,
> 같은 phase의 동시 사건이나 아직 모르는 구간을 억지로 설명하지 않고,
> 모든 판단을 원본 evidence까지 역추적할 수 있다.

---

# 50. B0.6 이후

다음 단계는 B0.7이다.

B0.7의 핵심 질문:

```text
현재 만든 인과 경로에서
설명되지 않는 빈칸은 왜 존재하는가?
```

예:

```text
A
↓
?
↓
C
```

B0.7은 이 `?`를 연구 대상으로 삼는다.

즉:

```text
B0.3
어디가 이상한가?

B0.4
어디서부터 달라졌는가?

B0.5
그 차이가 실제 원인인가?

B0.6
검증된 관계를 어떻게 연결할 것인가?

B0.7
연결되지 않는 빈칸에는 무엇이 있는가?
```

---

# 51. 설계자 관점에서의 최종 확인 질문

B0.6 구현을 검토할 때 기술 세부사항보다 다음 질문만 보면 된다.

```text
1. B가 근거 없이 화살표를 만들고 있지 않은가?

2. 같은 순간에 일어난 것을
   멋대로 앞뒤 순서로 만들고 있지 않은가?

3. 모르는 부분을 모른다고 남길 수 있는가?

4. 특정 조건에서만 성립하는 관계를
   모든 상황의 법칙처럼 일반화하지 않는가?

5. 반대 결과가 나왔을 때
   과거 기록을 지우지 않는가?

6. 모든 연결에서
   "왜 이렇게 판단했나?"를 원본 실험까지 따라갈 수 있는가?

7. 같은 evidence를 다시 넣었을 때
   같은 인과 지도가 나오는가?
```

이 일곱 가지가 만족되면 상위 설계 의도는 제대로 지켜지고 있다고 볼 수 있다.

---

# 52. 구현자에게 전달할 최종 계약

다음 의미를 만족하도록 현재 코드 스타일에 맞게 구현한다.

```text
- B0.4의 trace / divergence evidence 재사용
- B0.5의 intervention / mechanism evidence 재사용
- 기존 journal / provenance 재사용
- role 기반 대상 식별 유지
- 결정론적 canonical / digest 유지
- evidence 없는 causal edge 금지
- 동일 phase 동시 사건의 임의 ordering 금지
- conditional causal relation 지원
- contradiction evidence 보존
- missing link 표현 지원
- domain 범위 보존
- journal restart 후 동일 causal structure 재구성
```

파일 수, class 이름, enum 이름, 내부 helper 구조는 현재 코드베이스와 가장 잘 맞는 방식으로 구현자가 결정한다.

단, 위의 의미적 계약은 변경하지 않는다.

---

# 53. 최종 요약

B0.6은 "그래프를 그리는 기능"이 아니다.

B0.6의 진짜 역할은:

```text
실험 기록
↓
근거 확인
↓
조건 확인
↓
모순 확인
↓
연결 가능한 것만 연결
↓
모르는 곳은 비워둠
↓
인과 경로 생성
```

이다.

즉 B가 처음으로 자신이 수행한 연구 결과를 구조화된 지식으로 바꾸는 단계다.

B0.6의 가장 중요한 철학은 다음 한 문장으로 고정한다.

> **관찰한 것보다 더 많이 말하지 않는다.**

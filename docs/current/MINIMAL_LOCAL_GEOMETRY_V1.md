**상태:** **승인됨 (2026-09-22).** Q1~Q5 확정. **단계 2/7 완료** — PortBond + 인접 불변조건
**날짜:** 2026-09-22
**선행:** `LOCAL_INTERACTION_PRINCIPLES_V1.md` (원칙 4종), `PRECONDITION_CENSUS_2026-09-21.md`
**단계:** 8단계 중 **단계 2**
**관련:** `LANGUAGE_REVISION_GOVERNANCE_V1.md` 10절이 이 설계 전체를 "언어 확장 제안이

---

## 0. 이 문서가 무엇인가 — 설계자의 재정의 (2026-09-22)

> 이건 "기하 추가 문서"가 아니라 **"비물리적 정보가 물리를 결정하지 못하게 만드는
> 첫 구조 개편 문서"** 다.

```
이전:  누구랑 붙을지 애매함
       -> ID / 배열 순서가 몰래 결정

새 방향: 누구랑 붙을지
       -> 공간 + 포트 + 에너지 + 규칙이 결정
       그래도 안 정해짐
       -> 숨은 tie-break 금지
       -> 부족한 물리 정보라고 판정
```

포트에 `N/E/S/W`를 붙이는 것은 수단이지 목적이 아니다.
한 줄로: **입자 번호가 아니라 실제 공간적 관계가 결합 상대를 결정하도록,
최소한의 기하를 세계 상태에 넣는 v3 설계.**

---

## 1. 이 설계가 답해야 하는 질문

단계 5(양립 가능한 변화 동시 commit)를 하려면 **무엇이 양립 가능한지** 판정해야 한다.
판정하려면 **누가 누구와 실제로 접촉했는지** 알아야 한다.

지금은 알 수 없다. 사슬 멤버가 전부 같은 `(x, y)`에 겹쳐 있어서
`A-B-C`인지 `A / B-C`인지 A와 C가 서로 안 닿는지 **표현할 방법이 없다.**

> **목표 한 줄:** 구조 안에서 "누가 어디에 있고 어느 면으로 무엇과 닿아 있는가"를
> 상태로 표현한다. 그래서 접촉이 **기하에서 유도되고**, 이름·순서에서 나오지 않게 한다.

---

## 2. 근본 원인 — 포트에 이름이 없다

조사하다 이걸 찾았다. ID tie-break의 **근본 원인**이다.

```
재료가 ports: 4 를 선언한다        -> 결합 슬롯이 4개
그런데 orientation 은 방향 하나다   -> 입자당 단 하나
결합 규칙은 (kind, orientation) 으로 매칭한다
```

따라서 **4개의 포트가 전부 구별 불가능하다.** 규칙이 한 포트에 맞으면 네 개 모두에 맞는다.

`_grow_chains`가 `sorted(members)`로 고르는 이유가 여기 있다 —
**고를 물리적 근거가 애초에 없으니** 이름으로 고른 것이다.
tie-break를 지우는 것만으로는 안 되고, **구별할 것을 만들어야** 한다.

이게 `LOCAL_INTERACTION_PRINCIPLES_V1.md` 원칙 3이 말한
"부족한 물리 자유도"의 정체다.

## 3. 두 가지 선택지 — 그리고 권고

기하를 넣는 방법은 크게 둘이다.

### (가) 셀 내부 미시 좌표 (sub-cell position)

한 칸 안에 더 미세한 좌표를 둔다. `(8, 8)` 안에서 `(8.3, 8.1)` 같은 식
— 정수 물리이므로 실제로는 `(8, 8, sub_x=3, sub_y=1)`.

| 장점 | 단점 |
|---|---|
| 접촉·거리·각도를 자연스럽게 표현 | **좌표계가 하나 더 생긴다** |
| 회전·굽힘으로 확장 가능 | 셀 경계를 넘는 이동 규칙이 복잡해짐 |
| | 미시 해상도가 새 자유 파라미터 (몇 등분?) |
| | 기존 `stream`·`wrap`·보존 검사가 전부 영향받음 |

### (나) 이름 있는 포트 + 격자 인접 (권고)

**입자는 지금처럼 칸을 차지한다.** 대신:

1. **포트에 방향 이름을 준다.** `ports: 4` → `ports: {N, E, S, W}`
2. **결합은 이웃한 두 칸 사이에서 일어난다.** 같은 칸이 아니라.
3. 구조의 멤버는 **각자 자기 칸**에 있다. 겹치지 않는다.

```
지금:              제안:
  (10,10)            (10,10) (11,10) (12,10)
   A B C               A   ─   B   ─   C
   전부 한 점        A.E ↔ B.W    B.E ↔ C.W
```

| 장점 | 단점 |
|---|---|
| **좌표계가 늘지 않는다** — 기존 격자 그대로 | 구조가 공간을 차지한다 (원래 그래야 맞다) |
| "옆"·"접촉면"이 즉시 생긴다 | 이동 시 모든 멤버를 함께 옮겨야 함 |
| **포트가 구별된다 → ID tie-break의 근거가 사라진다** | 사슬이 꺾이면 모양을 저장해야 함 |
| 모양이 저절로 생긴다 (`A-B-C` 직선 vs `A / B-C` 꺾임) | 기존 세계 2개의 결과가 **바뀐다** |
| 감사기의 "한 칸" 검사를 "인접" 검사로 바꾸면 됨 | |

**(나)를 권고한다.** 이유는 셋이다.

1. **포트 이름만으로 원칙 3 위반의 근본 원인이 사라진다.** (가)는 위치를 주지만
   여전히 "어느 포트"를 말하지 못한다. 포트 이름이 본질이고 미시 좌표는 부수적이다.
2. 새 좌표계·새 해상도 파라미터가 없다. 검증할 표면이 훨씬 작다.
3. 주형 복사가 요구하는 "옆"이 바로 나온다 — 사슬 옆 칸에 다른 사슬이 나란히 설 수 있다.

(가)는 나중에 회전·굽힘·충돌 각도가 실제로 필요해지면 **그때** 추가한다.
지금 넣으면 쓰지도 않을 자유도를 검증해야 한다.

## 4. 제안하는 상태 표현

### 4.1 포트에 이름을 준다

```
지금:   materials: [{kind: 0, mass: 1, ports: 4}]
제안:   materials: [{kind: 0, mass: 1, ports: ["N","E","S","W"]}]
```

포트 수가 아니라 **포트 목록**이다. 재료가 `["E","W"]`만 선언하면 그 재료는
동서로만 결합한다 — 사슬이 직선만 만들 수 있고, 가지를 칠 수 없다.
**이것이 "기하가 구조를 제한한다"의 첫 사례다.** 개수가 아니라 방향이 제한한다.

### 4.2 결합이 어느 포트를 쓰는지 기록한다

```
지금:   PhysicalBond(left_id, right_id, rule_id, stored_energy, x, y)
제안:   PhysicalBond(left_id, left_port, right_id, right_port,
                     rule_id, stored_energy)
```

`x, y`가 사라진다. 결합은 이제 **두 입자 사이의 관계**이고, 위치는 각 입자가 가진다.
(지금은 결합이 위치를 갖고 입자가 거기 겹쳐 있어야 했다 — 거꾸로였다.)

**불변조건이 바뀐다:**

```
지금:  bonded particles must share the bond location
제안:  bonded particles must be neighbours, and each one's bond port
       must face the other
```

즉 `A.E ↔ B.W` 결합이면 B는 반드시 A의 동쪽 칸에 있어야 한다. 검사 가능하다.

### 4.3 결합 규칙이 포트를 지정한다

```
지금:   left_orientation: "E", right_orientation: "W"
제안:   left_port: "E", right_port: "W"
```

의미가 명확해진다. 지금 `orientation`은 "입자가 어느 쪽을 보는가"와
"어느 면으로 결합하는가"를 **한 필드로 뭉개고 있다.** 분리한다.

`orientation`은 남긴다 — 입자 자체의 방향(나중에 회전·비대칭 재료에 쓰인다).
결합 면은 `port`가 맡는다.

### 4.4 구조의 운동은 구조가 갖는다

`LOCAL_INTERACTION_PRINCIPLES_V1.md`가 지적한 대로, 최저 번호 멤버에 운동량을
저장하는 방식을 여기서 함께 없앤다.

```
제안:   StructureState(
            members = frozenset[int],
            total_momentum = (int, int),
            # 질량·기하는 멤버에서 유도되므로 저장하지 않는다
        )
```

`min(members)`가 사라진다. 이름표가 물리에서 빠진다.

## 5. 접촉 그래프가 저절로 나온다

기하가 생기면 단계 3(Contact Graph)은 **새 자료구조가 아니라 조회**가 된다.

```
접촉 후보 = 서로 인접한 칸에 있고,
            마주 보는 포트가 둘 다 비어 있고,
            그 (kind, port) 쌍에 맞는 결합 규칙이 있고,
            에너지 조건을 만족하는 모든 쌍
```

그리고 **양립 가능성도 기하에서 나온다:**

```
두 결합이 같은 포트를 요구한다        -> 양립 불가
두 결합이 서로 다른 포트를 쓴다        -> 양립 가능
두 구조가 같은 빈 칸으로 이동하려 한다 -> 양립 불가
```

단, **"양립 불가"가 곧 "어느 쪽인지 안다"는 뜻은 아니다.** 같은 포트를 두고
둘이 다투면 기하는 "둘 다는 안 된다"까지만 말하고 누가 이기는지는 말하지 않는다.
그건 원칙 3의 영역이다 — **보고하고 멈춘다.** 6.1 참조.

네가 말한 `A → B ← C`가 정확히 이렇게 된다:

```
    A(9,10).E  ↔  B(10,10).W      서로 다른 포트
    B(10,10).E ↔  C(11,10).W      -> 양립 가능 -> 동시 commit
```

**`THREE_BODY_BIND` 없이 `A—B—C`가 한 번에 생긴다.** 원칙 1·2가 그냥 따라온다.

삼각형 `A-B`, `B-C`, `C-A`도 기하가 허용하면 된다 — 격자에서는 세 칸이
서로 인접할 수 없으므로 **격자가 자연히 막는다.** 우리가 금지한 게 아니라
공간이 허락하지 않는 것이다. 이게 올바른 종류의 제한이다.

## 6. 이 설계가 여는 것과 여전히 막는 것

정직하게 적는다.

### 열리는 것

| 항목 | 어떻게 |
|---|---|
| ID tie-break 제거 — **일부만** | 포트가 구별되므로 고를 근거가 생긴다. 아래 6.1 참조 |
| 동시 다중 결합 | 서로 다른 포트면 양립 |
| 사슬 길이 4 이상 | "한 tick 한 결합" 천장이 필요 없어진다 |
| **"옆"** | 주형 복사의 전제. 나란한 두 사슬이 표현된다 |
| 구조의 모양 | 직선·꺾임·가지가 구분된다 |
| 촉매 중간체 | `C-A`, `C-A-B` 같은 구조가 표현 가능 |

### 6.1 정직하게 — 기하가 모든 모호성을 없애지는 않는다

설계 중에 확인했다. **이름 있는 포트는 경합을 줄이지만 전부 없애지 못한다.**

해소되는 경우 (현재 증명된 결함):

```
구별 불가능한 두 멤버 + 도착 하나
-> 도착이 있는 칸을 향한 빈 포트를 가진 멤버만 결합 가능
-> 기하가 결정한다
```

**해소되지 않는 경우:**

```
   A(9,10).E   ->  (10,10)을 향함
   B(11,10).W  ->  (10,10)을 향함
   도착 X 가 (10,10) 에 있음
```

A와 B **둘 다** X를 향한 빈 포트를 갖고, 둘 다 규칙이 맞고, 둘 다 에너지가 충분하다.
**여전히 두 가지 합법적 결과가 있다.** 기하가 결정하지 못한다.

이 경우를 결정하려면 상태에 더 필요하다 — 도착이 어느 쪽에서 왔는지,
tick 안에서의 도착 위상, 상대 속도. **전부 지금 상태에 없다.**

따라서:

- 이 설계는 **"모든 모호성을 없앤다"고 주장하지 않는다**
- 원칙 3은 계속 적용된다 — **남은 경합은 tie-break가 아니라 보고한다**
- `contested_census`는 폐기되지 않는다. **기하 도입 후 경합이 얼마나 줄었는지**를
  측정하는 도구가 된다

**이것이 이 설계의 성공 기준이다:** 경합을 0으로 만드는 것이 아니라,
**남은 경합이 전부 "진짜로 물리 정보가 부족한 경우"가 되는 것.**
지금은 포트에 이름이 없어서 생긴 가짜 경합이 섞여 있다.

---

### 여전히 막히는 것

| 항목 | 왜 |
|---|---|
| 회전·굽힘 | 포트가 절대 방향(N/E/S/W)에 고정. 구조가 회전하면 포트도 돌아야 하는데 그 규칙이 없다 |
| 접촉 각도 | 인접이냐 아니냐만 있고 각도는 없다 |
| 환원 불가능 N체 (②) | `PhysicalBond`가 여전히 2항. hyperedge는 단계 8 |
| 구조끼리의 충돌 | 두 구조가 부딪히면? 미정의 |

**이 넷은 이번 설계의 범위가 아니다.** 필요해지면 그때 각각 다룬다.
지금 다 넣으면 검증할 표면이 폭발한다.

## 7. 깨지는 것 — 호환성

**이건 v3 포맷이다.** v1·v2는 그대로 두고 새 포맷을 만든다.

| 영향 | 내용 |
|---|---|
| 세계 명세 | `ports: 4` → `ports: ["N","E","S","W"]`, 규칙의 `*_orientation` → `*_port` |
| `PhysicalBond` | `x, y` 제거, `left_port`/`right_port` 추가 |
| 불변조건 | "같은 칸" → "인접 + 마주 보는 포트" |
| **기존 세계 2개의 결과** | **바뀐다.** 결합된 입자가 더 이상 겹치지 않으므로 digest가 달라진다 |
| `_stream_free` | 구조 전체를 함께 옮기되 상대 기하 유지 |
| 감사기 `particles.py` | "사슬이 한 칸에 모였는가" → "인접하고 포트가 마주 보는가" |
| `precondition_census` | "한 칸에 3개" 기준이 의미를 잃는다. "접촉 가능한 쌍" 으로 재정의 |
| `contested_census` | 포트가 구별되면 경합의 정의가 바뀐다 |

**v1·v2 세계는 계속 돌아간다.** `deterministic_polymer_chain_v2.json`의 run digest는
보존된다. v3는 새 세계 파일로 시작한다.

| Q2 | 포트를 절대 방향으로 | **예. 회전 불가를 선언된 한계로 명시** |
| Q3 | 한 칸에 자유 입자 여럿 | **계속 허용** |

아래는 각 판단의 근거다.

### Q1. (가) 미시 좌표 vs (나) 이름 있는 포트

권고: **(나).** 3절 참조.

### Q2. 포트 이름을 절대 방향으로 할 것인가

`["N","E","S","W"]`는 절대 방향이다. 구조가 회전하면 포트도 돌아야 하는데
그 규칙이 없으므로 **지금은 회전이 불가능**하다.

대안: 포트에 추상 이름(`["a","b","c","d"]`)을 주고 방향 매핑을 따로 두면
회전이 가능해지지만, 매핑 자체가 새 상태다.

권고: **지금은 절대 방향.** 회전이 실제로 필요해질 때 추상 이름으로 옮긴다.
단, **"회전 불가"를 선언된 한계로 문서에 명시**한다 — 숨은 천장이 되지 않도록.

### Q3. 한 칸에 여러 입자를 계속 허용할 것인가

결합된 입자는 이제 각자 칸을 차지한다. 자유 입자는?

- **계속 허용:** 지금과 같음. 충돌이 한 칸 안에서 일어난다
- **배타적 점유:** 한 칸에 하나. 충돌이 "이웃으로 들어가려 함"이 된다

권고: **계속 허용.** 배타적 점유는 이동 규칙을 전부 다시 써야 하고,
"들어가려다 막힘"이라는 새 사건이 생긴다. 범위를 넘는다.

### Q4. 기존 세계 2개를 v3로 옮길 것인가

권고: **옮기지 않는다.** v1·v2는 동결된 비교 기준선으로 두고 v3 세계를 새로 만든다.
`RULES.md`가 "서로 다른 세계의 결과를 합산하지 않는다"고 했다.

### Q5. 이 설계 자체가 틀렸을 가능성

**가장 큰 위험은 "포트 이름이 진짜 부족한 자유도인가"이다.**
내가 근본 원인이라고 판단했지만, 구현해보니 또 다른 것이 부족할 수 있다.

완화책: 단계 3(재명명 불변성)을 먼저 통과시킨다. 거기서 실패하면
**포트 이름이 충분하지 않다는 뜻**이고, 그때 미시 좌표나 도착 위상을 검토한다.
전부 만들고 나서 확인하지 않는다.

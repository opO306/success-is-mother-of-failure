# A-MICRO v6 C0 수치 실행 계획 v1 — 숫자에게 무엇을 요구하는가

**상태:** 7판 (2026-09-25) — **11.5절: Ar 1차 기준 후보 Lang 2024, C1-A/B/C 단계, 원자 단위계 방향.** 6판 — **11.4절: N3-A(Born–Mayer) 철회. C0 = 역학 검증(합성 퍼텐셜 허용, 현실 주장 금지), C1 = 첫 실제 물질(Ar–Ar, 반발·인력을 같은 PES에서). 표현 방식 미정.** 5판 — **11.3절: N3를 N3-A(모델 계열 채택)·N3-B(정량 계약, 미확정)로 나눔. C0 물리 법칙은 아직 동결되지 않았다.** 4판 — **11절: E5 분리(E5-A·E5-B), N3 결정 = P-c Born–Mayer형 + 적용 범위 계약.** 3판(2026-09-24) — **설계자 판정 반영(10절)**: E9 추가, N3 순서 수정, E7 재정의, N6 기각, N9 추가, N8 → 네이티브 도구.
실행 계층은 `A_NUMERIC_EXECUTION_STACK_V1.md`(A-Numeric VM이 계산 의미의 기준). **코드 없음, 수 체계 미선택.**
**상위:** `A_MICRO_V6_PHYSICS_CLOSURE_V1.md`(2판 승인, C0 = 반발만 있는 보존적 쌍 상호작용), `A_V6_DEFORMABLE_MATERIAL_ARCHITECTURE_V1.md`
5절(수치 계약 5개, 수렴 두 종류, `energy_balance_residual`).
**목적:** 후보에게 점수를 매기는 것이 아니라, **숫자 체계에게 무엇을 요구하는지를 먼저 못 박는 것.** 구현이 편한 숫자가 물리 법칙을 몰래
정하는 일을 막는다.

**순서 (3판):** `A_NUMERIC_EXECUTION_STACK_V1.md` 5절 — A-Numeric VM → 네이티브 도구 → C++ 직렬·병렬·CUDA에 L1 → 차등 시험(E9 포함) →
능력표(**아직 탈락 없음**) → C0 퍼텐셜 물리 결정 → 요구 연산으로 탈락 → 동적 범위 증명·성능 → 선택 → 그 다음에야 C0 구현.

## 1. C0 연산 목록 (operation census)

한 시간 간격(step)에 C0이 하는 일:

| # | 단계 | 연산 | 숫자 체계에 주는 부담 |
|---|---|---|---|
| O1 | 위치 차이 `d = xⱼ − xᵢ` (주기 경계면 최소 상 규약) | 뺄셈, 상자 크기로 감기(wrap) | 감기가 정확한가. 최소 상 선택은 **분기**(4절) |
| O2 | 거리 관련량 | `r² = d·d` (곱·합). 퍼텐셜 모양에 따라 `r`(제곱근), `1/r²`(나눗셈) | 제곱근·나눗셈의 반올림이 플랫폼마다 같은가 |
| O3 | 범위 판정 `r² < r_c²` | 비교 | **분기** — 인과가 켜지고 꺼짐(4절) |
| O4 | 퍼텐셜·힘 평가 | 퍼텐셜 모양에 따라 다항식 / 거듭제곱 / 지수(`exp`) | 초월 함수는 라이브러리마다 결과가 다름 |
| O5 | 두 입자에 ±힘 | 같은 값을 한쪽엔 더하고 한쪽엔 뺌 | 운동량이 **비트 단위로** 보존되려면 두 입자가 받는 양이 정확히 같은 크기 |
| O6 | 한 입자가 받는 여러 힘 합산 | 대규모 덧셈 | **합산 순서가 결과를 바꾸는가** — 바꾸면 재명명 불변성이 비트 수준에서 깨짐 |
| O7 | 시간 진화 | `p += F·Δt`, `x += p·(Δt/m)` | `Δt/m`은 종류별 상수로 미리 계산 가능. 곱셈 반올림 |
| O8 | 에너지 계산 | `Σ p²/2m + Σ U` | 큰 합의 정밀도 — 잔차보다 계산 오차가 크면 잔차가 무의미 |
| O9 | 감사값 | 총 운동량, 총 각운동량 `Σ x × p`, `energy_balance_residual` | 감사가 실행기와 같은 반올림을 쓰면 같은 오류를 못 잡음 → 5절 |

### 1.1 연산 목록은 퍼텐셜 모양에 달려 있다 — 그러나 숫자가 퍼텐셜을 고르면 안 된다

| C0 반발 퍼텐셜 후보 | 필요한 연산 | 물리 근거 |
|---|---|---|
| **P-a** `r²`의 다항식 + 매끄러운 차단 | 곱·합만 (제곱근·나눗셈 없음). 힘 = `−2 U′(r²) d` | 근사 — 모양은 임의, 가파름·범위만 물리 |
| **P-b** 거듭제곱 반발 (`r⁻¹²` 계열, WCA형) | 나눗셈 (`r²`로 쓰면 제곱근은 없음) | 근사 — 역사적 편의. 현실 반발의 모양은 아님 |
| **P-c** 지수 반발 (Born–Mayer형 `A·e^{−r/ρ}`) | 제곱근 + `exp` | 파울리 반발에 더 가까운 모양으로 알려짐 — 그래도 유효 모델 |

**구현자 공개 — 여기가 설계자가 경고한 바로 그 지점이다:** 고정소수점에 가장 편한 것은 P-a다. 숫자 편의 때문에 P-a를 고르면
"구현 편한 숫자가 물리를 몰래 결정"하는 것이다.

**순서 (설계자 수정 — 반대 방향 오류도 막는다):** 2판은 "후보 X가 P-c를 못 하면 X 탈락"으로 읽힐 수 있었다. 그러면 **아직 선택되지 않은
물리가 숫자를 결정**한다. 올바른 순서:

```
수 체계 능력 조사 → P-a/P-b/P-c 각각 지원 정도를 기록 (아직 탈락 아님)
독립적인 물리 근거로 C0 퍼텐셜 선택 → 그 퍼텐셜이 요구하는 연산 집합 확정 → 그 연산을 결정론적으로 못 하는 후보 탈락
```

**매끄러운 차단(모든 모양 공통 요구):** 유한 범위 퍼텐셜은 차단 거리에서 **값과 기울기가 모두 0**으로 가야 한다. 아니면 쌍이 차단 거리를
넘을 때마다 에너지가 계단처럼 튀고(O3 분기가 에너지를 만든다), 이것은 숫자 체계와 무관한 **물리 쪽 결함**이다.

## 2. 후보 — 재분류 (설계자 수정)

| 역할 | 후보 | 성질 |
|---|---|---|
| **주 실행기** | **F1 고정소수점 정수** | 덧셈이 정확·결합 법칙 성립 → 합산 순서 무관. 범위가 좁음, 나눗셈·제곱근·`exp`는 직접 구현 |
| **주 실행기** | **F2 결정론적 부동소수점** — (a) 하드웨어 IEEE를 엄격 규칙(고정 순서, FMA 자동 합성 금지, fast-math 금지)으로 / (b) 순수 소프트웨어 구현 | 범위가 넓음. 기본 사칙·제곱근은 IEEE가 정확 반올림을 보장하지만 **`exp` 같은 초월 함수는 보장 없음** → 직접 구현 필요. 덧셈 결합 법칙 불성립 → 합산 순서 규약 필요 |
| **주 실행기 (참고)** | **F3a 임의 정밀도 유리수** (v5의 `Fraction`) | 이산 사상을 **정확히** 계산. 그러나 `√`·`exp` 불가(P-a만 가능), 분자·분모가 시간에 따라 폭증할 수 있음 → 측정 대상 |
| **주 실행기 (참고)** | **F3b 임의 정밀도 부동소수점** (정확 반올림 라이브러리) | 결국 반올림 근사. 정밀도를 올려 가며 수렴을 보는 데 유용 |
| **독립 검증기 / 기준** | **V1 구간 산술** | 참값을 감싸는 데 강함. **세계 상태를 구간으로 들고 가면 구간이 계속 넓어져 "여기 있을 수도, 저기 있을 수도"인 세계**가 됨 → 주 실행기 아님 |

## 3. 탈락 조건 — **먼저 동결** (통과/탈락, 점수제 금지)

가중치 점수로 고르지 않는다. 아래 중 하나라도 걸리면 탈락, 전부 통과한 후보끼리만 비용을 비교한다.

| # | 탈락 조건 |
|---|---|
| E1 | 같은 설정에서 **CPU/GPU 비트 불일치** |
| E2 | **재명명·입력 순서**로 결과(비트)가 바뀜 |
| E3 | 넘침을 **조용히 감음**(wrap) 또는 NaN/무한대를 조용히 전파 — 검출되면 반드시 중단 |
| E4 | 시간 간격을 줄이거나 정밀도를 높여도 **수렴하지 않음**(두 종류, 5절) |
| E5 | ~~운동량 보존 계약 위반 — "수치 체계가 허용하는 범위에서 정확"~~ → **4판에서 둘로 나눔(11절).** "0이 아닌데 정확"이라고 부르지 않는다 |
| E5-A | **작용·반작용 계약 위반** — 한 입자에 `+J`를 주면 상대에게 **정확히 같은 크기의** `−J`. 예외 없이 통과해야 함 |
| E5-B | **전체 운동량 오차 계약 위반** — 계산 후 총 운동량 차이가 **사전에 계산한 반올림 오차 상한**을 넘거나, 정밀도를 높여도 0으로 수렴하지 않거나, 한 방향으로 계속 쌓임 |
| E6 | 같은 입력 두 번 실행이 비트 불일치 (결정론) |
| E7 | **선택된 물리 모델이 요구하는 연산**에 대해 플랫폼 독립적인 결과를 제공하지 못함 (선택 전에는 능력표에 기록만) |
| E8 | **분기 불안정** — 정밀도를 높여도 불연속 분기(4절)의 결과가 안정되지 않음 |
| **E9** | **실행 배치 의존** — 같은 초기 상태·이산화·정밀도에서 스레드 수(1/2/4/8/12), 작업 분할, GPU 블록·그리드 배치(32/64/128/256)를 바꿨을 때 정규화된 물리 상태가 비트 단위로 달라짐. 그러면 스레드 수가 몰래 세계의 물리 상태가 된 것 |

**비교 항목 (탈락이 아니라 측정):** 각운동량 표류, `energy_balance_residual`, 동적 범위, 정밀도당 비용, 실행 시간, 메모리, (선택) 비트 가역성.

**E1 정정 (1판의 잘못):** 1판은 "이 작업 환경에는 GPU 실행 경로가 없다"며 E1을 미판정으로 미뤘다. **확인하지 않고 쓴 틀린 문장이었다** —
실제로는 로컬 RTX 4060이 있고 PyTorch CUDA가 동작한다(9.4). E1은 미루지 않고 **숫자 체계 선택 전에 실측**한다(9절).

**E1의 뜻 (설계자):** 같은 초기 상태 · 같은 Δt · 같은 정밀도 · 같은 퍼텐셜 · 같은 경계 · 같은 상호작용 집합 → 직렬 CPU · 병렬 CPU · GPU의
**정규화된 물리 상태가 비트 단위로 동일.** "오차 범위니까 괜찮다"는 인정하지 않는다.

## 4. 분기 감사 — 숫자 오차가 인과를 켜고 끄는 곳

> **수치 오차가 불연속적인 물리 분기를 결정하는 지점은 특별 감사한다. 정밀도를 높였을 때 분기 결과도 안정화되어야 한다.** (설계자)

C0의 분기 지점:

| 분기 | 결과 | 완화 |
|---|---|---|
| O3 `r² < r_c²` | 쌍 상호작용이 켜짐/꺼짐 | 매끄러운 차단(1.1) → 경계 근처에서 힘이 거의 0이라 **어느 쪽이든 결과 차이가 연속적으로 작음**. 분기는 남지만 인과적 효과가 사라짐 |
| O1 최소 상 선택 | 어느 복사본과 상호작용하나 | 차단 거리 < 상자 절반이면 두 후보가 동시에 범위 안에 들 수 없음 → 효과 없음. 이 조건을 세계 명세 검증으로 강제 |
| 넘침 검출 | 중단 | E3 |

**감사 방법:** 기록된 모든 분기 지점에서 판정값의 여유(`|r² − r_c²|`)를 남기고, 여유가 수치 오차 한계보다 작은 분기 수를 센다. 정밀도를
높일 때 그 수가 줄어들고 결과가 안정되는지 본다.

## 5. 기준 계산기 (reference oracle) — 후보들이 모두 같은 틀린 답을 내는 것을 막는다

```
주 실행기 후보들  ──비교──→  고정밀 기준 계산기 (느림, 작은 입자 수, 짧은 시간)
                                  └─ 가능하면 구간 산술로 참값을 감싸는 독립 감사
```

**두 오차를 따로 잰다 (구현자 추가):**

| 오차 | 무엇과 비교 | 무엇을 알려 주나 |
|---|---|---|
| **반올림 오차** | **같은 Δt**의 이산 사상을 기준 계산기가 초고정밀(또는 F3a 정확)로 계산한 값 | 숫자 체계가 얼마나 틀리나 |
| **이산화 오차** | Δt → 0 외삽 / 해석해(두 입자 산란각) | 적분기가 얼마나 틀리나 — 숫자 체계와 무관 |

두 개를 섞으면 "Δt를 줄였더니 좋아졌다"가 숫자 덕인지 적분기 덕인지 모른다.

**기준 계산기는 A 실행기가 아니다.** 세계를 만들지 않고, 판정에만 쓴다. 독립 감사 원칙대로 `engine`을 import하지 않는다.

## 6. 시험 — 세 층

### L1 산술 단위
`+ − × ÷`, 거리 계산, 세 퍼텐셜 모양의 힘 계산, 대규모 합산(순서 뒤섞기), 반올림, 넘침 경계.

### L2 C0 단일 상호작용
두 입자 정면 산란 · 비스듬한 산란(산란각 vs 해석해) · 질량이 매우 다른 두 입자 · 매우 가까운 접근(가장 큰 힘 = 동적 범위 시험).

**구현자 참고 → N9 동적 범위 증명으로 격상 (설계자 조건):** 에너지 보존으로 최소 접근 거리를 제한하는 논리는 **반발 퍼텐셜 · 알려진 에너지
하한 · 정확한 연속 동역학 · 작은 거리에서 충분히 가파른 퍼텐셜**일 때만 성립한다. 실제 실행기는 한 step에 너무 멀리 움직여 허용 최소 거리
안쪽으로 넘어갈(overshoot) 수 있고, 상태값이 안전해도 **중간 계산**(64비트 × 64비트)이 먼저 넘칠 수 있다. 그래서 따로 계산한다:
① 물리적으로 가능한 상태 범위 ② 중간 연산이 요구하는 범위 ③ 수치 overshoot에 필요한 안전 여유 ④ 범위를 넘으면 반드시 중단.

### L3 다입자 장시간
입자 16 → 64 → 256 → …, 긴 시간.

| 측정 | 비고 |
|---|---|
| 총 운동량 표류 | E5 |
| 총 각운동량 표류 | 측정 |
| `energy_balance_residual` (± 그대로) | 측정 |
| 직렬 CPU / 병렬 CPU / GPU digest | E1 |
| 입력 순서·재명명 digest | E2 |
| Δt 절반 수렴 (짧은 시간 궤적 / 긴 시간 관측량) | E4 |
| 정밀도 증가 수렴 | E4 |
| 분기 여유 부족 수 | E8 |
| 실행 시간, 메모리 | 비용 |
| (선택) 전진 N → 속도 반전 → N 후 비트 복귀 | 비트 가역성 — 필수 아님 |

## 7. 알려진 사실 (후보 평가 전 참고 — 결론 아님)

- **정수 덧셈은 결합 법칙이 성립한다.** 고정소수점이면 O6 합산 순서가 결과를 바꾸지 않아 E2가 구조적으로 성립하고, GPU의 정수 원자적 덧셈도
  순서와 무관하게 같은 결과를 낸다. 부동소수점 원자적 덧셈은 그렇지 않다.
- **부동소수점도 E2를 통과할 수 있다:** 이름표 순서가 아니라 **값 기준 정렬 후 합산**하면 합산 대상의 모음은 이름과 무관하므로 결과도 이름과
  무관하다. 비용은 입자마다 정렬.
- **운동량을 상태로 두면**(속도 대신) 작용-반작용 충격 `F·Δt`를 두 입자에 같은 정수로 ± 적용해 총 운동량이 고정소수점에서 비트 단위로 정확.
- **정수 위치 + 도약(leapfrog) 적분은 비트 단위 가역이 가능**하다는 선행 연구가 있다(Levesque & Verlet, 1993). 필수 조건은 아니지만 F1의 장점 후보.
- **주기 상자 감기:** 위치가 정수 단위면 상자 길이 L도 정수이고 `x mod L`은 L이 무엇이든 정확하다. 2의 거듭제곱은 비트 연산으로 빠를 뿐 —
  **물리 정확성의 조건이 아니라 성능 최적화**. 그래서 상자 크기에 제약을 두지 않는다(N6 기각).

## 9. 다중 실행기 계약 — N7 (설계자 추가)

> C0 숫자 체계 선택 전에 최소 직렬 CPU / 병렬 CPU / GPU 실행 경로를 만들고, 동일한 수치 커널을 세 경로에서 실행해 E1·E2·E5·E6·E7을
> 실측한다. **GPU·병렬화 때문에 물리식이나 수치 정밀도를 바꾸는 것은 금지한다.**

**왜 지금:** 성능 최적화를 일찍 하는 것이 아니다. "하드웨어가 세계 법칙을 바꾸지 않는다"는 원칙을 숫자 체계를 고르기 **전에** 실제로
시험하는 것이다. 나중에 붙이면: CPU에서 F1 통과 → C0~C2 구축 → GPU 구현 → 병렬 합산 불일치 → 숫자 체계·실행 구조 재설계.
가장 먼저 사고가 나는 곳은 O6(한 입자에 모이는 힘 합산) — 직렬은 `((F1+F2)+F3)+F4`, 병렬은 `(F1+F2)+(F3+F4)`가 될 수 있다.

**범위:** GPU용 C0 엔진이 아니라 **수치 backend 시험 틀(harness)**. L1(산술·합산·반올림·넘침·거리)과 L2(두 입자 힘, 여러 쌍의 힘, ± 적용,
다입자 힘 합산)만 세 경로로 돌린다. 살아남은 숫자 체계만 C0 엔진 후보가 된다.

### 9.1 구조

```
                    같은 세계 상태
          ┌──────────────┼──────────────┐
      직렬 CPU        병렬 CPU          GPU
   (가장 단순, 최적화 최소)  (병렬화가 결과를 바꾸나)  (대규모 실행 경로 + CPU/GPU 계약)
          └──────────────┼──────────────┘
          정규 상태 · 보존 감사 · digest 비교
                         +
          고정밀 기준 계산기 (작은 계만 — 셋이 똑같이 틀리는 경우를 잡음)
```

네 역할을 섞지 않는다. 기준 계산기는 세 경로 어느 것과도 코드를 공유하지 않는다.

### 9.2 원인 분리표

| 직렬 | 병렬 CPU | GPU | 먼저 의심할 곳 |
|---|---|---|---|
| A | A | A | (통과) — 그래도 기준 계산기와 비교 |
| A | B | B | 병렬 합산(reduction) 설계 |
| A | A | B | GPU 수치 연산 — FMA 자동 합성, 비정규 수(denormal) 처리, 수학 함수 구현 |
| A | B | C | 둘 다 |

### 9.3 물리가 먼저, 연산은 그 다음

```
물리 모델 → 필요 연산 결정 → CPU/GPU가 그것을 동일하게 계산하는 방법 탐색     (허용)
GPU가 계산하기 쉬운 연산 → 그걸로 물리 법칙 결정                              (금지)
```

예: GPU의 `exp()`가 플랫폼마다 다르다 → 지수 퍼텐셜(P-c)을 지우는 것이 아니라 **세 경로가 공유하는 `exp` 구현을 직접 만든다.** 못 만들면
그 숫자 체계가 탈락이다(E7).

### 9.4 실제 환경 (2026-09-24 확인)

| 항목 | 상태 |
|---|---|
| GPU | NVIDIA GeForce RTX 4060, 8GB, 드라이버 CUDA 13.4 |
| PyTorch | 2.7.1 + CUDA 11.8 — **GPU 동작 확인** (int64 연산 포함) |
| Numba | 0.65.1 — **CPU 병렬 가능, CUDA 불가**(CUDA 툴킷 없음) |
| CUDA 툴킷(`nvcc`) · CuPy | **없음** |
| mpmath | 1.3.0 — 고정밀 부동소수점 + 구간 산술 둘 다 있음 → 기준 계산기(N5) 후보 |
| CPU | 논리 코어 12 |

**이 환경이 주는 제약 (구현자 공개):**
- **PyTorch만으로는 GPU 내부 합산 순서·FMA를 직접 통제할 수 없다.** `torch.sum` 같은 내장 축약은 순서를 우리가 정하지 못한다. 대신 **한 연산씩
  따로 부르는** 원소별 연산(곱 한 번, 더하기 한 번)은 각각 한 번 반올림되어 FMA가 끼어들 틈이 없고, 합산은 우리가 정한 **고정 트리 순서**로
  원소별 덧셈을 반복해 만들 수 있다. 느리지만 시험 틀에는 충분하다.
- **F1(고정소수점)의 곱셈:** 32.32 형식끼리 곱하면 중간값이 128비트가 필요한데 PyTorch에는 128비트 정수가 없다 → 32비트 조각으로 나눠
  곱하는 구현이 필요하다. 이것은 F1의 **실제 비용**으로 측정 항목에 넣는다.
- **진짜 사용자 정의 GPU 커널**(합산 순서·FMA를 커널 안에서 통제)이 필요해지면 CuPy(또는 CUDA 툴킷)를 **설치**해야 한다. 설치는 설계자
  확인 후(N8).
- 병렬 CPU 경로는 Numba 병렬(`prange`)과 PyTorch CPU 다중 스레드 중 하나 — Numba가 루프 구조를 우리가 정할 수 있어 기본 후보.

## 11. 설계자 판정 (2026-09-25, 4판)

### 11.1 E5 → E5-A · E5-B

"반올림이니까 괜찮음"도, "0이 아니니까 즉시 탈락"도 아니다. **증명 가능한 오차만 허용한다.**

| 후보 | E5-A 작용·반작용 | E5-B 총 운동량 오차 |
|---|---|---|
| F1 고정소수점 | **통과** | **비트 단위 정확 보존**(L2: 모든 계·축) |
| F2a binary64 | **통과** | 반올림 오차 **존재**, 현재 관측치는 오차 상한 안(L2: 234개 축 합계 중 214개 ≠ 0, 전부 상한 이하). **최종 판정 보류** — 정밀도 증가·장시간 시험에서 실제로 수렴하는지, 한 방향으로 쌓이지 않는지 확인 후 |

**구현자 공개 — E5-B를 재려면 정해야 할 것:** (1) "정밀도를 높이면"의 비교 대상 — 같은 이산 사상을 더 넓은 수 체계(F3b 또는 더 넓은
소프트웨어 부동소수점)로 돌린 판이 필요하다. 지금 VM에는 binary64보다 넓은 부동소수점 프로필이 없다. (2) "한 방향으로 쌓임"의 판정 —
장시간 표류가 무작위 걸음(√t)인지 체계적(∝ t)인지 가르는 통계 기준. 둘 다 L3(장시간)에서 정한다.

### 11.2 N3 — C0 기본 반발 = P-c Born–Mayer형 지수 반발 *(5판에서 조건부로 낮춤, **6판(11.4)에서 철회**)*

**근거(물리만):** P-a 다항식은 원하는 모양을 만들기 편한 수치 모델. P-b `r⁻¹²`는 순수 반발로 널리 쓰이나(WCA) 12승 자체는 전자 구조에서
나온 형태가 아니다. Born–Mayer 지수 반발은 전자 밀도 겹침에서 오는 짧은 거리 반발의 전통적 형태이고 `r⁻¹²`보다 잘 맞는 경우가 보고됨.
**그래도 유효 모형이다**(양자역학 자체 아님).

**적용 범위 계약:**
- C0 정상 영역의 기본 반발 = `U(r) = A·e^{−r/ρ}` 계열.
- Born–Mayer를 r → 0까지 믿지 않는다. 극단적으로 가까운 영역은 장기적으로 ZBL 계열(가려진 핵 반발)과 매끄럽게 연결 — **지금은 구현하지
  않는다.** 원자 번호·화학 종이 정의되지 않은 상태에서 ZBL 매개변수를 만들면 "모르는 물리를 개발자가 채워 넣기"가 된다.
- 검증된 영역보다 가까워지면 **외삽하지 않고 실행 중단**, 이유 `physics_domain_exceeded` 기록.

**순서 (설계자):** P-c 선택 → EXP 필요 → **A-Numeric VM에 `deterministic_exp_v1` 정의** → R1 독립 검증 → B0/B1/B2 동일 구현 → E7 검사 →
실제 P-c L2 → E4/E8/N9. — 숫자 체계가 물리를 고르는 것이 아니라, 물리가 P-c를 요구하므로 계산기가 EXP를 배운다.

**구현자 공개 — N3에 아직 정해지지 않은 것 (숨은 선택이 되지 않도록):**
1. **매끄러운 차단(1.1절, 모든 모양 공통 필수).** Born–Mayer는 무한 범위(지수 꼬리)다. 유한 범위로 자르려면 차단 거리 `r_c`와 차단 방식
   (값·기울기를 0으로 만드는 방법 — shifted-force, 곱하는 전환 함수 등)을 정해야 하고, **이 방식 자체가 또 하나의 모델 선택**이다.
2. **`physics_domain_exceeded`의 문턱 `r_min`.** 무엇이 "검증된 영역"인지는 매개변수 `A, ρ`와 대상 물질에서 나와야 한다 — 지금은 정해지지 않음.
3. **VM에 조건부 중단 명령이 없다.** VM 0.x는 넘침·영 나눗셈 등 산술 멈춤만 있고, "r² < r_min²이면 `physics_domain_exceeded`로 멈춤" 같은
   **선언된 물리 범위 검사** 명령이 없다. C0 커널 단계에서 설계 필요(예: `GUARD` 명령 — 비교 여유 기록과 함께). 지금은 만들지 않는다.
4. **`A`, `ρ`의 값과 단위계.** 미정.

### 11.3 설계자 판정 5판 (2026-09-25) — N3를 둘로, EXP·E5 승인 *(N3 부분은 11.4가 대체, EXP·E5 판정은 유효)*

**N3는 너무 빨랐다.** `A`, `ρ`, `r_min`, 어느 물질·입자 조합인지, 매개변수 출처, 유효 거리 범위, 차단 방식이 하나도 정해지지 않았는데
"C0 기본 반발 = P-c"를 법칙처럼 적었다. 모르는 물리를 그럴듯한 숫자로 메우지 않는다는 원칙에 맞춰 둘로 나눈다.

| | 내용 | 상태 |
|---|---|---|
| **N3-A 모델 계열** | Born–Mayer형 지수 반발을 **우선 채택**. 계산 편의 때문에 P-a·P-b를 고르지 않는다 | **승인(방향)** |
| **N3-B 정량 계약** | `A`, `ρ`, 유효 거리 범위(`r_min` 포함), 차단 연결 방식, 데이터 출처와 불확실성 | **미정.** 확정 전에는 C0의 실제 물리 법칙으로 **동결하지 않는다** |

- 시험용 임의 매개변수(dummy)로 **수치 틀(harness)**을 돌리는 것은 허용 — 단 그것을 "C0 물리"라고 부르지 않는다.
- `physics_domain_exceeded` 원칙(검증 범위 밖 외삽 금지)은 유지. 그 범위의 값은 N3-B에서 나온다.

**그 밖의 판정:** VM 0.2의 `EXP` 의미(정확한 e^x를 한 번 반올림) **승인** — 원하는 값과 구하는 방법이 분리되고, 어떤 하드웨어든 최종
비트만 같으면 된다. 표현은 "EXP 의미 확정 / VM 구현은 강한 검증 통과 / 어려운 사례 탐색은 계속 확장". E5-A·E5-B **승인(유지)**.

**순서 (5판):** VM 0.2 EXP → **B0/B1/B2 EXP 비트 일치** → EXP의 E7 검증 → Born–Mayer 실제 물리 자료 조사 → `A, ρ, r_min`, 차단, 출처 확정 →
N3-B 승인 → 실제 P-c L2 → E4 / E8 / N9.

### 11.4 설계자 판정 6판 (2026-09-25) — N3-A 철회, C0는 역학 검증, C1부터 실제 물질

N3-B 조사(`A_MICRO_V6_N3B_BORN_MAYER_SURVEY_V1.md`)에서 "Born–Mayer 값을 무엇으로"보다 앞선 문제 — **C0가 현실의 무엇을 표현하는지가 정해지지
않았다** — 가 드러났다.

1. **N3-A의 Born–Mayer 우선 방향 승인을 철회한다.** Born–Mayer는 특정 원자·이온 쌍과 거리 범위에 대한 유효 근사이며, A-MICRO의 보편적 현실
   반발 법칙으로 채택할 근거가 부족하다. **새 N3-A:** 실제 물리 종과 검증된 상호작용 자료를 먼저 정한 뒤, **그 자료가 요구하는 퍼텐셜 표현**을
   채택한다.
2. **입자를 Ar 전용으로 정의하지 않는다.** 실제 원자종을 표현할 수 있는 `species` 구조를 유지하고, **Ar은 첫 번째 현실 검증 종(reference
   species)**이다. (He, Ne, Ar … → 이후 실제 화학 원소들)
3. **C0 = 역학 바닥 검증으로 제한.** 선언된 **합성(synthetic) 반발 퍼텐셜** 허용 — 수치·역학 검증용이며 현실 물리 모델이라고 주장하지 않는다.
4. **C1 = 첫 실제 물질 상호작용 검증.** 첫 계는 Ar–Ar. 반발과 인력을 서로 다른 법칙으로 나누지 않고 **같은 검증된 쌍 퍼텐셜/PES**에서 함께 가져온다.
5. **Ar–Ar 퍼텐셜의 표현 방식은 미정.** Born–Mayer · 고정밀 해석적 PES · 표(tabulated) PES를 구현 편의가 아니라 **물리 정확도 · 검증 범위 · 출처**로 비교.
6. **VM 연산 목록이 물리 모델을 정하지 않는다.** 선택된 퍼텐셜이 새 연산이나 표 보간을 요구하면 그 연산을 정의하고 E7을 검증한다.
7. **`deterministic_exp_v1`과 네이티브 EXP는 유지** — N3-A 철회가 EXP 구현을 무효화하지 않는다(일반 수치 연산 기반).
8. **다음은 코딩이 아니라 Ar–Ar 현실 퍼텐셜 비교 조사:** 전체 적용 거리, 에너지 범위, 이론 수준, 실험 검증, 쌍(pairwise) 근사의 한계,
   **3체 항이 필요해지는 시점**을 함께.

**11.2·11.3의 N3 기록은 역사로 남기고 이 절이 대체한다.**

### 11.5 설계자 판정 7판 (2026-09-25) — Ar 퍼텐셜 선택 기준, C1 단계, 원문 확보, 단위계

### 11.6 설계자 판정 8판 (2026-09-25) — Lang 2024의 수치 의미와 적용 범위

1. **`r_min = 1.2 Å` 확정** — V = V_BO + V_rel + V_QED의 세 성분이 모두 직접 계산된 최소 거리. `R < 1.2 Å`: clamp 금지, 임의 반발로 교체 금지,
   Lang 식 외삽을 현실 Ar이라 주장 금지 → **`physics_domain_exceeded`로 중단.** 고에너지 충돌이 필요해지면 별도 closure에서 조사해 연결.
2. **물리 의미와 수치 의미 분리:** Lang의 해석식 = 수학 함수 `V_real(R)`. **A의 값 = `round_profile(V_real(R))`**(중간 반올림 없이 한 번).
   "정확"은 자연이 완벽하다는 뜻이 아니다 — 모델 불확도(σ)와 계산 오차는 **별개 장부**. VM 명령 배치·항 순서·Horner·CPU/GPU·소거 회피
   분기가 A의 물리적 V 값을 바꾸면 안 된다.
3. **종별 전용 VM 명령(`AR2_LANG2024` 등)을 만들지 않는다.** C1-A에서 **독립 기준 평가기(reference evaluator)**를 먼저 만든다 — 원문 매개변수를
   정확한 상수로, 초월 함수는 구간·충분한 정밀도로 감싸고, 한 값으로 확정될 때까지 정밀도 증가, 마지막에 한 번 반올림. 느려도 된다(정답을
   정의하는 계산기). 이후 B0/B1/B2는 Fortran처럼 분기·급수·소거 회피를 자유롭게 쓰되, **지원한다고 선언한 모든 입력에서 기준과 같은 비트** —
   못 맞추는 영역은 꾸며내지 말고 거부.
4. **힘:** 유한차분으로 정의하지 않는다. `F_real(R) = −dV_real/dR`(해석적), A 값 = `round_profile(F_real(R))`, 힘 벡터 `F⃗ = F(R)·r⃗/R`.
   새로 유도한 식이므로 **해석적 미분 구현**과 **고정밀 V의 독립 수치 미분(또는 자동/기호 미분 계열 감사)** 두 경로로 검증.
5. **C1-A 기준 단계만 먼저**(세계 커널에 넣지 않음): V 기준값, ±σ, R_e, D_e, 짧은 거리 반발, 긴 거리 점근, 지연 on/off, 해석적 힘,
   1.2 Å 경계, 1.2 Å 미만 거부. 기준 확정 뒤에만 B0/B1/B2로.
6. **극저온 물성은 C1-B 일반 검증과 분리:** 아홉 번째 진동 상태 존재 여부, 극저온 s파 산란 길이, 최고 진동 상태 결합 에너지는 퍼텐셜의
   작은 차이뿐 아니라 해석적 근사·보간 방법 자체에도 매우 민감하다(2026 Špirko 연구) → **별도 ultracold limitation**, Lang 2024 하나로 현실값
   확정 주장 금지. 상온·고온 희박 기체 검증 실패와 같은 판정으로 섞지 않는다.
7. **Cencek 2013은 C1-A의 선행조건이 아니다**(C1-C에서 필요). ACS SI에 `Ar3.f`, `E3.dat`, `params.txt`, `README`가 있음을 설계자가 확인 —
   C1-C 진입 전에 확보해 별도 계약 추출.

**구현 결과(C1-A 기준 평가기):** `A_MICRO_V6_ARAR_POTENTIAL_SURVEY_V1.md` 10절.

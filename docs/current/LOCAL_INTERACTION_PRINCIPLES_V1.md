## 왜 이 문서가 생겼는가

전제조건 조사에서 "한 칸에 3개가 모이면 커널이 건너뛴다"를 발견했고,
첫 대응으로 **"둘씩 짝지어 차례로 처리"** 를 제안했다.

**그 제안은 기각됐다.** 설계자의 지적:

> "둘씩 처리"는 단순 구현 편의처럼 보이지만 실제로는 아주 강한 물리 가정을 몰래 넣는다.
> **모든 다체 상호작용은 어떤 순서의 2체 상호작용으로 환원될 수 있다** — 이걸 세계 법칙으로
> 선언해버리는 셈이다.

이 지적이 맞다. `DETERMINISTIC_WORLD_LANGUAGE_DEEP_DESIGN_V1.md` 7.2절은 충돌 결과가
입사 방향·상대 속도·물질 종류·결합면 방향·저장 에너지·주변 공간·기존 결합에서
결정된다고 적었지 **2체만 허용한다고 적은 적이 없다.**

즉 "2개까지만"은 선언된 법칙이 아니라 구현에서 떨어져 나온 천장이다.
**causal v2 커밋이 고친 것과 정확히 같은 종류의 문제다** — 그때도 "최대 2개라는 한계는
규칙으로 선언된 적이 없고 산술에서 떨어져 나온 것"이었다. 같은 일이 3에서 재발했다.

## 채택한 원칙 4개

### 1. Cardinality neutrality — 참가자 수 중립

> 국소 물리 법칙은 특별한 물리적 근거가 없는 한 참가자 수(N=2, N=3)를 제한 조건으로
> 사용하지 않는다. 가능한 상호작용은 실제 접촉·기하·물성·에너지·결합 상태에서 결정한다.

`if len(group) != 2` 는 이 원칙 위반이다. `if len(group) == 3` 으로 바꾸는 것도
똑같이 위반이다. **개수가 법칙을 고르는 스위치가 되면 안 된다.**

### 2. No forced pairwise decomposition — 강제 2체 분해 금지

> 다체 상태를 구현 편의를 위해 임의의 순서의 2체 사건으로 강제 분해하지 않는다.
> **그 분해 순서가 결과를 바꾼다면 그것은 구현 순서가 물리 법칙으로 누출된 것이다.**

서로 양립 가능한 변화(같은 포트를 먹지 않고, 같은 에너지를 중복 소비하지 않고,
보존을 함께 만족)는 **하나의 원자적 상태 전이로 동시에 적용한다.**
`A-B를 먼저 만들고 다음 tick에 B-C`로 쪼갤 이유가 없다.

### 3. No arbitrary collision ordering — 임의 순서 금지

> 동시에 가능한 상호작용이 여러 개이고 현재 물리 상태가 결과를 유일하게 결정하지
> 못한다면, ID·배열 순서·thread 순서로 결정을 만들지 않는다.
> **필요한 물리 상태 변수가 누락된 것으로 판정한다.**

이게 가장 중요한 원칙이다. A 포트가 하나인데 B와 C 둘 다 결합 가능할 때
`particle_id가 작은 것 우선`을 넣으면 **그 순간 particle ID가 물리법칙이 된다.**

결정 불가능은 버그가 아니라 **신호**다 — 세계 상태 표현에 물리 정보가 빠져 있다는 신호.
부족한 자유도(sub-cell 위치, 도착 위상, 접촉면, 정확한 접촉 위치)를 찾아서 추가한다.

현실에서 서로 다른 위치에서 접촉했을 세 물체를 `(x=8, y=8)` 한 칸으로 붕괴시켜 놓고
"누가 먼저 부딪혔냐"고 물으면, **정보를 버려놓고 답을 요구하는 것이다.**

### 4. No artificial structural ceiling — 인위적 구조 상한 금지

> 구조의 성장·결합·변형에 사전에 정한 길이·참가자 수·크기 상한을 두지 않는다.
> 한계는 현재 물질·기하·에너지·보존 법칙·국소 상호작용 조건에서만 발생해야 한다.

허용되는 제한: 필요한 물질이 주변에 없음, 포트가 이미 점유됨, 기하적으로 공간이 없음,
에너지 부족, 결합 조건 불일치, 충돌로 구조가 깨짐.

금지되는 제한: `길이 3 이상 금지`, `움직이는 사슬 성장 금지`, `3개면 첫 둘만 처리`.

## 변이에 대한 따름정리

> **Mutation as physical divergence.** 변이는 별도 확률 사건이나 명령이 아니다.
> 정상적인 결합·절단·충돌·물질 도착 과정이 다른 국소 조건을 만나 다른 구조로
> 이어졌을 때, 그 차이를 **사후에** 변이로 분류한다.

`MUTATE()` 라는 사건은 존재하지 않는다. A+B+C가 `A-B-C`로 갈 예정이었는데
X가 먼저 포트를 차지해 `A-B-X`가 되거나, 충격으로 B-C가 끊겨 `A-B + C`가 남거나,
다른 orientation으로 접근해 직선 대신 다른 모양이 나오는 것 — 전부 같은 법칙의 결과다.

**결정론은 유지된다.** 같은 완전한 상태에서 같은 상호작용이 일어나면 같은 "변이"가
다시 일어난다. 미세하게 다른 충돌 역사나 물질 도착 순서 때문에 결과가 갈리는 구조이지,
확률로 뿅 생기는 게 아니다.

**진화 가능성을 만들려면 변이를 구현하면 안 되고, 변이가 일어날 수밖에 없는 자유도를
구현해야 한다.**

## 두 종류의 "3개 동시 결합"을 구분한다

섞으면 안 된다.

### ① 기존 pairwise 법칙 여러 개가 동시 성립 — **지금 열어도 된다**

```
    A
    ↓
→   B   ← C          B에 서로 다른 빈 포트 2개
```

A와 C가 각각 다른 포트에 접근하고 둘 다 조건을 만족하면,
한 local update에서 `A—B—C`가 바로 만들어진다.

기하가 허용하면 `A-B`, `B-C`, `C-A` 세 결합이 동시에 생기는 삼각형도 원칙적으로 가능하다.

**`THREE_BODY_BIND` 같은 새 명령이 필요 없다.** 기존 결합 법칙 두 개가 서로 충돌하지
않으니 동시에 성립한 것으로 처리하면 된다.

### ② 환원 불가능한 N체 상호작용 — **별도 물리 근거가 필요하다**

```
A + B + C → D
단, A+B 또는 B+C만으로는 절대 진행 안 됨
```

이건 `Bond(A,B)` + `Bond(B,C)` 두 개로 설명되지 않는다. `Bond(A,B,C)` 자체가
하나의 물리 관계이고, 셋 중 하나를 빼면 성질 자체가 사라진다.

현재 `PhysicalBond(left_id, right_id, ...)` 는 **두 노드 사이 edge로만 표현 가능**하다.
②를 표현하려면 hypergraph로 가야 한다:

```
현재:  Bond(A, B)

확장:  InteractionRelation(
           participants = [A, B, C, ...],
           ports = [...], geometry = ...,
           stored_energy = ..., constraints = ...)
```

**당장 모든 결합을 hyperedge로 바꾸자는 게 아니다.** ②가 실제로 필요한 현상을
만나기 전에는 열지 않는다. 다만 **자료구조 때문에 불가능해지는 것**은 기록해둔다 —
그게 이 프로젝트가 반복해서 당한 실패다.

## 목표 구조

```
한 tick에서 경로가 겹치는 모든 물질·구조 수집
        ↓  Local Interaction Set
실제 접촉 가능한 관계 계산
        ↓  Contact Graph  (장기적으로 Hypergraph)
가능한 elementary transition 생성
   ├─ 충돌  ├─ 에너지 전달  ├─ 결합  ├─ 절단  └─ 그대로 통과
        ↓
서로 양립 가능한 변화는 동시에 적용
        ↓
충돌하는 후보가 여러 개이고 현재 상태로 결정 불가능?
        ↓
임의 순서 선택 금지 → 부족한 물리 자유도 식별
   (sub-cell geometry / arrival phase / orientation / contact location)
```

핵심은 이것이다.

```
2개면 2체 물리 / 3개면 3체 물리 / 4개면 4체 물리     ← 아니다

N개가 한 국소 영역에 존재
  → 현재 위치·기하·포트·에너지·운동량·관계 확인
  → 가능한 elementary / joint interaction 도출
  → 서로 양립 가능한 변화는 동시 발생
  → 참가자 수 N은 그냥 결과적으로 정해짐       ← 이것이다
```

## 촉매에 대한 정정

**"촉매 = 세 물체가 동시에 충돌해야 한다"는 틀렸다.**
어제 조사 문서가 "촉매는 제3의 물체다 → 3체 조우가 전제"라고 적었는데, 그건 촉매의
한 경로일 뿐이다.

설계 문서 8.4절의 촉매 정의(반응물을 붙잡음, 중간 구조 안정화, 낮은 활성화 에너지
경로 제공, 반응 후 회수 가능)에 더 자연스러운 것은 **중간체를 거치는 과정**이다.

```
C + A    → C-A
C-A + B  → C-A-B
C-A-B    → C + A-B
```

이건 전부 2체 접촉으로도 진행될 수 있다. 다만 **어떤 반응은 여러 참가자의 배치가
동시에 맞아야 전이 상태가 형성될 수도 있다.**

따라서:
- "모든 반응은 pairwise로 환원된다" → 고정하면 촉매에서 또 벽을 만난다
- "모든 반응은 N-body다" → 과하다

일반 원칙: **국소 상태가 허용하는 최소한의 상호작용 관계를 사용하고, 참가자 수를
임의로 제한하지 않는다.**

진짜 필요한 것은 무조건적인 3체 충돌 규칙이 아니라, **이미 결합돼 있거나 움직이는
구조가 추가 물질과 계속 상호작용할 수 있는 일반적인 local interaction 체계**다.
이렇게 하면 3체뿐 아니라 4체·8체·고분자·촉매 표면까지 자연스럽게 확장된다.

멤버 (2,1), 도착 3  ->  두 번째 멤버에 결합
멤버 (4,7), 도착 9  ->  첫 번째
멤버 (7,4), 도착 9  ->  두 번째

**네 경우 모두 번호가 작은 쪽이 이긴다.** 이름표만 바꿨는데 결합 상대가 바뀐다.

나중에 커널이 이걸 상태에서 결정하게 되면 이 테스트가 깨지면서 알려준다.

부수적으로 발견: `CausalWorldState.__post_init__` 의
`a chain carries its motion on its lowest-numbered member` 도 **ID로 쓰인 불변조건**이다.
멤버를 재명명하면 유효하던 상태가 예외를 던진다. 같은 계열의 문제다.

## 구현 순서 — 2026-09-22 재판정: 기하가 단계 2의 **전제**다

처음에 기하를 "주형의 전제"로만 잡았는데 틀렸다. **양립 가능성 판정 자체가 기하를 요구한다.**

지금 상태로 simultaneous commit을 일반화하면:

```
A-B 가능, B-C 가능  ->  둘 다 동시 commit!
```

인데 실제 기하에서는 **두 접촉이 동시에 존재할 수 없었을 수도 있다.**
그러면 ID 순서 대신 **"기하 없는 병렬 commit"이 새로운 숨은 물리**가 된다.
같은 괴물이 이름만 바꿔 돌아오는 것이다.

`bonded particles must share the bond location` 때문에 현재 사슬은 한 점이라,
`A-B-C`인지 `A / B-C`인지 아니면 A와 C가 서로 안 닿는지 **표현할 방법이 없다.**

### 확정된 순서

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 경합 탐지 | **완료 (2026-09-22)** |
| 2 | **최소 국소 기하** — 구조 내부 상대 위치, 접촉면·포트 방향, 실제 접촉 관계, 구조가 움직여도 상대 기하 유지 | 다음 |
| 3 | Contact Graph — 현재 상태에서 실제 가능한 접촉만 생성 | |
| 4 | elementary transition 생성 — 결합·충돌·절단·에너지 전달·무변화 | |
| 5 | 양립 가능한 transition 동시 commit (원칙 2) | |
| 6 | 결정 불가능 시 임의 tie-break 금지, 부족한 자유도 보고 (원칙 3) | |
| 7 | cardinality 제한 제거 — 2개든 N개든 같은 경로 (원칙 1) | |
| 8 | 실제 필요가 확인되면 N-body relation / hyperedge (②) | |

### `len(group) != 2`를 먼저 지우면 안 된다

그 줄은 잘못된 법칙이지만, 지금은 역설적으로
**"기하 없는 상태에서 모호한 다체 물리를 실행하지 못하게 막는 벽"** 역할도 한다.

**먼저 표현 능력을 올리고, 그 다음에 벽을 제거한다.**

## 운동량이 최저 번호 멤버에 저장되는 구조 — 부수 발견이 아니다

처음에 이걸 부수 발견으로 적었는데, `_grow_chains`의 ID tie-break 못지않게 중요하다.

`a chain carries its motion on its lowest-numbered member` 는
**ID가 관찰용 이름표가 아니라 구조의 운동 상태 저장 위치를 결정한다**는 뜻이다.

장기적으로는 없애야 한다. 사슬의 운동량은

```
member 1이 보유 / member 2는 0 / member 3는 0     <- 지금
```

이 아니라

```
ConnectedComponentState
    total_momentum
    total_mass
    geometry
    angular/rotational state (향후)
```

처럼 **구조 자체의 상태**여야 한다. 그렇지 않으면 이름표 문제를 고쳐도 계속 나온다:

- 어느 멤버가 운동량을 대표하나
- 대표 멤버가 절단되면 어떻게 하나
- 두 구조가 합쳐질 때 누구 운동량 필드를 쓰나

## known-defect 테스트의 취급

`tests/test_known_defects_causal_kernel.py` 는 **결함이 존재함을 증명하는** 테스트다.
일반 회귀 테스트와 목적이 반대다 — **우리가 원하는 최종 상태는 그 테스트가 실패하는 것이다.**

파일 맨 위에 "실패는 좋은 소식이다. 고쳐진 것이다"와 교체 절차를 적어뒀다.
각 테스트에 `replace_with:` 로 고쳐진 뒤 무엇을 대신 단언해야 하는지도 명시했다.

이렇게 하지 않으면 몇 달 뒤 다른 AI가 빨간 테스트를 보고
**"회귀 발생! 고쳐야 합니다"** 하면서 ID 편향을 복원할 수 있다.
너무 인간다운 실패라 미리 막는 게 낫다.

현재 기록된 결함 3종:

| 테스트 | 결함 |
|---|---|
| `test_defect_kernel_is_not_relabelling_invariant` | 재명명이 결합 상대를 바꾼다 |
| ~~`test_defect_chain_motion_is_stored_on_the_lowest_numbered_member`~~ | ID가 운동량 저장 위치를 정한다 — **v4에서 해결 (2026-09-24, Stage B)**, v2는 레거시 파일로 이동 |
| `test_defect_a_chain_takes_at_most_one_arrival_per_tick` | 선언되지 않은 1 tick 1 결합 천장 |

커널 코드에도 같은 지점에 `KNOWN DEFECT` / `DEFECT` 주석을 달았다.
문서를 찾아가지 않아도 코드만 읽고 알 수 있어야 한다.

`RULES.md` 3절대로, 새 규칙마다 결함을 주입해 잡히는지 확인한다.

## 0. 5문장 검사 — 구현 전 필수 관문

`PREIMPLEMENTATION_POSSIBILITY_CHECK_V1.md` 25절이 이 단계에 이 검사를
적용하라고 지정했다. **추측이 아니라 실제 코드로 측정한 답을 적는다.**

### 질문 1 — 무엇이 실제로 존재하는가?

```
CausalParticleSpec : particle_id, kind, x, y, direction, orientation, kinetic_energy
CausalWorldState   : tick, particles, heat, bonds, port_limits,
                     chains_may_move, grid_size, named_ports, port_bonds
PortBond           : left_id, left_port, right_id, right_port, rule_id, stored_energy
```

**운동은 입자에만 있다** — `direction`(방향) + `kinetic_energy`(크기).
구조 수준의 운동 상태는 **어디에도 없다.** 사슬은 `chains()`가 결합에서
매번 다시 계산하는 파생물일 뿐, 자기 상태를 가진 적이 없다.

### 질문 2 — 어떤 결과들이 물리적으로 가능할 수 있는가?

구조 `A—B—C`가 한 tick에 할 수 있는 일:

```
전체가 한 몸으로 평행 이동
정지 (운동량 0)
일부 멤버만 움직이려 함 → 구조가 늘어나거나 끊어짐
외부 충돌로 감속·정지
결합 절단 후 조각들이 각자 이동
(향후) 회전
(향후) 두 구조끼리 충돌
```

**지금 코드가 허용하는 것은 첫 둘뿐이다.** 나머지는 미구현이거나 미정의다.
그 사실 자체는 정당하다 — 범위를 좁게 잡는 건 괜찮다. **문제는 첫 둘조차
ID로 결정하고 있다는 것이다.**

### 질문 3 — 그중 서로 동시에 가능한 것은 무엇인가?

```
전체 이동  +  내부 결합 유지          → 양립 (같은 상대 기하로 함께 이동)
전체 이동  +  외부 입자와 새 결합      → 양립 여부는 도착 기하가 정한다
전체 이동  +  같은 칸으로 다른 구조 이동 → 양립 불가 (공간 경합)
```

세 번째는 **이번 단계 범위 밖**이다(구조끼리 충돌은 미정의).
1·2번을 다루되, 3번이 나타나면 원칙 3대로 **보고하고 멈춘다.**

### 질문 4 — 하나만 일어나야 한다면 무엇이 그것을 결정하는가?

**측정했다.** `_stream_free`에 `min(members)`가 세 번 나온다:

```python
holder = by_id[min(members)]
if holder.kinetic_energy:
    chain_step[min(members)] = VELOCITY[holder.direction]
...
step = chain_step.get(min(members)) if members else None
```

> **구조 전체의 이동 방향은 "번호가 가장 낮은 멤버의 `direction`"이 정한다.**

실제로 돌려본 결과:

```
최저 번호 멤버가 E 보유 → 구조 전체가 (8,8) → (9,8)
최저 번호 멤버가 N 보유 → 구조 전체가 (8,8) → (8,7)
```

**답이 ID다.** 질문 5로 간다.

### 질문 5 — 그 답이 ID·순서라면 어떤 물리 정보가 빠졌는가?

**재명명 실험으로 증명했다.** 물리적으로 완전히 동일한 상황
(한 멤버가 E로 움직이고, 결합한 다른 멤버는 정지)을 이름만 바꿔 두 번 만들었다:

```
움직이는 쪽 = 1번, 정지 = 2번  →  구조가 (9,8)로 이동. 정상
움직이는 쪽 = 2번, 정지 = 1번  →  ValueError:
                                  "a chain carries its motion on its
                                   lowest-numbered member"
```

**같은 물리인데 이름표만 바꾸면 상태 자체가 거부된다.**
이건 `test_defect_chain_motion_is_stored_on_the_lowest_numbered_member`로
이미 기록해둔 결함이다(`tests/test_known_defects_causal_kernel.py`).

> **빠진 물리 정보: 구조 수준 운동량(structure-level momentum).**
>
> 지금은 "구조가 어디로 얼마나 빨리 가는가"를 저장할 곳이 없어서,
> 멤버 하나에 얹어놓고 "그 하나는 최저 번호여야 한다"는 규칙으로
> 억지로 유일하게 만들었다. **번호가 물리를 하고 있는 이유가 이것이다.**

## 1. 지금 구조가 이렇게 된 이유 — 변호

`__post_init__`의 해당 주석은 이렇게 적고 있다:

> 사슬은 운동을 정확히 한 멤버에만 싣는다. 복사본을 모든 멤버에 퍼뜨리면
> 같은 운동이 에너지·운동량 총합에서 여러 번 세어지므로, 단일 보유자가
> "사슬이 움직인다"를 서술이 아니라 **양**으로 만든다.

**이 걱정은 옳다.** 운동량을 멤버마다 복제하면 `total_energy()`와
`momentum()`이 같은 운동을 N번 센다. 보존 검사가 즉시 깨진다.

문제는 **해결책**이었다. "한 곳에만 저장"은 맞지만, 그 한 곳을
**멤버 중 하나**로 고른 게 잘못이다. 올바른 답은 **구조 자체**다 —
구조는 하나뿐이므로 중복 계산이 애초에 불가능하다.

## 2. 제안하는 표현

### 2.1 `StructureState`

```
StructureState(
    members       : frozenset[int]      -- 이 구조에 속한 입자 id
    momentum      : tuple[int, int]     -- (px, py). 구조 전체의 운동량
    motion_energy : int                 -- 구조의 평행 이동 에너지
)
```

**`motion_energy`를 따로 두는 이유는 3.2에서 측정으로 증명됐다** —
총 운동량이 같아도 원래 에너지가 다를 수 있으므로, 이 둘은 중복이 아니라
**서로 독립인 상태량**이다.

**저장하지 않는 것과 그 이유:**

| 항목 | 왜 저장 안 하나 |
|---|---|
| `total_mass` | `members` + 재료 명세에서 유도된다. 저장하면 두 곳이 어긋날 수 있다 |
| `geometry` | 멤버들의 `(x,y)`가 이미 갖고 있다 |
| `topology` | `port_bonds`가 이미 갖고 있다 |
| `direction`/`speed` | `momentum`에서 유도. 둘을 같이 저장하면 불일치 가능 |

**원칙:** 유도 가능한 것은 저장하지 않는다. 저장된 값이 둘이면 언젠가 어긋나고,
어긋나면 어느 쪽이 진실인지 정하는 새 규칙이 필요해진다 — 또 하나의 숨은 법칙.

**단, `motion_energy`는 유도 불가능함이 증명되었으므로 이 원칙의 예외가 아니다.**
원칙은 "유도 가능한 것"에만 적용된다.

### 2.2 운동량을 방향+크기가 아니라 벡터로 두는 이유

지금 입자는 `direction`(N/E/S/W) + `kinetic_energy`(정수)로 운동을 표현한다.
구조도 같은 방식을 쓸 수 있지만, **벡터가 더 정직하다**:

```
입자 둘이 결합:  하나는 E로 3,  하나는 N으로 3
  방향+크기 표현: "E이면서 N"을 표현할 수 없다 → 어느 하나를 버려야 함
  벡터 표현    : (3, -3). 그대로 보존된다
```

구조는 여러 입자의 운동량이 합쳐지는 곳이므로 **대각 성분이 자연스럽게 생긴다.**
방향+크기로 두면 그때마다 "대각은 금지"라는 선언 안 된 제약이 생긴다
— 원칙 4(인위적 구조 상한) 위반이다.

**다만 이동은 여전히 카디널이다.** `(3,-3)`을 가진 구조가 한 tick에
어떻게 움직이는지는 **별도 문제**이고, 아래 4절에서 다룬다.

### 2.3 입자의 운동과의 관계

```
자유 입자        : 자기 direction + kinetic_energy 를 그대로 가진다 (변화 없음)
구조 멤버        : kinetic_energy = 0. 운동은 StructureState 가 가진다
```

멤버의 `kinetic_energy`를 0으로 두는 건 지금 v1 규칙과 같다.
**달라지는 것은 "그럼 운동은 어디 있나"의 답뿐이다** —
지금은 "최저 번호 멤버", 앞으로는 "구조".

## 3. 보존이 어떻게 유지되는가

이게 이 설계의 핵심 검증 지점이다.

### 3.1 운동량

```
지금:   구조 운동량 = mass(구조 전체) × holder.kinetic_energy × VELOCITY[holder.direction]
제안:   구조 운동량 = StructureState.momentum          (그냥 읽으면 된다)
```

`momentum()`에서 `min(members)` 조회가 통째로 사라진다.

### 3.2 에너지 — **첫 권고안이 측정으로 반박됐다**

지금은 `kinetic_energy`가 곧 에너지이고, 운동량은 거기에 질량을 곱한 것이다:

```
momentum = mass × kinetic_energy × VELOCITY[direction]
```

처음에 "에너지 = 맨해튼 운동량 `|px|+|py|`"를 권고했다. **측정해보니 틀렸다.**

```
질량 2인 사슬, 보유 에너지 3:
  현재 momentum()      = (6, 0)
  현재 total_energy()  = 7   (운동 3 + 결합 저장 4)
  |px|+|py|            = 6   ← 에너지 3의 2배
```

**운동량은 질량이 곱해진 양이라 에너지와 단위가 다르다.** 질량이 1이면
우연히 같아 보이지만, 사슬은 질량이 2 이상이므로 바로 어긋난다.

#### 고친 권고 — 에너지는 운동량을 질량으로 나눈 것

```
energy = (|px| + |py|) // total_mass
```

**그런데 이게 항상 정확히 나누어떨어지지 않는다.**

한 몸으로 움직이는 사슬은 운동량이 `mass × energy`로 **만들어진** 것이라
항상 떨어진다. 하지만 **서로 다른 운동량을 가진 멤버들이 합쳐져 구조가
되면** 그렇지 않다:

```
멤버 둘의 운동량 3과 2가 합쳐져 5,  구조 질량 2  →  5/2 는 정수가 아니다
```

**이건 새 문제가 아니다.** `_grow_chains`가 이미 같은 벽을 만나고 있다:

```python
if carried % total_mass:
    continue        # no exact integer velocity for the joined body
```

도착 입자를 흡수할 때 정수 속도가 안 나오면 **결합 자체를 거부**한다.
즉 기존 물리가 이미 "정수로 안 떨어지면 그 일은 일어나지 않는다"를
선택하고 있다.

#### 두 번째 반박 — 운동량만으로는 에너지를 복원할 수 없다

수정안도 반박됐다. **총 운동량이 같아도 원래 에너지가 다를 수 있다:**

```
경우 A: 멤버 둘의 운동량 +3, -1    총 운동량 2,  멤버가 지녔던 에너지 4
경우 B: 멤버 둘의 운동량 +2,  0    총 운동량 2,  멤버가 지녔던 에너지 2

둘 다:  members=2, total_mass=2, momentum=(2,0)
        -> 완전히 동일한 StructureState
        -> 공식은 양쪽 다 (|2|+|0|)//2 = 1 을 낸다
```

**원래 에너지 4와 2를 구별할 수 없고, 공식이 내는 1은 어느 쪽도 아니다.**

극단적으로 `A→3, B←3`이면 총 운동량은 0인데, 움직이던 둘이 갖고 있던
에너지가 0이었을 리는 없다. **그 에너지는 어디론가 가야 한다.**

#### 그런데 — 기존 코드에 이미 답이 있었다

Q2를 확정하기 전에 실제 에너지 경로를 측정했다. 세 실험 전부 돌렸다.

**실험 ① 정면 충돌 (운동량 상쇄):**
```
BEFORE  momentum (0,0)   energy 6    입자 둘이 각각 KE 3
AFTER   momentum (0,0)   energy 6    입자 둘 다 KE 0
                                      bond.stored_energy = 6
```
**에너지가 사라지지 않는다.** 상쇄된 운동 에너지 6이 전부
`bond.stored_energy`로 들어간다. 이미 구현된 경로다.

**실험 ③ 직각 운동량:**
```
BEFORE  momentum (3,-3)   energy 6
AFTER   momentum (3,-3)   energy 6    bonds: 0   ← 결합이 안 생겼다
```
`_resolve_collisions`가 자유 입자 쌍의 결합에
**`momentum == (0, 0)`을 요구**하기 때문이다. 직각으로 만나면 결합 자체가
일어나지 않고 그냥 지나간다.

**실험 ② 정지한 사슬이 다른 방향 입자를 흡수:**
```
BEFORE  momentum (0,-3)   energy 7
AFTER   momentum (0,-3)   energy 7    사슬 전체가 N 방향을 갖게 됨
```
`_grow_chains`가 사슬의 방향을 **도착 입자의 방향으로 덮어쓴다**
(벡터 합이 아니다). 그리고 **움직이는 사슬은 성장 대상에서 제외**되므로
(`if holder.kinetic_energy: continue`), 사슬이 두 방향 운동량을 동시에
가질 기회가 없다.

#### 확정된 결론

> **지금 코드에서 구조가 가질 수 있는 운동량은 전부 카디널이다.
> 대각 운동량은 "정의되지 않은" 것이 아니라 "도달 불가능"하다.**

따라서:

1. **`StructureState`는 운동량과 에너지를 둘 다 저장한다.**
   운동량에서 에너지가 유일하게 유도되지 않음이 증명됐으므로,
   이 둘은 중복 정보가 아니라 **서로 다른 상태량**이다.
   2.1의 "유도 가능한 것은 저장 안 한다" 원칙은 **유도 가능할 때만**
   적용된다.

2. **불일치 검사가 필요하다.** `momentum`과 `motion_energy`가 서로
   모순되면 거부한다. 카디널 운동만 도달 가능하므로 당분간 검사는
   단순하다: `|px| + |py| == motion_energy × total_mass`.
   **대각이 도달 가능해지면 이 검사부터 다시 설계해야 한다.**

3. **상쇄로 사라지는 운동 에너지는 이미 `bond.stored_energy`로 간다.**
   새 경로를 발명할 필요가 없다. 구조를 만들 때도 같은 경로를 쓴다.

**이 결론도 틀릴 수 있다.** 그래서 구현 순서에서 **보존 재검증을
재명명 불변성보다 먼저** 둔다(6절, Q5).

## 3.5 구조의 생명주기 — **타입 정의보다 이쪽이 어렵다**

> 팀의 공동 통장을 만드는 것은 쉽다. 어려운 것은 **새 사람이 들어오면 돈을
> 어떻게 합치고, 한 사람이 나가면 어떻게 나누는가**다.

`StructureState`를 정의하는 것보다 **구조가 생기고 사라질 때 보존이
유지되는지**가 훨씬 어렵다. 이걸 정의하지 않으면 나중에
"대표 멤버의 운동량을 그냥 복사" 같은 악령이 돌아온다.

다섯 사건 각각에 대해 **before/after 회계를 명시한다.**

### CREATE — 자유 입자 둘이 결합해 구조가 생김

```
before:  자유입자 A(운동량 pA, 에너지 eA), 자유입자 B(pB, eB)
after:   Structure(members={A,B}, momentum=pA+pB, motion_energy=?)
         + bond.stored_energy
```

**측정된 현재 동작(실험 ①):** 자유 입자 쌍은 `momentum == (0,0)`일 때만
결합하고, 그때 **운동 에너지 전부가 `bond.stored_energy`로 간다.**

```
motion_energy = 0                      (운동량이 0이므로)
bond.stored_energy = eA + eB           (측정: 3+3 → 6)
```

**보존 조건:** `eA + eB == motion_energy + bond.stored_energy`

### GROW — 구조가 자유 입자를 흡수

```
before:  Structure(M, p, e) + 자유입자 C(pC, eC)
after:   Structure(M∪{C}, p + pC, e')  + 새 bond.stored_energy
```

**측정된 현재 동작(실험 ②):** 정지한 사슬만 성장하고
(`if holder.kinetic_energy: continue`), 합쳐진 몸의 속도는
`carried // total_mass`, 나머지는 결합에 흡수된다.

```
speed    = (mass_C × eC) // (mass_M + mass_C)      정확히 나누어떨어질 때만
absorbed = eC - speed                               → bond.stored_energy
```

**나누어떨어지지 않으면 결합이 일어나지 않는다** — 이미 구현된 규칙이고,
정수 물리의 결과이지 임의 금지가 아니다.

### MERGE — 구조 둘이 결합

```
before:  Structure(M1, p1, e1) + Structure(M2, p2, e2)
after:   Structure(M1∪M2, p1+p2, e')
```

**미측정.** 지금 코드에 구조끼리 결합하는 경로가 없다
(`_grow_chains`는 자유 입자만 흡수한다).

**따라서 이 사건은 이번 단계에서 정의하지 않는다.** 정의하려면
"운동량이 상쇄될 때 남는 에너지를 어디로 보낼지"를 CREATE와 같은
방식으로 정해야 하는데, 그건 구조끼리 충돌 규칙(단계 4+)이 먼저다.

### SPLIT — 결합이 끊겨 구조가 나뉨

```
before:  Structure(M, p, e)
after:   Structure(M1, p1, e1) + Structure(M2, p2, e2)   또는 자유 입자
         + bond.stored_energy 가 방출됨
```

**부분적으로 측정됨.** `_break_existing`이 결합을 끊을 때:

```
released = bond.stored_energy + rule.break_heat
each     = released // 2                  ← 양쪽에 정확히 반씩
```

**그런데 이건 v1/v2의 "결합이 끊기면 두 입자가 각자 반대 방향으로
튀어나간다" 규칙이다.** 구조가 셋 이상일 때 어떻게 나뉘는지는
**정의되어 있지 않다.**

**미해결 질문:**
- 길이 4 사슬의 가운데 결합이 끊기면 운동량 `p`를 두 조각에 어떻게 나누나?
- 질량 비례로 나누면 정수로 안 떨어질 수 있다
- 그때 SPLIT 자체가 일어나지 않는 것이 맞나?

**이번 단계에서 정의하지 않는다.** 단, 이 질문을 여기 기록해둔다 —
나중에 "절단이 왜 안 되지?"를 다시 발견하지 않도록.

### DISSOLVE — 구조가 완전히 해체되어 자유 입자로

```
before:  Structure(M, p, e)
after:   자유 입자들
```

**여기서 Q4의 빚이 터진다.** 자유 입자는
`direction`(N/E/S/W) + `kinetic_energy`(정수)만 가진다.
구조가 `(3,-3)` 같은 대각 운동량을 가졌다면 **자유 입자 언어로
표현할 수 없다.**

**다행히 3.2에서 측정한 대로 대각 운동량은 현재 도달 불가능하므로,
이 문제가 지금 당장 터지지는 않는다.** 하지만 대각이 도달 가능해지는
순간(단계 4에서 구조 이동을 정의할 때) **DISSOLVE가 먼저 깨진다.**

> **기록해둘 빚:** 구조 이동을 정의하기 전에
> `StructureState ↔ 자유 입자` 운동 표현 변환이 가능한지 먼저 검사한다.

### 요약 — 이번 단계가 정의하는 것과 미루는 것

| 사건 | 이번 단계 | 근거 |
|---|---|---|
| CREATE | **정의** | 실험 ①로 현재 동작 측정 완료 |
| GROW | **정의** | 실험 ②로 현재 동작 측정 완료 |
| MERGE | **미정의** | 코드에 경로 자체가 없음 |
| SPLIT | **부분 정의** | 2체는 측정됨, 3체 이상은 미해결 |
| DISSOLVE | **미정의** | Q4의 표현 변환 문제가 선행 |

**미정의를 숨기지 않는다.** 미정의 사건이 일어나려 하면 원칙 3대로
**보고하고 멈춘다.**

## 4. 열어두는 것과 닫는 것 — 정직하게

### 4.1 이번 단계가 **답하지 않는** 질문

| 질문 | 왜 미룸 |
|---|---|
| 구조가 대각 운동량을 가지면 한 tick에 어떻게 움직이나? | **4.2에서 다룸. 이게 가장 큰 미해결** |
| 두 구조가 같은 칸으로 가려 하면? | 구조끼리 충돌은 미정의 (단계 4+) |

| 구조가 외부 입자와 부딪히면? | 단계 5(접촉 그래프) 이후 |

### 4.2 대각 운동량의 이동 — 미해결 문제

`momentum = (3, -3)`인 구조는 한 tick에 어디로 가야 하나?

```
후보 1: 대각으로 한 칸 (9,7)          → 격자에 대각 이동이 없다. 새 물리
후보 2: x 성분만 이동, y는 누적        → 어느 축을 먼저? 그게 또 임의 순서
후보 3: 이동 안 함 (정수 나눗셈 실패)   → 원칙 4 위반? 아니면 정당한 물리?
후보 4: tick을 나눠 x·y를 번갈아       → 숨은 상태(위상)가 필요
```

**이 문제는 이번 설계가 풀지 않는다.** 대신:

> **StructureState는 대각 운동량을 *표현*할 수 있게 하되, 그런 구조의
> *이동*은 아직 정의하지 않는다. 대각 운동량을 가진 구조를 이동시키려
> 하면 — 원칙 3대로 — **"물리 정보가 부족하다"고 보고하고 멈춘다.**

**보고 방식:** 일반 개발 오류(`NotImplementedError`)가 아니라
**물리적으로 결정 불가능하다는 기록**으로 남긴다:

```
UnresolvedMotion(
    reason = "insufficient_physical_state",
    structure = ...,
    momentum = (3, -3),
)
```

이유는 **나중에 census로 세기 위해서**다. `contested_census`가 경합을
세듯이, 결정 불가능한 이동이 실제로 몇 번 일어나는지 측정할 수 있어야
한다. 개발 오류로 던지면 "일어나면 안 되는 일"이 되지만, 기록으로
남기면 **"얼마나 자주 일어나는가"를 물을 수 있다.**

**그리고 3.2의 측정이 이 문제의 긴급도를 낮춰준다:**

> 지금 코드에서 대각 운동량은 **도달 불가능**하다. 자유 입자 쌍은
> `momentum == (0,0)`일 때만 결합하고, 움직이는 사슬은 성장하지 않으며,
> 정지한 사슬은 도착 입자의 방향을 통째로 물려받는다.

즉 **대각 이동 규칙이 없어도 지금은 아무것도 막히지 않는다.**
표현만 열어두고 규칙은 미루는 것이 실제로 안전하다.

> **단계 4(구조 이동)의 진짜 과제가 바로 이것**이라는 걸 여기서 미리 못 박는다.
> 카디널 운동량만 다루면 단계 4는 쉽고, 대각을 다루면 새 자유도가 필요하다.
> **그리고 대각이 도달 가능해지는 순간 DISSOLVE(3.5절)가 먼저 깨진다.**

## 7. 결정 — **확정됨 (2026-09-22)**

| | 질문 | 판단 |
|---|---|---|
| Q1 | 운동량을 벡터로 | **승인** |
| Q2 | 에너지를 운동량에서 유도 | **기각 → 별도 저장으로 확정** |
| Q3 | 대각 운동량 구조의 이동 | **승인** (표현만, 이동은 결정 불가로 보고) |
| Q4 | 자유 입자 통일 | **조건부 승인** (전환 검사 부채 기록) |
| Q5 | 보존 검증 우선 | **승인** (단, 성공 기준 강화) |

### Q1. 벡터 운동량 — 승인

`momentum: tuple[int, int]`.

여러 멤버의 운동량이 합쳐질 때 E 성분과 N 성분이 동시에 존재할 수 있다.
`direction + magnitude`로는 하나를 버려야 한다.

```
(3, 0)  + (0, -3)  = (3, -3)      둘 다 보존
(3, 0)  + (-3, 0)  = (0, 0)       상쇄
(5, 0)  + (-3, 0)  = (2, 0)       부분 상쇄
```

**주의 — 비유의 정확한 의미:** "힘센 쪽이 이긴다"가 아니다. 서로 반대
방향일 때는 차이가 남지만, **직각이면 합쳐진 새 방향이 생긴다.**
동쪽 3과 북쪽 3은 "동쪽이 이김"이 아니라 `(3,-3)`이다.

또한 여기서 다루는 것은 **힘(force)이 아니라 이미 가진 운동량**이다.
힘과 지속 시간이 운동량을 바꾸는 문제(`force × time = Δmomentum`)는
**다음 계층**이고 이번 단계 범위가 아니다.

### Q2. 에너지 유도 — **기각. 별도 상태량으로 저장한다**

권고안이 **두 번 반박됐다** (3.2 참조):

1. 첫 안(맨해튼 합) — 질량 2에서 에너지 3인데 운동량 6. 단위가 다름
2. 수정안(`// total_mass`) — **총 운동량이 같아도 원래 에너지가 다를 수 있음**

```
멤버 운동량 +3, -1  →  총 2, 원래 에너지 4
멤버 운동량 +2,  0  →  총 2, 원래 에너지 2
                       동일한 StructureState, 공식은 양쪽 다 1
```

**확정:** `StructureState(members, momentum, motion_energy)` — 셋 다 저장.
운동량에서 에너지가 유일하게 유도되지 않음이 증명되었으므로
**중복 정보가 아니라 독립 상태량**이다.

**불일치 검사:** 카디널 운동만 도달 가능한 현재는
`|px| + |py| == motion_energy × total_mass`. 대각이 도달 가능해지면
이 검사부터 다시 설계한다.

**상쇄된 에너지의 행선지는 이미 존재한다** — 실험 ①에서 측정한 대로
`bond.stored_energy`로 간다. 새 경로를 발명하지 않는다.

### Q3. 대각 운동량 구조의 이동 — 승인

표현은 허용하고 이동은 정의하지 않는다. 보고는
`UnresolvedMotion(reason="insufficient_physical_state")`로 —
**개발 오류가 아니라 census로 셀 수 있는 물리 기록**으로 남긴다 (4.2 참조).

측정 결과 **대각 운동량은 현재 도달 불가능**하므로 이 결정으로
막히는 것이 없다.

### Q4. 자유 입자 통일 — 조건부 승인

**단계 3에서는 자유 입자를 건드리지 않는다.** 변경 범위를 줄이고
v1/v2 호환을 지키기 위해서다.

**단, 부채를 기록한다:**

> 구조의 병합·절단(MERGE/SPLIT/DISSOLVE)을 구현하기 전에,
> `StructureState ↔ 자유 입자` 운동 표현 변환이 가능한지 다시 검사한다.

자유 입자는 `direction`(N/E/S/W) + `kinetic_energy`만 가지므로,
구조가 대각 운동량을 갖게 되는 순간 **DISSOLVE에서 표현 손실이 생긴다**
(3.5절 DISSOLVE 참조). 지금은 대각이 도달 불가능해서 터지지 않을 뿐이다.

### Q5. 보존 검증 우선 — 승인, 단 성공 기준 강화

**구현 순서(보존 재검증 → 재명명 불변성)는 그대로 승인.**

**그러나 성공 기준을 고친다.**

기존: `test_defect_chain_motion_is_stored_on_the_lowest_numbered_member`가
깨지면 성공.

**이건 필요조건이지 충분조건이 아니다.** 옛 결함 테스트가 깨지는 것은
"옛 행동이 사라졌다"는 뜻일 뿐, **새 행동이 옳다는 증거가 아니다.**

**진짜 성공 기준 — positive relabeling invariance:**

```
state          --step-->  result
relabel(state) --step-->  relabelled_result

성공 조건:  relabel(result) == relabelled_result
```

그리고 **한 가지 치환으로 끝내지 않는다.** 원칙 3은 ID뿐 아니라
배열 순서·thread 순서도 물리를 결정하면 안 된다고 했다:

| 바꾸는 것 | 물리 결과 |
|---|---|
| 입자 id (`1,2,3` → `91,7,44`) | 동등해야 함 |
| `particles` 배열 순서 | 동등해야 함 |
| `bonds` 배열 순서 | 동등해야 함 |
| bond endpoint 순서 (`(A,B)` → `(B,A)`) | 동등해야 함 |
| 동일 규칙의 선언 순서 | 동등해야 함 |

**이것을 "비물리 정보 변환 테스트"로 일반화한다.**

이 설계를 구현하려다 아래 둘을 먼저 발견했다. 둘 다 **이 설계보다 아래
계층**이므로 순서를 바꿨다.

### 9.1 v3 구조가 tick을 못 넘겼다 — **해결됨**

```
BEFORE  port_bonds=2  grid=(16,16)  named_ports=1
AFTER   port_bonds=0  grid=None     named_ports=0
```

세 단계와 `step_causal_world`가 `CausalWorldState`를 위치 인수 여섯 개로
재구성하고 있어, `chains_may_move` 뒤의 필드가 전부 버려졌다. **구조 이동을
설계하기 전에 구조가 시간축에서 살아남는 것이 먼저다.**

`dataclasses.replace`로 전환해 해결했다. 이 설계가 추가할 `structures` 필드도
같은 방식으로 증발할 뻔했으므로, **`StructureState` 구현 전에 고친 것이 맞다.**

**그리고 커널만 고친 것으로 끝나지 않았다.** 같은 패턴이 커널을 감싸는
모듈들에 남아 있었다:

```
environment_kernel   4곳
gpu_environment      2곳
counterfactual       1곳
```

환경 쪽은 더 나빴다 — 인수를 **네 개**만 넘기고 있어서 `port_limits`와
`chains_may_move`까지 잃었다. 측정값:

```
BEFORE  port_limits={0:4}  chains=True   grid=(16,16)  named=1
AFTER   port_limits={}     chains=False  grid=None     named=0
```

즉 **v2 사슬도 환경 세계 안에서는 작동하지 않았다.** 이건 v3만의 문제가
아니었고, 아무도 알아채지 못한 이유는 환경 세계가 입자를 거의 쓰지 않기
때문이다.

재발을 막기 위해 테스트를 **모듈 전체를 AST로 훑도록** 만들었다. 정당한
생성자는 `initial_causal_state` 하나뿐이고(스펙에서 첫 상태를 만들므로
`replace` 할 대상이 없다), 나머지가 직접 생성하면 빨간불이 된다.

테스트: `tests/test_deterministic_v3_state_persistence.py`

### 9.2 자유 입자 충돌이 운동량을 회전시킨다 — **미해결, 기록됨**

```
N/1 + S/2  ->  E/1 + W/2        운동량 (0,1) -> (-1,0)
```

A0의 고정 속도 격자 충돌 규칙을 causal이 물려받았는데, causal은
`kinetic_energy`를 추가했다. 규칙이 의존하던 "운동량 크기가 같다"는 전제만
사라졌다.

**이 설계에 직접 영향을 준다.** 3.2절이 CREATE의 에너지 회계를 실험 ①로
측정했는데, 그 실험은 에너지가 같은 쌍이었다. 에너지가 다른 쌍은 **한 tick도
돌지 않는다** — 커널 자신의 보존 검사가 raise 한다. 즉 3.5절 CREATE의
보존 조건은 **등에너지 경우에만 측정된 것**이다.

> **순서 판단:** 자유 입자 충돌이 운동량을 깨는 상태에서 그 위에 구조의
> 운동량·에너지를 얹으면 원인 추적이 꼬인다. **9.2를 먼저 해결하고
> `StructureState` 구현으로 간다.**

**그리고 "해결"의 방식이 확정됐다 (2026-09-22).** 고치려고 시도했더니
**v1의 digest가 바뀌었다** — 이 결함은 포맷 무관 공용 코드에 있어서
causal 도입 시점부터 v1에 있었다. `LANGUAGE_REVISION_GOVERNANCE_V1.md`
9·10번(기존 버전 의미를 조용히 바꾸지 않는다)에 따라 **v1/v2/v3는
레거시로 동결하고 새 버전 v4에서 고친다.**

같은 조사에서 **두 번째 유형 F 결함**도 나왔다 — 산란과 절단이
`orientation`까지 함께 회전시키는데, 그런 회전 법칙은 선언된 적이 없다
(A0에는 `orientation` 필드 자체가 없었다).

> **따라서 이 설계의 구현은 v4 Stage B다.** v4 Stage A(수정된 충돌 의미)가
> 먼저다. v4의 범위는 처음부터 "충돌 의미 수정 + 구조가 소유하는 운동
> 상태"로 선언되므로, `StructureState`가 나중에 v4의 의미를 바꾸는 것이
> 아니라 예정된 단계다.
>
> 설계: `CAUSAL_COLLISION_SEMANTICS_V4.md`

기록: `tests/test_known_defects_causal_kernel.py::test_defect_unequal_energy_head_on_same_kind_breaks_momentum`
교훈: `VERIFICATION_LIMITS_AND_LESSONS.md` 유형 F

### 9.3 대각 도달 불가능성을 테스트로 고정 — **완료**

3.2절과 4.2절, 3.5절이 전부 "대각은 도달 불가능"에 기대고 있다. 그러면
그것은 설명이 아니라 **하중을 받는 전제조건**이므로 문서가 아니라 테스트에
둔다.

실제 세계 파일(`polymer_chain_v2`) 실행에서 움직이는 구조 4건, 운동량
`(3,0)` — 전부 카디널임을 확인했다. 누군가 결합·성장 규칙을 바꿔 대각이
처음 생기는 순간 빨간불이 되고, 그것은 회귀가 아니라 **DISSOLVE(3.5)와
구조 이동(4.2)을 다시 열라는 신호**다.

테스트: `tests/test_diagonal_momentum_is_unreachable.py`

# GEO v1B — v5 위에서 구조의 생성·성장 검증 (계획)

**상태:** **승인 (2026-09-24)** — D1~D4 판정과 수정 6개 반영(7절). 구현한다.
**바닥:** v5 기준 실행기 `311c7c5`(동결 후보 승인), 측정 `A_MICRO_V5_BENCHMARKS_V1.md`.
**설계자 방향:** 접촉 계산을 다시 만들지 않는다. 이미 검증된 면 접촉 위에서 CREATE·GROW가 **순서·이름·배열에 독립적으로**
구조를 만드는지, 그 **기하와 인과**를 검증한다. 현실 화학은 넣지 않는다(재료·결합 모델 교체 때 현실 근거 원칙 적용).

---

## 0. 먼저 — v5는 이미 무엇을 하는가 (측정한 사실)

GEO v1(`A_V4_GEO_CONTACT_GROWTH_V1.md`)은 v4에서 구조가 생길 수 없다는 문제에서 출발했다. v5 기준 실행기는 이미:

| 사건 | v5에서 | 근거 |
|---|---|---|
| CREATE (자유 입자 + 자유 입자) | 됨 | 멤버 하나짜리 구조 둘의 병합 |
| GROW (구조 + 자유 입자) | 됨, **움직이는 구조도** | 같은 병합 |
| **MERGE (구조 + 구조)** | **이미 됨** | E3 병합 보존식 `U' = ΣU + ΣK − K'`은 참가자가 몇 개든, 각각 몇 멤버든 같다 |
| 한 순간 여러 결합 | 됨 | 충돌 그래프 연결 성분 단위로 한 번에 |
| 한 순간 두 면으로 동시 결합(고리) | 됨 | 같은 두 구조 사이 결합 여러 개도 한 병합 |
| BREAK / SPLIT | **없음** | GEO v2 첫 항목 (G4) |

**D1 — MERGE는 이번에 v5 범위로 새로 승인한다 (2026-09-24).** 사실관계를 정확히: v5의 **구현과 보존식**은 이미 MERGE를 일반적으로
처리할 수 있었다(`_all_contacts`는 같은 구조 안만 빼고 모든 쌍을 보고, `_merge`는 크기와 상관없이 연결된 구조를 한 번에 합치며,
E3 식은 구조+입자와 구조+구조를 구분하지 않는다). 그러나 **승인된 범위는 CREATE/GROW뿐이었다** — 에너지 문서의 범위, 옛 GEO의
보류, `STRUCTURE_STATE_V1` 3.5의 "미정의". 따라서 이것은 "이미 승인돼 있었다"가 아니라 **최신 결정으로 v5 범위를 확장**하는 것이다.
v1~v4는 기존 의미 그대로. 이유: 구조 크기에 따라 같은 면-결합 법칙을 금지할 물리적 근거가 v5에 없다. 검증: 멤버 수와 관계없이
같은 접촉·포트·문턱·보존식이 적용되는가. 실패의 의미: "구조는 결합된 요소들의 집합일 뿐"이라는 v5의 일반화가 틀렸거나,
구조 크기에 따른 추가 물리가 필요하다는 것.

따라서 v1B는 **새 물리를 만드는 단계가 아니라 이미 있는 병합이 올바른지 넓게 검증하는 단계**다. 코드 변경은 5절의 작은 항목뿐이다.

## 1. 검증할 것

### 1.1 성장의 기하 — 모양이 법칙대로 생기는가

| 검사 | 내용 |
|---|---|
| 직선 사슬 | 한 줄 위에서 길이 **4 이상**, 이어서 수십 (지표일 뿐 목적이 아님) |
| 가지 | 동쪽으로 가는 사슬의 북/남 면에 입자가 붙어 T자·빗 모양 |
| 움직이는 구조의 성장 | 등속으로 가는 구조가 가는 길의 입자를 붙임 — v2에서 막혀 있던 것 |
| 고리 | 두 구조가 한 순간 두 면으로 동시에 닿아 닫힌 모양 (강체라 한 구조가 제 몸으로 고리를 닫는 일은 없다 — 이것도 확인). **확인할 것은 "고리라는 특별한 물리"가 아니라, 결합 그래프에 순환이 생겨도 특별 규칙 없이 일반 결합 집합으로 표현되는가**다. 사슬·가지·고리·빗 같은 모양 유형을 엔진에 넣지 않는다 — 엔진에는 멤버와 결합 그래프뿐이고, 모양 이름은 사람이 보고 붙이는 것 |
| 구조 + 구조 (D1) | 양쪽 모두 멤버 여럿, **양쪽 모두 U > 0, 질량 다름, 운동량 0 아님·서로 다름**. 병합 뒤 멤버 = 합집합, 결합 = A의 옛 결합 + B의 옛 결합 + 새 결합, `P' = P_A + P_B`, `U' = U_A + U_B + K_A + K_B − K'`를 직접 검증 + 독립 감사 통과 |
| 자리가 찬 면 | 결합이 이미 있는 면에 닿으면 비결합 접촉 → 중단(P3) |
| 모양 유지 | 긴 실행 뒤에도 모든 결합이 "면끼리 딱 붙은" 상태 — 매 사건 `validate`가 이미 강제, 여기서는 모양을 명시적으로 비교 |

### 1.2 순서·이름·배열 독립 — 성장이 많은 세계에서

A-V4.C와 기준 실행기 테스트의 불변 검사(재명명·입력 순서·관측 간격·갈릴레이·측정기)를 **성장이 풍부한 세계 여러 개**로 넓힌다.
지금 테스트의 세계는 사건이 몇 개뿐이다. 성질 기반 검사: 여러 seed의 세계에서 무작위 이름 치환·배열 섞기를 하고
`relabel(run(spec)) == run(relabel(spec))`.

### 1.3 v2 결함의 v5 대응 — 결함 기록 옮기기

`tests/test_known_defects_causal_kernel.py`에 남은 v2 `_grow_chains` 결함 둘:

| v2 결함 | v5 positive test |
|---|---|
| 구별 불가능한 두 멤버 중 번호가 작은 쪽에 붙는다 | 한 입자가 구조의 두 면에 **동시에** 닿을 수 있는 배치 → 둘 다 결합(양립) 또는 다툼 → 중단. 이름을 바꿔도 결과 불변 |
| 한 tick에 결합 하나 | 한 순간 서로 다른 면에 닿는 여러 입자가 **모두** 결합 |
| (표) 움직이는 사슬은 자랄 수 없다 | 1.1 "움직이는 구조의 성장" |

규칙대로(`LOCAL_INTERACTION_PRINCIPLES_V1` known-defect 취급): v5 positive test가 통과하면 두 결함을
`tests/test_legacy_causal_semantics.py`로 옮긴다. 옮긴 뒤에도 **물리적으로 잘못된 동작이다** — "v2 재현성을 위해 의도적으로
보존되는 legacy defect"로 적는다. 결함이 기능으로 세탁되면 안 된다. legacy 파일 머리말의 "v4에서 고쳐진 동작"도
"뒤 형식(v4 또는 v5)에서 고쳐진 결함"으로 일반화한다.

### 1.4 성장 조사 (관찰, 합격 기준 아님)

평범한 세계에서 구조 크기 분포가 어떻게 되는지 센다. 2D 정수 격자 세계는 모서리 중단이 지배하므로(측정 B: 73%) 두 계열을 따로 본다:

| 계열 | 설명 |
|---|---|
| 한 줄 무작위 | 한 줄 위, 무작위 간격·속도·질량 — 모서리 불가능 |
| 반 칸 어긋난 2D | 시작 위치를 반 칸씩 어긋나게 해 모서리 우연 일치를 줄인 2D (없애지는 못함) |

기록: 중단 이유별 비율, 최대 구조 크기, 크기 분포, 가지 수. **모두 시험 세계(`NON_CANONICAL_TEST_WORLD`)** — 현실 이전 후보 아님.
두 생성기의 파라미터와 seed를 결과 문서에 남기고, **두 계열의 결과를 합쳐 하나의 비율로 만들지 않는다.** 최대 크기 17이 성공이
아니고 2가 실패가 아니다 — 보는 것은 "정의된 v5 물리 안에서 어떤 구조 분포가 나오는가"뿐이다.

## 5. 코드 변경 (작음)

| 변경 | 이유 |
|---|---|
| v5 명세에 `world_class` 필수 필드 (`NON_CANONICAL_TEST_WORLD` / `CANONICAL_A`) — **D2** | 현실 근거 원칙 1.1. **물리가 아닌 메타데이터** — 실행기는 이 값을 절대 읽지 않는다(테스트 12). 지금 모든 fixture·벤치마크·테스트는 `NON_CANONICAL_TEST_WORLD`만 쓴다. `CANONICAL_A`는 값으로 있어도 되지만, 정규 A를 처음 만들 때 출처 관문을 따로 검증하기 전에는 쓰지 않는다. **`world_class` 도입 전 v5는 동결 전 연구 형식이며 digest 안정성 대상이 아니었다** — 이 필드로 이전 v5 digest가 바뀐다 |

| 실행기(`v5_reference`) | **변경 없음** — 동결 후보를 건드리지 않는다. 검증 중 결함이 나오면 멈추고 보고한다 |

## 7. 설계자 판정 (2026-09-24)

| | 판정 |
|---|---|
| D1 | **승인** — MERGE를 v5 범위로 **새로 승인**(기존 승인의 확인이 아님). v1~v4 불변 |
| D2 | **승인** — `world_class` 필수 메타데이터, 비인과(테스트 12), 지금은 `NON_CANONICAL_TEST_WORLD`만 |
| D3 | **조건부 승인** — 옮겨도 여전히 잘못된 물리로 명시, legacy 머리말 일반화 |
| D4 | **승인** — 관찰일 뿐, 계열별로 따로, 파라미터·seed 기록 |

**수정 6개:** (1) D1을 신규 범위 승인으로 기록 (2) 에너지 문서 범위를 CREATE/GROW/MERGE로 갱신 (3) `world_class` 비인과 명시 + 테스트
(4) legacy defect는 여전히 잘못된 물리 + 머리말 일반화 (5) 테스트 7을 양립 / 진짜 다툼으로 분리 (6) MERGE 테스트를 양쪽 U·다른 질량·운동량으로.

**한 줄:** GEO v1B는 구조를 만드는 기능을 새로 구현하는 단계가 아니라, v5의 일반적인 요소-접촉 법칙이 CREATE/GROW/MERGE/가지/순환까지
구조 크기나 이름과 상관없이 일관되게 확장되는지를 증명하는 단계다. 성립하면 "사슬 길이 3 천장"은 길이 4를 찍었다는 수준이 아니라,
**구조 크기를 제한하던 인공적인 구현 천장이 제거됐다**고 말할 수 있다.

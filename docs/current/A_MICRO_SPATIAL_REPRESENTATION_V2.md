# A-MICRO 공간 표현 v2 — 선행 설계 초안 (GEO-micro v1A)

**상태:** 초안 (2026-09-24). **승인 전 — 커널을 고치지 않는다.**
**위치:** `A_V4_GEO_CONTACT_GROWTH_V1.md`의 선행 단계. 설계자 결정(2026-09-24): CREATE/GROW 전에
(1) 접촉 사건 표현 (2) tick 안 꼭짓점·통과 접촉 (3) 격자로 표현 못 하는 접촉 후 위치 (4) 대각 운동에 필요한 것
(5) 재명명 불변성·보존·지역성 유지를 먼저 설계한다.
**방향 (설계자·sol):** 칸은 물리가 아니라 **검색용 구역**으로 강등한다. 실제 위치는 더 정밀한 정수 좌표.

## 0. 먼저 — 이것은 작은 단계가 아니다

측정한 사실: **지금 v4의 "에너지"는 운동 에너지가 아니다.**

```
자유 입자 상태  = 방향(N/E/S/W) + kinetic_energy(정수)
이동           = kinetic_energy가 1이든 5든 매 tick 정확히 한 칸
운동량          = 질량 × kinetic_energy × 방향
```

에너지 5인 입자와 에너지 1인 입자가 **같은 속도로 움직인다.** 에너지는 이동 거리와 무관한 "세기" 값이다.
지금까지는 모든 이동이 한 칸이어서 드러나지 않았다.

정밀 좌표로 가서 "속도만큼 이동"하게 하면 이 정의를 버려야 한다:

```
속도 v (벡터)  → 한 tick에 v만큼 이동
운동량 p = m v
운동 에너지 = ½ m |v|²
```

그러면 운동량 보존, 에너지 보존, 결합에 흡수되는 에너지, 절단 때 방출되는 에너지, 열과의 교환, 독립 감사기의
재계산이 **전부 다시 정의된다.** 따라서 이것은 v4 안의 한 단계가 아니라 **새 형식 causal v5**여야 한다
(거버넌스 9·10번: 기존 의미를 조용히 바꾸지 않는다). v1~v4는 그대로 동결된다. — **결정 S0**

## 1. 표현 (항목 1·2)

### 1.1 위치 — 고정소수점 정수

```
1 칸 = U 내부 단위 (예: U = 1024)
입자 위치 = (X, Y) 내부 단위 정수     칸 = X // U  (검색용)
```

부동소수점은 쓰지 않는다(CPU/GPU 결정론). 칸은 "근처에 누가 있나"를 빨리 찾는 색인일 뿐이다.

### 1.2 몸의 크기

접촉하려면 몸에 크기가 있어야 한다. 재료마다 **반지름 r**(내부 단위)을 선언한다. 입자는 원이다.
회전·모양은 이번 범위 밖. — **결정 S2** (원 대신 정사각형도 가능하지만 대각 접촉에서 방향이 튄다)

### 1.3 접촉 사건 — 결합과 분리

```
ContactEvent
    participants     두 입자 (또는 구조의 멤버)
    time             tick 안의 접촉 시각 — 정확한 유리수  (분자/분모)
    point            접촉 지점
    normal           접촉 방향 (두 중심을 잇는 방향)
    incoming         두 참가자의 접촉 직전 운동량
```

"접촉했다"는 이 사건이고, "결합했다"는 **그 사건에 결합 규칙이 적용된 결과**다. 결합하지 않는 접촉(튕김·통과
없음)도 사건이다.

### 1.4 꼭짓점·통과 접촉 — 홀짝 문제가 사라지는 이유

지금의 "같은 칸이면 만남"을 버리고 **연속 충돌 판정**을 쓴다. 두 원의 중심이 tick 동안 직선으로 움직일 때
거리가 `rA + rB`가 되는 가장 이른 시각 `t ∈ [0, 1)`을 푼다. 정수 계수의 2차방정식이다.

- 정면으로 다가오는 경우: 해가 유리수로 나온다 → 정확히 표현 가능
- 비스듬히 스치는 경우: **해가 무리수**(제곱근)일 수 있다 ← 2절의 핵심 문제

통과(자리 바꿈)는 경로 중간에 거리가 `rA + rB` 아래로 내려가므로 반드시 잡힌다. **거리의 홀짝은 더 이상
결과를 정하지 않는다.**

## 2. 핵심 문제 — 정수로 정확히 표현할 수 없는 순간들 (항목 3)

세 곳에서 정확한 값이 정수가 아니다.

| 어디서 | 값 | 왜 |
|---|---|---|
| 비스듬한 접촉 시각 | 제곱근 | 원과 원의 거리 방정식 |
| 결합 후 속도 | `(p₁ + p₂) / (m₁ + m₂)` | 질량 합으로 나눔 |
| 결합 후 운동 에너지 | `|P|² / 2M` | 2와 M으로 나눔 |

**여기서 반올림 규칙을 몰래 넣으면 그것이 새 물리가 된다.** 지금까지 한 방식("정확히 안 떨어지면 안 일어남")은
설계자가 G2에서 기각한 바로 그 패턴이다. 후보:

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **S3-a 정확한 유리수** | 위치·속도를 분수로 저장 | 반올림 없음, 보존 정확 | 분모가 계속 커질 수 있음. 제곱근은 여전히 못 다룸 |
| **S3-b 운동량이 기본, 위치는 누적기** | 구조는 정수 운동량 P와 질량 M을 갖고, 매 tick `누적 += P`, 실제 이동 = `누적 // M`, **나머지를 상태로 보관**(선 그리기 알고리즘처럼) | 운동량 **정확히** 보존. 반올림이 아니라 "아직 덜 간 거리"를 기억 — 잃어버리는 정보가 없다 | 에너지 `|P|²/2M`은 여전히 분수. 에너지 단위를 `1/(2M)`로 쪼개야 함 |
| **S3-c 선언된 반올림 + 나머지는 열** | 고정소수점으로 반올림, 잃은 에너지는 열로 | 단순 | 운동량 나머지는 열로 보낼 수 없다 → **운동량 보존이 깨짐** |

**권고: S3-b.** 운동량을 기본량으로 삼고 위치를 "운동량의 누적"으로 만들면 대각 이동도, 결합 후 속도도
반올림 없이 정확하다. 에너지는 **2 × 운동 에너지 × 질량의 최소공배수** 단위 같은 공통 분모를 세계가 선언하는
방식을 따로 설계해야 한다 — **결정 S4 (가장 어려운 결정, 선택지를 따로 문서화할 필요)**.

**비스듬한 접촉 시각의 제곱근**은 세 안 모두 정확히 못 다룬다. 선택지:
- 접촉을 "tick 안의 정확한 시각"이 아니라 "tick 끝에 겹쳐 있으면 접촉"(겹침 판정)으로 — 통과 문제는 겹침으로
  잡히지만(경로 중간 겹침 검사), 시각은 tick 단위로만 앎
- 접촉 판정만 정확한 정수 비교로(거리² ≤ (rA+rB)² 는 제곱근 없이 판정 가능), 시각은 몰라도 되게 설계

**권고:** 두 번째. **"언제"는 몰라도 "닿았나"는 정수로 정확히 판정할 수 있다.** 결합 결과가 접촉 시각에
의존하지 않게 규칙을 쓴다(운동량 합·질량 합만 사용). 접촉 후 위치는 3절.

## 3. 접촉 후 위치 (항목 3 계속)

결합한 두 몸은 거리 `rA + rB`로 붙어 있어야 한다. 접촉 순간 위치가 격자 단위로 떨어지지 않으면?

- **정의되지 않은 위치를 고르지 않는다.** 가능한 규칙:
  - 두 몸의 **질량 중심**을 보존하고(운동량 보존과 같은 원리), 접촉 방향을 따라 `rA + rB`만큼 떨어뜨림
  - 질량 중심이 정수로 안 떨어지면 → 위치도 누적기(S3-b)의 나머지로 표현
- 이 규칙은 **번호·배열 순서를 쓰지 않는다**(질량·위치·방향만). 재명명 불변.
- 그래도 표현이 안 되는 경우가 남으면 → **`UnresolvedPlacement`로 기록하고 실행 중단**(아래 5절 정책)

## 4. 대각 운동 (항목 4)

S3-b에서는 운동량이 벡터 정수이고 이동은 `누적 += P`를 x·y에 **동시에** 적용한다. "x 먼저? y 먼저?"라는
질문 자체가 없다 — 그 질문은 네 방향 한 칸 이동이 만든 가짜 질문이었다.

필요한 추가 상태: **구조마다 위치 누적기의 나머지(x, y)** 두 정수. 자유 입자도 질량 1짜리 구조로 보면
같은 규칙이다(자유 입자와 구조의 표현이 하나로 통일 — `STRUCTURE_STATE_V1` Q4 부채 해소).

따라서 `UNRESOLVED_DIAGONAL_MOTION`은 v5에서 **사라진다.** v4에서는 설계자 결정대로 기록 + 중단이다.

## 5. 정의되지 않은 물리의 처리 — 설계자 결정 반영

| 사건 | 처리 |
|---|---|
| 같은 포트·같은 대상을 두 후보가 다툼, 물리가 승자를 못 정함 | `ContestedContact` 기록 + **실행 중단**. 번호도, "둘 다 안 붙음"도 고르지 않는다 |
| 대각 운동량 (v4) | `UNRESOLVED_DIAGONAL_MOTION` 기록 + **실행 중단** |
| 접촉 후 위치 표현 불가 (v5) | `UnresolvedPlacement` 기록 + **실행 중단** |
| 서로 양립하는 결합 여럿 | 한 tick에 **모두 함께** 적용 (원칙 2, 유지) |

"실행 중단"은 오류로 끝나는 게 아니라 **정해진 형태의 결과**로 끝난다: 어느 tick에서 어떤 미정의 사건이
있었는지를 담은 기록. census가 이것을 센다 — 자주 멈추면 부족한 물리 자유도를 찾으라는 신호.

**v4에 미칠 영향:** 지금 v4는 대각 구조를 "움직이지 않고 기록"한다(A-V4.B). 설계자 결정에 맞추려면
"기록 + 중단"으로 바꿔야 한다 — 단, 지금 v4에서 대각 구조는 손으로 만든 상태에만 있으므로 실행 결과는
바뀌지 않는다. `tests/test_diagonal_momentum_is_unreachable.py`의 "영구 불변식" 지위도 내린다.

## 6. 재명명 불변성·보존·지역성 (항목 5)

| 성질 | 어떻게 지키나 | 검사 |
|---|---|---|
| 재명명 불변 | 모든 규칙이 위치·질량·운동량·재료만 읽음. 동시 적용은 집합 연산 | A-V4.C 테스트를 v5로 확장 |
| 운동량 보존 | S3-b에서 운동량이 기본 정수량 — 합이 정확히 보존 | 매 tick 커널 자체 검사 + 독립 감사 |
| 에너지 보존 | **S4가 정해져야 판단 가능** | — |
| 지역성 | 한 tick 이동 거리 < 칸 크기 U, 반지름 < U/2 → 접촉 후보는 **이웃 칸 안에만** 있다. 이 두 조건을 세계 명세 검증에서 강제 | 명세 거부 테스트 |
| 격자 독립 | U를 바꿔도(1024 / 512 / 256) 같은 물리 상태면 같은 결과 — 칸이 법칙에서 빠졌다는 증거 (sol 제안) | 새 테스트 |
| CPU/GPU | 입자 계산은 지금도 CPU(`gpu_environment`가 `step_causal_world` 호출). 정수만 쓰므로 유지 | 기존 동등성 테스트 |

**순서 (승인 뒤):** S4 에너지 표현 설계 → v5 명세 형식 → 위치 누적기와 이동 → 접촉 판정 → 격자 독립·재명명·보존
검사 → 그 다음에야 GEO v1B(CREATE/GROW).

**정직하게:** S4가 풀리지 않으면 v5 전체가 막힌다. 반대로 S4를 억지로 정하면(예: 반올림) 이번에 설계자가
막은 "구현 한계가 법칙이 되는" 문제가 에너지에서 다시 생긴다.

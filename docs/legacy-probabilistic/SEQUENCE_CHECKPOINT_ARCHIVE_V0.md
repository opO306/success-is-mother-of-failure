# 서열 세계 무손실 체크포인트 기록 v0

**상태:** 단계 C 장기 실행 저장 기반  
**목적:** 사건이나 시간을 생략하지 않고 반복되는 전체 상태 복사만 줄임

## 1. 저장 구조

```text
초기 전체 상태(-1)
  + 사건 0..7의 후보 요약·난수·원본 사건
체크포인트(7)
  + 사건 8..15의 후보 요약·난수·원본 사건
체크포인트(15)
  + 나머지 사건
마지막 체크포인트
```

체크포인트 간격은 세계 시간이 아니라 외부 저장 설정이다. 이번 검증에서는 8사건을 사용했다.

## 2. 사건마다 보존하는 정보

- 연속 사건 번호
- 사건 직전 후보 수
- 사건 직전 전체 가중치
- 실제 난수 연산, 인수와 결과
- 세계 시간과 사건 종류
- 사건 payload와 사건 뒤 상태 해시

선택되지 않은 후보 전체는 저장하지 않지만 같은 엔진과 체크포인트에서 다시 계산할 수 있다.

## 3. 임의 시점 복원

관찰자가 프레임 `N`을 요청하면 `N`보다 작거나 같은 가장 가까운 체크포인트를 찾는다. 그 뒤 기록된 난수를
사용해 원래 세계 전환 함수를 순서대로 실행한다.

각 단계에서 다음이 기록과 다르면 복원을 거부한다.

- 후보 수
- 전체 가중치
- 난수 연산과 인수
- 선택된 사건
- 체크포인트 상태

따라서 결과 상태를 직접 끼워 넣지 않는다.

## 4. 무결성

각 실행 기록은 정규 JSON 표현의 SHA-256 digest를 가진다. 전체 검증기는 모든 실행을 초기 상태부터 다시
실행하고, 체크포인트와 최종 관측 해시까지 비교한다.

gzip 파일은 생성 시각을 `0`으로 고정해 같은 내용이면 압축 파일도 동일하게 만들 수 있다.

## 5. 세계와의 분리

기록기는 완료된 `SequenceExperiment`만 입력받는다. 체크포인트 간격, 압축률, digest와 복원 결과는 세계
전환이나 다음 사건 선택에 들어가지 않는다.

## 6. 확장 시 다시 볼 것

- 현재 기록은 같은 코드 버전에서의 완전 복원을 전제로 한다.
- 향후 물리 법칙이 바뀌면 엔진 버전 또는 코드 digest를 기록해야 한다.
- 장기 실행에서는 체크포인트 간격이 짧을수록 저장량이 늘고 임의 접근은 빨라진다.
- 간격이 길수록 저장량은 줄지만 한 프레임 복원에 더 많은 사건 재실행이 필요하다.

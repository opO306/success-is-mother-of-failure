# 단계 B 구상 일치성 검증

**대상:** 관측 격리 기록기와 재생 가능한 확률 사건원  
**날짜:** 2026-09-17  
**판정:** 기반 통과, 실제 세계 전환 연결 전

## 1. 무엇을 만들었는가

세계 밖에서 사건을 순서대로 받아 적는 변경 불가능 기록 사슬과, 같은 seed로 같은 우연을 다시 꺼낼 수 있는
확률 사건원을 만들었다. 기록된 난수 사건만 있으면 원래 난수기 없이도 같은 추출 순서를 재생할 수 있다.

## 2. 세계 안에서 실제로 무슨 일이 일어나는가

확률 사건원은 결과값과 그 결과가 몇 번째 추출인지 보여주는 사건 사본을 함께 내놓는다. 세계는 결과값만
사용할 수 있고, 바깥 실행기가 사건 사본을 기록한다. 기록기는 세계 객체나 확률 사건원에 전달되지 않는다.

## 3. 설계 의도와 일치하는 부분

- 기록 여부에 따라 난수 소비량과 결과가 달라지지 않는다.
- 같은 seed는 같은 표본 역사를 만들며 다른 seed는 다른 역사를 만들 수 있다.
- seed, 난수기 종류, 난수 체크포인트와 개별 추출 결과를 외부 사건으로 보존할 수 있다.
- 사건 기록은 이전 기록의 해시를 포함해 중간 수정과 순서 변경을 탐지한다.
- 기록된 실행과 다른 종류·인수의 난수 호출이 나타나면 재생을 중단한다.

## 4. 근사·미구현·남은 강제

- 현재 확률 사건원은 Python의 재현 가능한 의사난수다. 외부 열잡음·하드웨어·양자 엔트로피는 아직 없다.
- 기록 기반은 독립적으로 검증했으며 실제 새 언어의 세계 전환 함수에는 아직 연결하지 않았다.
- 난수 체크포인트는 사건으로 직렬화할 수 있지만, 직렬화된 체크포인트에서 직접 난수기를 복원하는 공개 API는
  아직 없다. 개별 난수 사건 재생은 가능하다.
- 외부 실행기가 기록 결과를 읽어 다음 세계 입력을 바꾸는 잘못된 코드를 작성할 가능성은 언어 차원에서 완전히
  금지되지 않았다. 단계 C 통합 테스트에서 세계 전환 함수가 기록 객체를 입력으로 받지 못하도록 유지해야 한다.
- 아직 모든 몸·물질 사건이 기록되는 것은 아니다. 전 상태 기록은 새 실행 경로와 연결하면서 완성한다.

## 5. 검증 증거와 다음 결정

- 확률·기록 전용 테스트 9개 통과
- 전체 회귀 테스트 481개 통과
- `engine.living`의 다른 실행 파일은 기록기나 재생기의 클래스를 참조하지 않음

다음 단계에서는 기록 시스템을 확장하기 전에 최소 실행 원자의 의미를 설계한다. 세계 전환은 값과 사건을
반환하되 기록기를 인수로 받지 않는 형태를 유지한다.

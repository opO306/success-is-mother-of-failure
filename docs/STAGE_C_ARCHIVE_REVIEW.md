# 단계 C 무손실 체크포인트 기록 구상 일치성 검증

**대상:** `engine/sequence/archive.py`와 길이 3 탐색의 체크포인트 재기록  
**판정:** 무손실 복원·외부 관찰 분리 통과, 코드 버전 독립 장기 보존은 미구현

## 1. 무엇을 만들었는가

매 사건 뒤 전체 상태를 복사하는 대신 초기 상태, 8사건 간격 체크포인트, 마지막 상태와 모든 중간 사건을
저장하는 기록기를 만들었다. 임의 프레임은 가장 가까운 체크포인트부터 실제 세계 전환을 다시 실행해 복원한다.

압축 JSONL 기록기, 전체 복원 검증기와 기존 기록 비교기도 함께 만들었다.

## 2. 실제로 일어나는 일

- 세계 실행 방식과 난수 소비는 이전과 동일하다.
- 실행이 완료되면 외부 기록기가 체크포인트와 사건 사본을 만든다.
- 복원 시 후보를 다시 계산하고 기록된 난수로 사건을 다시 선택한다.
- 후보 수, 가중치, 사건 또는 체크포인트가 하나라도 다르면 복원을 실패시킨다.
- 검증기는 마지막 상태만 보지 않고 초기 상태부터 모든 구간을 다시 통과한다.

## 3. 설계 의도와 일치하는 부분

- 세계 내부 사건이나 시간 구간을 생략하지 않았다.
- 결과 상태를 근사하거나 예측해서 저장하지 않았다.
- 체크포인트 간격과 압축 정보는 세계로 돌아가지 않는다.
- 자연 정지와 사건 제한을 기존과 동일하게 보존했다.
- 기존 8,332회 실행과 새 8,332회 실행의 모든 관측값이 동일했다.
- 새 기록 8,332개를 전부 재실행해 체크포인트와 최종 상태를 확인했다.
- 사건이나 체크포인트 하나가 변조되면 검증이 실패하는 테스트를 추가했다.

## 4. 근사하거나 강제한 부분

- 체크포인트 간격 `8`은 저장량과 복원 비용을 절충한 외부 설정이다.
- 선택되지 않은 후보 목록 전체는 저장하지 않고 후보 수와 가중치 합만 저장한다. 상세 목록은 동일 엔진으로
  재계산해야 한다.
- 압축은 저장 공간을 줄이는 대신 기록·읽기 CPU 시간을 사용한다.
- 현재 archive format은 `v1`이지만 물리 엔진 코드 digest는 기록하지 않는다. 미래 코드 변경 뒤에도 같은
  기록을 복원하려면 엔진 버전 고정이 필요하다.
- 파일 SHA-256은 파일 전체의 무결성을 보여주지만 장기 보존 서명이나 외부 공증은 아니다.

## 5. 검증 증거

- 체크포인트 기록 포함 집중 테스트 74개 통과
- 전체 프로젝트 회귀 테스트 546개 통과
- 전수 재검증: `8,332/8,332` 실행 통과
- 기존 기록과 비교: `8,332/8,332` 관측값 동일
- 기존 전체 상태 파일: `133,402,373` bytes
- 체크포인트 압축 파일: `9,983,743` bytes
- 저장량 감소: 약 `92.5%`
- 새 파일 SHA-256:
  `AFA542B1118DA312E046B576D89092E9423F489DAC809CF821F7EDF09DED633C`
- 순서가 있는 최종 상태 해시 묶음 digest:
  `5F2010723EECC499B9379CF68D095BCAFAA840B971433127E0071882E9179B84`

## 쉬운 요약

- 노트북(일꾼 6명)에서도 **6명 방식(W6)이 혼자 방식(SERIAL)보다 확실히 빨랐다**: 중앙값 69.37초 → 18.08초, 약 **3.8배**. 5번씩 잰 시간이 서로 전혀 겹치지 않았다(혼자 방식 가장 빠른 값 69.34초 > 6명 방식 가장 느린 값 18.29초).
- 계산 결과 10개가 Vast 서버의 결과와 **비트까지 똑같았다**. 다른 CPU에서 같은 코드가 비트 동일한 답을 낸다는 것은 이미 [XREPRO_RESOURCE_V1](XREPRO_RESOURCE_V1.md)(2026-10-06, Windows 데스크톱 Ryzen 5 5600 ↔ 노트북, Resource Evolution 코드)에서 확인됐다. 이번에 더해진 것은 **다른 계산 경로(A resume V1의 N14/T1000/p163)와 다른 OS(Vast Linux 서버 Ryzen 9 3900X ↔ 노트북 WSL2 Linux)** 조합이다. (처음 작성 때 "첫 확인"이라고 잘못 썼고 2026-10-11에 고침.)
- 경험 탭 v1 공유 힌트의 첫 실제 사용: Vast 기록을 보고 "W6부터 재 봐라"고 제안 → 노트북 측정이 그것을 확인(`HINT_CONFIRMED_SUBMIT_FOR_EXISTING_ADMISSION`). 이것은 **기존 관리자 승인에 제출할 후보**일 뿐이고 승인·장부 등록은 하지 않았다.
- 대가: 6명 방식은 CPU를 더 쓴다(중앙값 75.0초 → 95.6초, 약 27% 증가). 시간 최소(WALL_MIN)에는 유리하지만 CPU 최소(CPU_MIN)에는 불리하다. 기존 규칙대로 CPU_MIN은 SERIAL 유지.

- 비교 항목: 기존 검사기 `checker.FIELDS`(outcome, completed_steps, stop, stop_step, cells, endpoints_key) + endpoints_scaled + effective_p.

## 알아 둘 이상한 점 (원인 미확인)

- 노트북에서 SERIAL의 CPU 시간(약 75초)이 wall(약 69~71초)보다 크다. 실행기 자신의 기록도 주 프로세스 CPU 75.9초 > 반복 구간 70.7초다. 계산은 단일 프로세스라 보통은 CPU ≤ wall이어야 하고 Vast에서는 거의 같았다. 후보: WSL2(가상 머신)의 CPU 시간 회계 방식. **UNCONFIRMED** — 판정은 wall 기준이라 이번 결론에는 영향 없음. CPU_MIN 판단에 노트북 CPU 값을 쓰려면 먼저 확인해야 한다.

## 아직 모르는 것

- 노트북 한 대·이 시간대의 결과다. 다른 CPU 일반화가 아니다(원격 PC의 SMT 있는 Ryzen 5 5600은 범위 밖).
- WSL2 가상 CPU는 Windows가 실제 코어에 배치한다. Linux 안의 CPU 지정이 실제 코어 고정이라는 보장은 없다.
- 정식 장부 등록(검사관 서명·관리자 승인)은 하지 않았다. 판정은 제출 후보다.
- 교육비 절감, 관리자 전체 선택 비용, W3/W4 경로는 이번 범위 밖.
- `RwForce` 공유·OS 격리 부재 등 기존 한계 유지.

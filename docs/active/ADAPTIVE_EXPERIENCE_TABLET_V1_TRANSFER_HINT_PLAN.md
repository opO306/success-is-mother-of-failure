# 경험 탭 V1 — 다른 기계 기록을 "먼저 시도할 후보"로 쓰기 (계획, 2026-10-10)

설계자 아이디어(원문): "장부를 공유해서 다른 곳에서도 써볼수 있게 하는 대신 첫 공장일경우만 이 대안써서 빠르게 이 방식으로 시도해보고 안되면 그때부터 스스로 방식을 찾는 방법". 구현 승인 원문: "그럼 이대로 구현해 잠깼다 ㄱㄱ".
양식: [공통 검토 표준 V1](IMPLEMENTATION_CRITICAL_QUESTIONS_STANDARD_V1.md) A–H.

## A. 왜 하는가?
- 처음 보는 기계에서는 지금 모든 실행 방식(혼자/W3/W4/W6)을 재야 한다. 다른 기계의 서명된 기록이 "W6가 확실히 빨랐다"고 말하면, 이 기계에서는 **기준(혼자) + 그 후보 하나만** 먼저 재고, 확인되면 나머지 측정을 생략할 수 있다.
- 현재 코드 확인: v0에는 이미 `policy.classify(...)=='TRANSFER_HINT_ONLY'`(다른 기계 기록은 힌트일 뿐) 분류가 있으나, 그 힌트를 쓰는 부분이 없다. `catalog.search`는 기계가 아니라 문제(N,T,p,goal,physics,numeric,source)로 찾으므로 다른 기계 기록이 이미 검색된다.
- 가장 단순한 해결: v0을 고치지 않고, 새 `experiments/adaptive_experience_tablet_v1/transfer.py`에 **측정 순서 제안기**와 **확인 판정기**만 추가. 실행 선택·활성화 권한은 주지 않는다.
- 선택하지 않은 대안: (가) v0 `safe_method`가 힌트를 바로 선택 — 확인 없이 다른 기계 결과를 믿게 됨, 기존 규칙(PREPARED.md 31행) 위반. (나) 기계 동일성(CPU 모델·env_id)으로만 허용 — v0 문서가 이미 "모델 동일은 성능 근거 아님"으로 거부.

## B. 무엇을 당연하게 여겼는가?
| 가정 | 근거/상태 |
|---|---|
| 실행 방식이 달라도 물리 결과는 같다 | RULES.md 실행기·세계 분리 규칙의 요구사항. 이 계획은 결과 동일을 **입력으로 받아 확인**만 하며 스스로 증명하지 않음(`results_identical` 거짓이면 즉시 거부) |
| "이 기계에서 W6가 가능한가"는 기존 `routes.candidates`(→ `selector.placements`: 서로 다른 물리 코어 수와 cgroup quota로 가능한 방식만 생성)가 판정 | 코드 확인(`selector.py:81-99`) |
| 기록의 측정값은 서명된 원본에서 재검증된 것 | `catalog.load` → `_derive`가 서명·승인·원본 해시를 재검사(코드 확인) |
| 다른 기계와 이 기계의 일꾼 능률이 비슷하다 | **UNCONFIRMED — 그래서 확인 측정이 필수.** 예: V12.3 Vast 서버는 32코어 표시에 quota 7.68 |

## C. 설계가 틀렸다면?
- 힌트가 틀린 경우: 확인 측정에서 걸러지고 스스로 찾기(전체 측정)로 넘어간다 — 손해는 기준+후보 측정 시간뿐.
- 측정 잡음으로 잘못 확인될 위험: 판정을 "후보의 최악 시간 < 기준의 최선 시간"(5회씩, 겹치지 않을 때만)으로 보수적으로 잡는다. v0 기록 조건(방식마다 5회)과 같은 수.
- 위험한 경로: 이 판정기가 실행 선택으로 오인되는 것 → 결과에 `authority='NONE'`, 확인돼도 `SUBMIT_FOR_EXISTING_ADMISSION`(기존 판정자 서명·관리자 승인 절차를 거쳐야 실제 사용)만 반환. v0 `safe_method`는 그대로 직렬.

## E. 문제가 왜 발생했는가?
새 기능 요청이며 결함 수정이 아님. v0 설계가 "다른 기계 기록 사용"을 의도적으로 보류(TRANSFER_HINT_ONLY만 정의)한 상태.

## F. 무엇으로 입증하는가?
반례 중심 시험: 같은 기계 기록은 힌트 아님 / 과거 기록에서 W6·SERIAL 시간이 겹치면 힌트 없음 / 이 기계에서 W6 불가(코어 부족·quota)면 힌트 없음 / CPU_MIN은 힌트 없음 / 확인 측정에서 겹치면 스스로 찾기 / 결과 불일치 시 거부 / 반복 수 부족·잘못된 값 거부 / 확인돼도 권한 없음·v0 safe_method는 직렬 유지.

## G. 무엇을 아직 모르는가?
- 실제 기계 간 기록 공유 통로(파일 배포·서명 신뢰)와 실제 측정 실행기 연결은 이번 범위 밖.
- 보수적 판정 기준(겹침 없음, 5회)이 적절한지 — 설계자 결정 사항.
- 결과 비트 동일 보장의 실제 검증 방법 — 기존 replay/검증 계층에 의존.

## 설계자 결정 사항 (보수적 기본값으로 구현)
1. 과거 기록 힌트 조건: 후보 최악 < 기준 최선(겹침 없음).
2. 이 기계 확인 조건: 기준·후보 각 5회, 겹침 없음, 매회 결과 동일.
3. 기계 적합 조건: 기존 계산기가 이 기계에서 그 방식을 허용(코어·quota). CPU 모델 동일은 요구하지 않음(기록만).
4. 목표 WALL_MIN에만 적용(CPU_MIN은 v0가 항상 직렬).

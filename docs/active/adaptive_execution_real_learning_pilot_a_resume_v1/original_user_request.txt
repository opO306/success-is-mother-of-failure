# ADAPTIVE_EXECUTION_REAL_LEARNING_PILOT_A_RESUME_V1

**최종 목표:** 실제 경험 수집 → 검증 → 관리자 승인 → 다음 요청의 개선 → 복귀

## 1. 현재 상태부터 확인

기준 브랜치, HEAD, 작업 트리, 원본 보호 해시를 먼저 확인하세요.

이미 완료된 사항:

- 실제 N14 직렬/W6 비교 계산과 CPU 재현
- 증거 해시 불일치 원인 규명
- `INITIAL_STATE_CANON_V2` 도입
- 원본 지문과 내용 지문 분리
- 실제 파일 저장 직후 재판독
- 과거 프랑스 실측 10건의 내용 검증
- 관련 시험 202개 통과
- 경량 검사 추가 비용 1% 이내 확인

기존 실패 `REAL_LEARNING_FAIL`은 변경하지 않습니다.

이번에는 위 기능들을 처음부터 다시 만들지 마세요.

**새 계산기를 만들거나 검사관을 늘리지 않고, 이미 만든 연결 구조가 실제 실행에서도 끝까지 작동하는지 확인하는 것이 목적입니다.**

기존 공식 결과나 과거 봉인 파일은 수정하지 않습니다.

## 4. 첫 번째 실제 계산을 초기 관문으로 사용

이번 실행에서 가장 중요한 변경 사항입니다.

**처음부터 10회 계산을 무조건 진행하지 마세요.**

첫 번째 직렬 계산이 끝나면 즉시 다음을 확인합니다.

- 실제 원본 파일 저장 완료
- 저장된 바이트 지문 일치
- 새 내용 지문 일치
- 기존 시작 상태 지문과 관계 정상
- 저장된 요청 N14/T1000/p163 유지
- 실제 CPU 직렬 배치 확인
- 계산 결과·정지·정밀도 확인
- 별도 CPU 재현 결과와 대조

이 관문에서 문제가 하나라도 발견되면 즉시 STOP합니다.

다음 CPU W6 계산을 시작하지 않습니다.

첫 직렬 계산은 정식 5회 반복의 첫 표본으로 인정하고 중복 실행하지 않습니다.

한 번의 실제 계산으로 저장·재판독과 수치 검증 경로를 확인한 뒤에만 나머지 측정을 이어갑니다.

## 5. 나머지 실제 측정

첫 관문을 통과하면 동일 세션에서 직렬과 W6를 각각 총 5회 측정합니다.

봉인된 교대 순서를 유지합니다.

각 계산 결과는 저장 직후 경량 검사를 거쳐야 하며, 모두 동일한 원래 초기 상태에서 시작합니다.

각 실행의 다음 정보를 보존합니다.

- 전체 실행시간
- 누적 CPU 사용시간
- CPU 배치와 프로세스 정보
- 시작·종료 시 환경 부하
- 사용 정밀도와 모든 재시도
- 실제 결과와 구간 끝점
- 원본 파일 지문
- 표준 내용 지문
- 경량 검사에 추가된 시간과 메모리

반복 간 최대/최소 비용 비율 1.25 기준을 유지합니다.

기존 CPU 재현 결과를 무조건 신뢰하거나, 다른 세션의 replay를 재사용하지 마세요. 새 세션에 묶인 재현 증거를 생성하고 같은 조건에서 불필요하게 중복 생성하지 않습니다.

## 6. 실제 경험을 가르치는 과정

10회 측정이 완료되고 관련 정확성 관문을 통과하면 다음 순서로 진행합니다.

**1단계: 경험 후보**

실제 비용 기록을 CANDIDATE 상태로 보존합니다.

**2단계: 독립 검사관**

기존 검사관이 실제 저장 원본에서 시작해 초기 상태, 결과, 반복, 비용, 배치, 정밀도, 세션을 독립 판독합니다.

검사관은 실행 담당이 만든 요약만 신뢰하지 않습니다.

**3단계: 관리자 승인**

검사관이 `REAL_SESSION_COST_CHECKED` 영수증을 발급하고, 관리자가 기존의 명시적 연구용 승인 절차에 따라 새 프로필을 활성화합니다.

검사관이 스스로 프로필을 활성화하면 안 됩니다.

**4단계: 반장에게 새 경험 전달**

새 요청을 시작할 때만 승인된 지식을 사용합니다.

이미 시작한 요청의 프로필은 변경하지 않습니다.

**5단계: 학습 후 실제 계산**

반장이 새로 선택한 CPU 방법으로 N14 계산을 한 번 더 수행합니다.

결과가 독립 재현 증거와 일치하는지 확인합니다.

새 호스트에서 실제로 W6가 더 빠르다면 W6를 선택했는지 기록합니다.

반대로 직렬이 빠르다면 데이터를 왜곡해서 W6를 고르게 하지 마세요.

**6단계: 복귀**

기존 LEGACY 프로필로 서명된 복귀를 수행합니다.

복귀 후 새 요청이 기존 정책을 읽는지 확인합니다. 복귀 확인을 위해 불필요한 전체 물리 계산을 추가하지 않습니다.

실패 시 다음 요청을 STOP합니다.

## 7. 검사 비용 최소화

이번 연구는 학습뿐 아니라 가벼운 계산기 구조를 유지하는 것도 중요합니다.

다음 원칙을 지킵니다.

- 계산마다 새로운 검사관 프로세스를 만들지 않습니다.
- 파일 저장·재판독은 경량 검사로 수행합니다.
- 전체 CPU 재현은 검증이 필요한 고유 조건에 대해 수행하고, 동일 세션의 유효한 증거를 재사용할 수 있는 경우 중복하지 않습니다.
- 결과 원본을 반복 복제하지 않고 해시·참조를 활용합니다.
- 실행시간뿐 아니라 추가 CPU 시간, 메모리, 증거 크기까지 기록합니다.
- 새 기록의 경량 검사 비용이 실제 실행시간의 1%를 넘는지 확인합니다.

정확성 검사를 생략해서 얻은 속도 향상은 인정하지 않습니다.

## 8. Vast 비용과 종료 안전

실제 유료 계산 전에 다음을 먼저 보고하세요.

- 사용할 정확한 instance ID
- machine ID와 국가
- CPU 모델 및 W6 배치 가능 여부
- 현재 시간당 가격
- 사용 가능한 메모리
- 정확성 관련 환경
- 예상 전체 시간
- 외부 종료 감시기 준비 상태

기본 예산은 기존 실측 A의 상한을 유지합니다.

- 시간당 $0.25 이하
- 총 임대 예산 $0.25 이하
- 전체 할당 최대 60분
- 계산 마감 최대 54분
- 결과 회수 및 인계 시간 확보
- 실제 정지 확인 시간 확보

기존 프랑스 서버 54815136은 정지 상태이며, 이전 승인은 종료됐습니다.

같은 서버를 재시작하더라도 새로운 승인과 세션 식별자가 필요합니다.

다른 machine이나 국가를 선택한다면 기존 A 안전 정책에 고정된 호스트 정보도 확인하고, 필요한 경우 실행 전에 별도의 정정을 봉인하세요.

지난 승인서나 종료 영수증을 새 실행의 승인 근거로 재사용하지 마세요.

**서버 임대·재시작은 정확한 후보와 현재 가격을 보고하고 사용자 승인을 받은 뒤에만 수행합니다.**

서버 사용 중에는 외부 종료 감시기를 먼저 ARMED하고, 결과 회수·해시 확인 후 정상 COMPLETED 종료를 요청합니다.

검사 실패는 FAILED로 기록합니다.

기한 초과 시에는 추가 계산을 멈추고 안전하게 종료합니다.

정지 성공은 실제 `actual=exited/stopped`로 확인합니다.

## 9. 판정 규칙

**REAL_LEARNING_LOOP_VALIDATED**

실제 계산으로 새로운 비용 정보를 수집하고, 독립 검증과 관리자 승인 후 다음 요청의 선택이 개선됐으며, 실제 계산의 결과 일치와 복귀가 모두 확인된 경우.

**REAL_LEARNING_COST_USEFUL**

위 조건을 만족하고, 실제 관측된 재사용 절감이 준비·측정·검증·교육 비용 전체를 초과한 경우.

**REAL_LEARNING_NOT_READY**

정확한 계산은 수행했지만 충분한 학습 증거, 실제 개선 또는 복귀 확인이 부족한 경우.

**REAL_LEARNING_FAIL**

정확성 불일치, 잘못된 승인, 원본 변조, 무단 실행, 필수 증거 실패 등 중대한 위반이 확인된 경우.

학습 성공과 비용 회수 성공은 반드시 별도로 판정합니다.

## 실패 원인과 책임

새 운송기의 직접 SSH 연결 검사는 API의 public_ipaddr와 ports[22/tcp]를 정확히 비교하도록 추가됐다.
정지 상태 API에서는 ports 필드가 생략되므로 첫 show 단계에서 EXACT_INSTANCE_API_BINDING으로 거부됐다(선택 출력에는 null로 나타남).
준비 중 실제 exited 응답 원본을 이미 확보했으므로, 정적 검토에서 예방할 수 있었던 가정 오류다.
컨테이너나 서버 식별을 위조하지 않았고 검사를 우회하지 않았다. 실패 후 운송기 수정·자동 재시도는 0회다.
현재 봉인된 운송기는 다음 실행에 사용하면 안 된다. static_review의 당시 STATIC_READY는 실행 준비 성공을 의미하지 않으며 이 실패 기록이 최신 결과다.

## 실행 및 종료 원본

사용자가 이미 실행한 서버에 처음 읽기 API로 접근한 시각은 08:21:49.882362 UTC다.

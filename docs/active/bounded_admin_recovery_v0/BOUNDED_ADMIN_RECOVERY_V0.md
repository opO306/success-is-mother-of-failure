# BOUNDED_ADMIN_RECOVERY_V0 — 행정 복구 설계와 시험 준비

기준 `394d16c9`. 이번 변경은 별도 정책·정적 관문·결함 주입 시험 소스의 준비다.
유료 실행, 기존 운송기의 자동 재시도 연결, 최초 ZIP의 수정은 승인되지 않았다.
기존 결과 `REMOTE_TEST_GATE_FAILED / UNRESOLVED`와 이전 행정 실패 3회는 그대로 유지한다.

## 오류 분류와 권한

허용 후보는 **실행에 필요한 기존 봉인 파일의 누락** 하나뿐이다. 존재하는 파일의
바이트가 달라지면 누락 복구로 취급하지 않는다. 모든 실패·error의 원문을 판독하여
같은 누락에 귀속시켜야 하며, 다른 오류나 미분류 오류가 하나라도 있으면 중단한다.
81건이 같은 경로에서 실패했다는 사실은 그 뒤 계산이 맞다는 증거가 아니다.

| 상황 | 정책 | 보존·후속 행동 |
|---|---|---|
| 승인된 기존 봉인 파일 누락만 존재 | 사전 승인과 독립 출처 확인 후 최대 1회 복구 후보 | 최초 ZIP·실패 원본 보존, 별도 후보 ZIP 봉인 |
| 계산·수치 불일치 | 자동 복구 금지 | 원본 회수·정지, 별도 진단 보고 |
| 서명·원본 변조 | 자동 복구 금지 | 신뢰 근거 보존·정지 |
| 서버 식별·guardian·supervisor·종료 제어 오류 | 자동 복구 금지 | 추가 계산 중지, 외부 정지 우선 |
| 원본 회수 실패·CPU 사용량 미상·회수/정지 여유 부족 | 재시험 금지 | 확보한 원본 보존·정지 |
| 서버가 이미 정지하거나 시간창이 종료됨 | 같은 승인으로 재시작 금지 | 별도 서버 승인 필요 |

사용자는 최초 시험 **전에** 정책 버전, 허용 누락 경로와 원본 SHA-256, 복구 1회·전체
재시험 1회를 명시적으로 승인해야 한다. 이 정책의 작성 요청, 과거 6항 실행 승인,
패키지 자체의 `approved=true`는 복구 승인이 아니다. 사후 승인으로 과거 창을 되살리지 않는다.

## 패키지 완전성 관문

`package_gate.py`는 프로젝트를 import하지 않고 ZIP과 외부에서 해시로 고정한 inventory·
dependency contract만 읽는다. ZIP 전체 해시, 정확한 멤버 집합, CRC, 경로 탈출·중복·
링크·암호화, 멤버별 raw SHA-256을 먼저 확인한다. 다음으로 명시적으로 검토한 실행
봉인 파일 자체의 존재와 raw hash 및 `files` 참조를 검사한다. 누락은 `INCOMPLETE`,
변조·모호한 경로·자기 선언 inventory는 `INTEGRITY_REFUSED`다.

원래 ZIP에는 813개 멤버가 있다. 누락된 A-resume `code_seal.json`의 683개 참조는
이미 들어 있지만 봉인 파일 자체가 빠져 있다. 새 contract는 그 파일도 실행 의존성으로
명시한다. 과거 A-source `manifest.json` 같은 역사적 운송 목록을 실행 봉인으로
무조건 해석하지 않는다. 대신 검토한 실행 봉인 목록과 호출 지점을 별도 고정한다.

수정 패키지는 최초 멤버를 모두 같은 바이트로 포함하고, **contract에 이미 고정된
누락 경로만** 추가할 수 있다. 기존 파일 교체·삭제·새 계산 코드·검사 기준 변경·
승인 파일 추가는 거부한다. 후보 ZIP과 inventory의 새 해시는 외부 승인 범위에 다시
묶어야 한다. 이번 작업에서는 후보 ZIP을 만들지 않는다.

정적 검사 범위는 선언한 실행 의존성과 봉인 참조다. 임의의 동적 경로·외부 라이브러리·
실제 Linux 환경의 실행 가능성까지 증명하지 않는다. `COMPLETE_DECLARED_ONLY`도
실행 승인이나 320개 시험 통과를 뜻하지 않는다.

## 독립 증거와 검토기 경계

`planning.py`는 실행 권한을 발급하지 않는 계약 검토기다. 출처·원본 보존·오류 분류·
누적 예산·서버 제어·후보 패키지·사전 승인·횟수 원장 8종의 독립 검증 영수증을 요구한다.
영수증 raw hash와 역할을 패키지 밖에서 사전에 공급한 pin에 대조한다. 출처 영수증의
검증자와 패키지 작성자가 다르고 기존 원본 경로/해시와 일치해야 한다.

**그 pin이 진짜 독립 검증자의 것인지는 이 검토기가 만들어내지 않는다.** 외부 승인과
기존 서명 검증 경로가 먼저 검증하여 제공해야 한다. 영수증 JSON의 `VERIFIED` 문자열,
서로 다른 이름, 두 개의 자기 작성 manifest만으로 독립 검증이 성립하지 않는다.
이 어댑터와 실제 제어 연결은 미구현이며, 검토기는 통과해도 `execution_authorized=false`다.

기존 A-resume 성공 승인 원본과 현재 파일의 raw hash 비교는 작성자의 출처 교차 확인이다.
새 복구의 독립 검증 완료로 표시하지 않는다. 이번에는 실제 승인·독립 영수증을 만들지 않는다.

## 시간·비용·자원과 정지

최초 allocation ID/start UTC, instance/machine/country, 상한, 원본 ZIP·실패 evidence ZIP,
승인·원장 참조를 변경하지 않는다. 누적 시험 wall·프로세스 트리 CPU의 최초 사용량을
재시험까지 합산하고 복구 작업의 wall/CPU 예약도 보수적으로 같은 잔여량에서 뺀다.
메모리 512 MiB, CPU affinity 1개는 같은 제한이다.
시간당 $0.25 이하·전체 실행료 $0.05 이하도 같은 최초 원장을 쓴다.

다음 전체 관문+합성 측정의 **최대** wall/CPU 예약량을 사전에 봉인한다. 관측 12.70초를
다음 실행의 보장값으로 쓰지 않는다. 복구 작업 시간, 원본 회수와 해시 확인 시간도
별도 최악 예약량이 있어야 한다. `현재 최초창 나이 + 복구 + 전체관문/측정 + 회수 <= 420`,
그 뒤 정지 확인 180초가 `<=600`이어야 한다. 더 이른 기존 guardian/supervisor 마감도
유지한다. 예산·제어·횟수 원장의 외부 관측은 검토 시각에서 5초 이내여야 하며,
최초 UTC 시작과 관측 나이가 일치해야 한다. 이 신선도 제한도 미래 승인할 정책 범위다.
누적 CPU/wall 잔여가 예약량보다 작거나 알 수 없으면 거부한다.

봉인된 기존 `offline.py`는 매 프로세스 120초 제한이다. 그 자체는 **두 번 합친** 제한을
보장하지 않으므로 미래 외부 제어 어댑터가 잔여 한도를 실제로 집행해야 한다. 이 작업은
그 어댑터를 연결하지 않는다. 120초를 다시 부여하거나 보호 검사를 우회하는 구현은 금지다.
최초 관문 CPU 사용량이 현재 STOP 원본에 없고 기존 실행은 이미 종료됐으므로 현재 기록은
복구 허가 조건을 충족하지 못한다.

복구 횟수는 패키지를 변경하려고 시작하기 **전에**, 재시험 횟수는 실행하기 **전에**
외부 append-only 원장에 예약한다. 실패해도 횟수를 돌려주지 않는다. 실패한 재시험의
부분 결과·skip도 보존하고 즉시 종료한다. 성공 요구는 기존 6개 파일의 전체 320개,
failed/error/skip=0 및 합성 측정 완료이며 부분 239개만 재시험해서는 안 된다.
이 정책을 추가 서버 임대·정지 서버 재시작 권한으로 사용하지 않는다.

## 준비한 결함 주입과 검증 순서

`tests/bounded_admin_recovery_v0/test_bounded_admin_recovery_v0.py`는 별도 synthetic ZIP과 TEST_ONLY 영수증으로
누락·참조 누락·해시 변조·경로 탈출·링크·중복·추가 코드·기존 멤버 삭제/교체·
contract/inventory 변조·자기 선언 출처·혼합 오류·횟수 초과·예산 초기화·미상 CPU·
마감 부족·종료 제어·서버 불일치·승인 부재/사후 승인·부분 시험·skip 등을 주입한다.
테스트 fixture의 독립 증거는 가짜 입력이며 실제 독립 검증으로 보고하지 않는다.

이번 준비 단계에서는 로컬 프로젝트 동적 시험을 실행하지 않는다. Python AST 구문 확인,
원래 ZIP의 읽기 전용 정적 관문, 기존 봉인·원본 raw hash 대조만 수행한다.
다음 동적 검증은 별도 승인된 환경/예산에서 새 행정 시험을 먼저 수행하고 결과 원본을
확인한다. 그 통과만으로 기존 320개를 통과했다고 표시하지 않는다. 이후 실제 복구와
320개 전체 재시험도 각각 사전 승인·잔여 자원·독립 증거 조건을 만족해야 한다.

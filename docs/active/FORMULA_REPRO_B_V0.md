## 무엇을 재현했나

`exact_expression_hybrid_probe.zip`의 `probe.py`·`test_probe.py`·`vendor/`를 **바이트 그대로** 복사했다. 상류 `SHA256SUMS.json`과 해시가 일치한다. 그 코드를 import만 하는 하네스로 다시 측정했다. 비교한 평가기는 셋이다.

| 평가기 | 내용 |
|---|---|
| original | `exact_expression_gate_v0.lang_iv.G_of_R2`(상류 기준선 = 저장소 원식) |
| cache | 같은 lang_iv 코드에서 상수 변환만 정밀도별로 공유(대수 변경 없음) |
| algebra | **정확한 수식 정리**: 같은 e^(−αR)에 붙는 항의 분수 계수를 미리 합치고, R과 1/R의 Laurent 다항식을 Horner로 평가 + 상수 공유 |

정밀도 정책은 상류 기본값을 그대로 쓴다(64, 96, 128, 192, 256, 384, 512 오름차순, 상한 512). 정밀도를 올릴 때마다 정확한 초기조건에서 다시 계산한다. `algebra`의 준비 단계(`exact_program()`)는 상류 startup 비교와 같은 방식으로 계산 시간에 넣었다. original과 cache는 준비 단계를 실행하지 않는다.

## 확인 1 — 수식 변환의 적용 조건 (관측 일치와 별도)

- **기호 항등식:** 상류 시험 27개가 이 PC(Windows, Python 3.12.7, sympy 1.14.0, mpmath 1.3.0)에서 모두 통과했다. 여기에는 sympy로 원식을 직접 미분해 정리된 계수와 같음을 보이는 시험이 포함된다. 단거리·감쇠·지연 항을 손으로 전개한 대조에서도 R > 0이면 원식과 같은 식이다.
- **적용 조건:** 정리된 식은 R과 den(R) = 1 + Σ RET_B·R^(m+1)으로 나눈다. RET_B 계수가 모두 양수이므로 R > 0이면 den ≥ 1이다. 실행 중 도메인 의무(R ≥ r_min > 0, 원래 V1 규칙)가 이를 보장한다.
- **상수 동일성:** vendor의 상수 발췌본은 저장소 `a_reference/ar2_lang2024.py`의 COMPONENTS·RET_A·RET_B·R_MIN_BOHR와 정확히 같다. vendor의 V1 파일 3개도 저장소와 바이트가 같다(줄바꿈 정규화 후).
- **포함 검사(필요조건):** r_min〜30 bohr의 48개 반지름에서 64·96·128·192비트 algebra 구간이 원식 1024비트 구간을 포함했다(192건, 실패 0). 구간 입력 12개 × 4정밀도에서는 algebra 구간이 원식의 끝점·중점 값을 포함했다(48건, 실패 0). 이것은 표본 검사이며 모든 입력에 대한 증명이 아니다.

## 확인 2 — 최종 관측값 일치 (세계 인증 아님)

측정 실행 189회와 고정 정밀도 판독 전부에서, 결정된 관측 칸(위치 FX(96,48), 운동량 FX(96,80))이 **저장소** `exact_expression_gate_v1.stream` 384비트 기준과 같았다(독립 checker가 저장된 정확한 끝점에서 칸을 다시 계산). 누락·무효·불일치는 0이었다.
**이것은 관측 칸의 일치일 뿐이다.** 정확한 상태·궤적·세계 이력의 동일성을 인증하지 않는다. 기준도 같은 mpmath 구간 산술을 공유한다.

## 비용 3 — 최초 준비를 포함한 전체 시간 (부모가 프로세스를 띄운 순간부터 종료까지, 중앙값)

- 준비(`exact_program()`)는 wall 1.3〜1.9 ms이다. Windows의 process_time은 15.6 ms 단위로만 증가해서 준비 CPU는 대부분 0으로 찍힌다. 그래서 짧은 실행(1·10 step)은 CPU가 아니라 wall로 판단해야 한다.
- 1 step에서도 algebra가 느리지 않았다. 다만 시간 대부분은 Python 시작과 import(약 0.3 s)다.
- 여기에는 이미 만들어진 정리법을 실행하는 비용만 들어 있다. 정리법을 개발하고 증명한 비용은 포함하지 않는다.

## 운영 공개

- 첫 두 실행은 **측정 전 검사 단계에서 멈췄다.** 원인은 cp949로 pytest 출력을 해독하다 실패한 것, 그리고 상대 경로가 upstream 폴더 기준으로 해석된 것이다. 두 폴더는 지우지 않았고 결과 묶음의 `aborted_launches`에 보존했다. 측정은 세 번째 실행(`aa38620`) 한 번이다.
- 동시 부하: 측정 중 다른 Python 프로세스는 Windows MCP 서버 2개뿐이었다(32분 동안 각 CPU 약 10 s). 측정 실행 189개의 자식 프로세스 종료를 checker가 모두 확인했다.
- 메모리는 프로세스 피크 RSS만 기록했고 분석하지 않았다.

## 아직 모르는 것

- 기호 항등식은 sympy가 확인했고 수치 포함은 표본이다. 정리된 평가기의 모든 입력 구간에 대한 형식 증명은 없다. mpmath 구간 산술은 기준과 공유하는 TCB다.
- 시나리오 3개, 최대 1000 step, 상한 512비트만 시험했다. 더 긴 시간·더 많은 원자에서 배율이 유지되는지는 모른다.
- 정밀도 정책은 상류 기본 계단만 썼다. 중간 정수 비트나 예측기와의 결합은 다음 단계(정밀도 Pilot A, 결합 비교)의 몫이다.
- 128비트에서 결정된 사례가 최소 정밀도라는 근거는 없다(더 낮은 정수 비트는 시험하지 않음).

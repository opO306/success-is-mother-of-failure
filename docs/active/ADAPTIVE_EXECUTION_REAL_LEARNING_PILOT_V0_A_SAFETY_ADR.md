# ADR-A1: 실측 A의 외부 감시·기한·전체 비용 보강

Status: Accepted for bounded preparation; remote validation pending.
Date: 2026-10-08. Decider: 설계자의 우선 후보 진행 지시와 실측 A 계획.

## Context

기존 11272b13을 보존한다. 선택된 France 상품 53170012/machine56006의 A 준비를 진행한다.
사용자가 서버를 준비하며 자동 임대·시작은 하지 않는다. 기존 프로토콜과 과거 ZIP·증거를 보존한다.
현재 구현은 계산/서버 종료 기한이 결합돼 있고, ARMED 이후 생존 확인과 외부 전체 비용이 빠져 있다.

## Decision

새 보충 정책을 코드보다 먼저 봉인한다. 기존 guard/controller/replay/inspector/manager/book을 재사용한다.
할당 시작(사용자 시작 시각이 제공되면 그 시각, 아니면 첫 running 외부 관측 시각)을 명시한다.
시작 이전의 비용은 미확인으로 남기며, 이를 누락한 경제성은 전체 비용 회수 판정에 쓰지 않는다.
그 시각부터 compute 3240초, 회수 3420초, 정지 확인 3600초를 고정한다. 재시작으로 기한을 연장하지 않는다.
외부 guardian은 대상/가격/제어 상태를 15초 간격으로 다시 확인하고 5초 간격 상태를 기록한다.
신뢰된 별도 관리 relay가 상태를 게스트에 전달한다. 실행 직전과 RSS watcher에서 45초 신선도,
인스턴스·ARMED 해시·순번·제어 상태를 확인한다. 오래됨/잘못됨은 STOP이다.
같은 UID 게스트가 파일을 위조하는 공격을 차단하는 OS 격리가 아니며 숨기지 않는다.
runner job_total은 잠정값으로 남긴다. 외부 전체 할당/가격/회수/정지 확인 기록을 별도로 합쳐
WALL_MIN 교육비·추가 재사용 손익분기를 계산한다. 청구액과 미래 이득은 미확인으로 구분한다.

## Options considered and trade-offs

계산을 51분으로만 줄이는 방법은 현재 예산 내에서 회수 시간을 벌 수 있지만 감시기 중단 탐지와
전체 비용 누락을 해결하지 못한다. 전체 시스템 재구현은 원본 보존과 제한 구현 목적에 맞지 않는다.
기존 부품을 소폭 보강하고 외부 관리 relay를 추가하는 방법을 택한다. 신선도 보장을 위해 관리 통신을
추가하며, 이 통신이 실패하면 계산을 중단하므로 유효 결과 없이 멈출 가능성이 있다.

## Consequences and action items

- 원래 p163/반복/변동비/선택/정확성 기준은 바꾸지 않는다. 실제 결과를 보기 전에 정정 코드를 다시 봉인한다.
- 관련 122개와 신규 결함 20개, 총142개를 승인된 원격에서 CPU1/wall·CPU120초/512MiB/물리·GPU0으로 확인한다.
- 모든 자식 CPU 시간의 실제 계상, W6 물리 배치, 현재 수치 환경은 유료 호스트에서 별도 관문이다.
- 장기 통신 장애와 실제 물리 FAILED 종료는 아직 미확인이다. A 통과 뒤 B 자동 실행은 금지한다.

응. **재개하는 게 맞아.** 이번 실패는 아직 H2SOLV 계산법의 실패가 아니라 **링커 단계에서 프로그램 자체가 만들어지지 않은 실패**야.

그리고 중요한 점 하나. 방금 Git 원격을 다시 확인했는데:

```text
origin/master
0f7b744cf754450424a63c47f305e0327c5b37c1

origin/codex/h2-representation-pilot1
264f5880ee1dedd5a97b008c29dd8d67057664b9
```

이야. 네가 말한 `0b79ee3`은 아직 로컬 전용이라 원격에서는 확인할 수 없다. 또 `master`는 그 사이 앞으로 움직였으니 **이번 Pilot에서 자동 rebase/merge하지 말고 현재 로컬 Pilot 계보를 그대로 유지**하는 게 맞아.

이번 재개는 “실패했으니 옵션 이것저것 바꿔서 될 때까지 두드린다”가 아니야. 딱 하나의 사전 가설을 검사하는 거야.

> **현재 배포 Makefile의 MPFR 링크 순서가 현대 GCC의 `--as-needed`와 충돌했고, README에 공식적으로 설명된 정적 라이브러리 연결 방식이라면 원본 source 변경 없이 빌드되는가?**

이건 충분히 값어치 있는 테스트다.

구현자한테는 아래처럼 넘기면 돼.

# H2SOLV Pilot 1 — Vendor Build Resume V2

이전 단계는 공식 archive provenance를 확인했지만 첫 vendor build가 **링크 단계에서 실패**하여 계약에 따라 STOP했습니다.

현재 알려진 실패:

```text
undefined reference to MPFR symbols
```

관측:

```text
MPFR library 존재
필요 MPFR symbols 존재
배포 Makefile은 -lmpfr 위치가 object보다 앞
현재 GCC/linker 환경은 --as-needed 영향 가능
```

이는 현재 **링크 순서/빌드 환경 가설**이며 아직 해결 확인된 사실이 아닙니다.

이번 작업은 이 가설 하나만 검사합니다.

## 1. 기존 원본은 절대 수정하지 말 것

다음은 byte-for-byte 그대로 유지하십시오.

```text
공식 ZIP
afba_v1_0.tar.gz
h2solv.f
README
Makefile
MPFUN source
공식 input/output
```

원본 tree에서 직접 patch하지 마십시오.

새로운 별도 build directory/copy에서만 실험하십시오.

기존 archive/source hash를 실행 전후 다시 확인하십시오.

## 2. README가 설명하는 정식 build 방법만 먼저 시도

이번 재개에서 임의로 linker flag를 이것저것 추가하지 마십시오.

**README에 명시된 static-library/link 방법을 그대로 별도 build directory에 재현**하십시오.

기록:

```text

실제 link command

README 방식과 배포 Makefile 방식의 차이
```

### 중요한 구분

성공하면:

```text
README_SUPPORTED_BUILD_PATH_WORKS
```

입니다.

다음과 같이 쓰지 마십시오.

```text
원본 Makefile이 올바르다
H2SOLV가 검증됐다
```

반대로 실패해도 과학 방법의 실패가 아닙니다.

## 3. 이번 build 재시도는 1개의 사전 정의된 실험

README 방식으로 한 번 시도합니다.

성공:

```text
VENDOR_BUILD_ENVIRONMENT_COMPATIBILITY_SUPPORTED
```

실패:

```text
VENDOR_BUILD_STILL_UNRESOLVED
STOP
```

실패한 뒤:

```text
-lmpfr 위치 계속 변경
--no-as-needed 추가
소스 patch
함수 제거
컴파일러 여러 개 무작위 교체
```

등으로 자동 확장하지 마십시오.

새 원인이 나오면 증거를 보존하고 STOP합니다.

## 5. “프로그램이 0으로 종료됐다”만으로 PASS 금지

이 확인됐으므로 wrapper가 별도로 실패를 판정해야 합니다.

를 확인하십시오.


입니다.

대신 **과학적으로 의미 있는 필드**를 먼저 정의해서 비교하십시오.

가능한 경우 배포 output의 자릿수/출력 정밀도에 맞춰 exact decimal comparison도 따로 기록하십시오.

# ADAPTIVE_EXECUTION_LEARNING_V1 — 봉인 설계

2026-10-08 / 기준 `0f4450e8` / OFFLINE_TEST_ONLY / NOT_PRODUCTION.

## 먼저 공개하는 한계

이번 단계는 새 세션의 **합성 경험을 입력으로 받는 지속 원장과 학습 순환**이다.
실제 계산기의 종료 훅, 운영 키, OS 계정 격리, 실제 새 세션 비용 측정은 아직 없다.
합성 비용의 VERIFIED는 합성 시험 범위이며 실제 성능이나 정확성 인증이 아니다.
실제 기록의 수집과 후보 보존은 허용하지만 운영 승격은 외부 정확성·세션 증명
어댑터가 없으면 거부한다. 기존 V0의 비용 검증과 공유 RwForce 한계를 보존한다.

## 결정과 흐름

실행 담당은 종료 기록을 append-only 원장에 UNKNOWN으로 남기고, 원본 파일과
해시를 붙인 CANDIDATE를 만든다. 기록에는 요청·초기 상태·환경·세션·선택 이유·
전체 wall·모든 시도 CPU 합계·결과·최종 정밀도·영역·정확성 증거 수준이 들어간다.
요청 전체 CPU에는 실패한 정밀도 시도까지 포함한다. 각 시도는 원래 상태에서 시작한다.
기록기가 계산이나 정밀도 재시도 규칙을 실행하거나 수정하지 않는다.

정보 공백은 정확한 요청/초기 상태/환경/세션에 묶는다. N14 직렬 선택이 유효하면
느리다는 이유로 오류가 되지 않는다. GPU 지원 밖은 UNKNOWN 성능과 별도로
UNSUPPORTED로 남으며 성능 학습으로 자격을 얻지 못한다.

독립 검사관은 원장 요약 대신 원본을 다시 읽고, 과거 봉인 증거와 대조하고,
시간 합계·세션·중복·정밀도·결과·기존 실행기 자격·5회 반복과 1.25 spread를 검사한다.
검사 결과에는 비용 검증 범위와 수식 미해결을 기록하고 Ed25519로 서명한다.
관리자는 수집 **이전**에 준비된 검사관 공개키로 검사하고, VERIFIED 프로필을 보관한다.
검사 영수증의 해시를 만든 사람이 그 해시를 '신뢰 해시'로 넘기는 V0 방식은 사용하지 않는다.

관리자 승인은 다른 키의 서명이다. 프로필·목표·직전 버전·결정 식별자·사유를 묶는다.
승격과 활성화를 분리하고, 활성화된 bytes를 요청 시작 시 고정한다.
이미 시작한 요청의 snapshot은 이후 승인/복귀와 무관하다. 다음 요청만 새 프로필을 읽는다.
복귀도 같은 승인을 요구하며 이전 VERIFIED 또는 LEGACY를 선택한다.
복귀 실패·원장/프로필 변조는 STOP 기록을 남기고 후속 요청을 차단한다.

CPU_MIN과 WALL_MIN 승인은 별개다. CPU_MIN은 GPU까지 포함한 누적 CPU 실측을
비교할 수 있지만 새 세션에는 이전 세션 성능을 재사용하지 않는다.
환경 전체 내용과 session_id가 모두 같아야 한다. 전력·에너지·전기요금은 이 목표에 없다.

## 학습 가치와 자원 봉인

목표별 예상 순이득 = 확인된 반복 수 × 요청당 이득 하한 − 측정 상한 − 검증 상한
− 학습 상한. 알려지지 않은 항목은 DEFER_INFORMATION_NEEDED이다.
이미 정확성 범위 안인 실행기, LOW 위험, 허용 자원 내 비용, 양의 순이득일 때만
PROPOSE_ONLY를 만든다. 제안은 승인/실행을 일으키지 않는다.
실현 이득은 향후 실제 재사용 수와 실제 비용을 모으기 전까지 UNCONFIRMED다.

현재 실행 승인: 0건, $0. 로컬 계산/시험 금지 유지.
승인 대상으로 제안할 작은 원격 CPU 시험: 1 worker, wall/누적 CPU 각각 120초,
RSS 512 MiB, 최대 3시도(각 실패 보존), 실제 궤적/GPU 호출 0.
유료 노드 상한 시간당 $0.25, 총 $0.10, 할당 10분. 자동 시작/예산 확대 없음.
기존 V0 24개와 V1 신규 시험 및 봉인된 과거 자료를 읽는다. 자료 64개/32MiB 이내.

## 권한 분리와 보안 범위

이번 서명은 cryptography의 Ed25519 구현을 사용한다. 자체 암호 알고리즘을 만들지 않는다.
시험 fixture가 ingest 전에 임시 TEST_ONLY 검사관/관리자 키를 준비한다.
실행 담당 API에는 비밀키·서명 생성·승격·활성화 기능이 없다. 임의 서명/영수증/
검사관 키 교체/다른 목표 승인/승인 재사용을 결함 주입으로 거부한다.
이 시험용 발급자는 운영 승인자를 대신하지 않는다. PRODUCTION 활성화는 항상 거부한다.

모듈·파일·서명 분리는 OS 격리와 다르다. 같은 계정의 구현자는 키·공개키 저장소·
코드·원장을 교체할 수 있다. root까지 적대자인 보안을 달성했다고 주장하지 않는다.
운영 전 별도 OS 계정/ACL·읽기 전용 trust root·외부 검사 서명기·사용자 관리자 승인기,
외부 append-only 원장 증인, tail 삭제/분기 감지, 동시 요청 직렬화가 필요하다.
프로토타입은 단일 작성자 오프라인 전용이며 동시 writer가 있으면 거부한다.

## 판정과 중단

UNKNOWN → CANDIDATE → VERIFIED. 거부는 CANDIDATE에 붙이고 원본을 지우지 않는다.
변조/결과 불일치/복귀 실패는 STOP을 고정한다. 악성 승인은 거부 기록으로 보존한다.
검증되지 않은 비용은 공식 선택에 사용하지 않는다. 합성 프로필은 오프라인 선택만 바꾼다.
실제 V1 선택기·GPU/물리·구간/반올림·P2·원래 상태 재시작은 import/수정하지 않는다.

과거 V0 검사와 결과 원본은 preservation_manifest로 raw byte SHA-256을 묶는다.
이 설계와 protocol/preservation manifest를 코드 작성 전 commit하고 seal한다.
신규 시험부터 작성하고 구현한다. 실행 전 코드 seal과 byte 보존 ZIP을 별도로 만든다.
검사기 독립성 시험은 import 경계와 결함 검출을 확인하며 별도 사람 감사가 아니다.

## 후속 관문

실제 종료 훅 연결 → 세션/비용/정확성 증명 어댑터 → 운영 키와 OS 격리 →
새 세션의 별도 승인 소규모 비용 측정 → 실제 재사용과 총 비용 판정 → 서비스 승인.
INDEPENDENT_FORMULA_VERIFICATION_V0는 공유 RwForce를 해결할 별도 후속 과제다.
현재 외부 guardian의 DEADLINE/COMPLETED 실제 exited 증거를 보존한다.
장기 통신 장애와 실제 FAILED 종료는 미검증이다. 다음 유료 실행마다 정확한 인스턴스
전용 승인·현재 가격·guardian seal·ARMED 확인이 필요하다.

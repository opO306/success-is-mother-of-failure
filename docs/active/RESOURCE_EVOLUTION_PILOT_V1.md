## 1. 무엇을 했나 (쉬운 말)

비유: 같은 물건(정확히 같은 결과)을 만드는 공장에서, 일꾼 수(코어), 하루 전기 할당량(CPU 예산), 마감 시간(wall 예산), 창고(RAM)를
바꿔 가며 작업 지시서(계획)를 어떻게 고르면 가장 싸게 끝나는지 본 것이다. "배고픔"은 할당량 축소, "공격형"은 실패·버리는 일을
감수하고 빨리 끝내려는 지시서, "조건학습"은 "이 종이 울리면 곧 전기가 끊긴다"를 배우는 것이다.

실제 의미:
- 계산 1회 = 새 프로세스 1개, 지정 물리 코어에 고정(SMT 형제 2i/2i+1 확인: 같은 코어에 둘 올리면 1.82배 느림).

- 계획: BASE(algebra, 동결 P3 시작 p), CONS(+16비트 더 높게), AGG1(R1+R2, −24비트 낮게), AGG3(R1+R2로 p 3개 동시), SPEC_EVAL 등.
- 예산 단위 u = 학습용 요청(200/2000 step, 평가에 안 씀)으로 잰 "계산 1회 CPU". 단계 H0(풍족)–H4(0.7u, 1코어).

## 4. 꼭 답할 20개 질문

1. **wall 기준 가장 빠른 코어 수**: 9개 묶음은 4코어(8.4 s)≈6코어(8.8 s)≈3코어(9.0 s). 요청 하나는 코어 수와 무관.
2. **CPU 기준 가장 효율적**: 총 CPU는 코어 수와 거의 무관(25–26.5 s). 효율(향상/코어)은 1–3코어가 0.98–1.02로 가장 좋다.
3. **병렬화가 이득인 위치**: 독립 요청 병렬(S1)만 CPU 증가 없이 이득. 나머지는 CPU를 더 쓰고 시간을 조금 줄이거나 못 줄임.
4. **원자쌍 병렬**: 3쌍 문제에서 1000 step 요청의 지연을 2.2배 줄였지만 CPU 1.4배 + 시작 0.5 s. 100 step에서는 시작 비용 때문에 손해.
   원자가 많아지면 달라질 수 있다(미시험).
5. **적당한 압박이 효율을 높였나**: 압박 자체가 아니라, 압박을 본 선택기가 낭비 많은 추측 실행을 버렸기 때문에 효율이 좋아졌다
   (H2: AGG3 46 s → BASE 25 s). 처음부터 BASE를 쓰면 압박 없이도 같은 효율이었다.
6. **거부가 급증한 지점**: 추측 실행(AGG3)은 H2→H3(3u→1.5u)에서 9/9→0/9. 단일 작업자 계획은 H3→H4(1.5u→0.7u)에서 9/9→0/9.
7. **적응형이 고정형을 이겼나**: FIXED_AGG3는 이겼다(H3 0/9 → 9/9). FIXED_BASE는 못 이겼다: 완료는 같고, wall 이득(H0 6%, H1 0.4%)을
   CPU 2.8–2.9배로 샀다. **더 단순한 정책(BASE)이 CPU 기준 승자.**
8. **중립 신호가 정말 중립이었나**: 예(V=0, 계획 변화 0/12). 다만 이 설계에서는 당연한 결과라 약한 대조다.
9. **조건 반응이 실제 부족에서 도움이 됐나**: 예. 압박 시행에서 학습형 15/19 완료(배우는 데 필요한 처음 2회씩 실패), 대조군 0/19.
10. **잘못된 신호 비용**: 무압박 오경보 2회에서 CONS는 CPU 7.6/8.6 s(대조 AGG3 19.8/26.6 s) — CPU는 오히려 절약, wall은 한 번
    +15%, 한 번 −46%(대조 쪽 지연 이상치). 이 문제에서는 오경보 비용이 작거나 음수였다.
11. **소거와 역전**: 둘 다 일어났다(소거: 무강화 2회 만에 임계 아래; 역전: B 2회 만에 학습, A 무반응). 학습률 0.3 때문에 빠르다.
12. **누가 어디서 이겼나**: 풍족(H0–H2): AGG3가 p50 약 7–8% 빠름, CPU 1.8–2.8배. 압박(H3): CONS 15/18 대 AGG3 0/18.
    낮은 p에서 시작하는 AGG1은 어디서도 이기지 못했다(첫 시도 성공 3/27).
13. **공격형 평균 이득 대 꼬리**: AGG3는 H0에서 평균 −7%, p95도 나빠지지 않았다(9.6 대 11.4 s; n=27이라 신뢰 낮음). 그러나 이 이득의
    대부분은 더 빠른 계산식(E2)에서 왔다: 같은 계산식으로 p만 동시 시도(SPEC_P_E1)하면 이득 0–4%. AGG1은 평균·꼬리 모두 나빴다.
14. **빠른 후보 적중률·검증 비용**: float64 0/9. 검증 비용은 실제 구간 계산 전체(0.3–9 s)와 같다.
15. **오수락**: 0(검증된 칸 전부 끝점 재유도 일치, 틀린 후보 주입 9/9 거부). 관측된 0이지 증명은 아니다.
16. **"80% 후보"가 안전한 부품이 될 수 있나**: 검사 없는 후보(Type B)는 불가(0/9이고 틀려도 모름). 검증기 붙은 후보(Type C)는
    안전하지만, 이 문제에서는 검증이 곧 정답 계산이라 이득이 없다. 영역 제한 정확 계산(Type A, E2)은 안전하고 CPU 약 8% 절약.
17. **압박이 클수록 누가 유리**: 보수형. 공격형은 버리는 계산이 예산을 먼저 먹어 H3에서 전멸했다.
18. **R1+R2는 자원 환경에서도 순이득이 있었나**: 예, 작게. 묶음 실행 전 코어 수에서 CPU −8%, wall −8% 안팎(3회 중앙값).
19. **신경망이 필요한 근거**: 없다. 필요한 판단은 "CPU가 빠듯하면 추측 실행 끄기, 신호를 배우면 보수형"이라는 2–3개 변수 규칙이었고,
    표/규칙으로 충분했다.
20. **T11을 시작할 정보 가치**: 낮다. 후보 공간이 작고 결론이 단순하다(BASE_E2 + 요청 병렬 + 압박 시 CONS). T11보다는 요청 하나의
    계산 비용 자체를 줄이거나, 원자 수가 많은 문제에서 S4를 다시 보는 편이 정보 가치가 크다(추론).

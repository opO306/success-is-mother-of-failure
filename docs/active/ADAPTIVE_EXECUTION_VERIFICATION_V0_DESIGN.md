# ADR-AEV0: 경험을 검증한 뒤 실행 담당에게 가르치는 체계

**Status:** 설계·제한 구현의 작업 규격 봉인. production 활성화 없음.
**Date:** 2026-10-08
**Deciders:** 설계자(자원 승인·production 도입), 규칙 관리자(봉인·프로필 적용), 별도 검사기(경험 판정).

## Context

V1과 원본은 보존한다. N14의 직렬 선택은 봉인 규칙을 지켰고 계산 결과도 정확했다.
이는 수치 오류가 아니라 실행 비용의 정보 공백이다. GPU의 CPU 사용시간이 적었다는 기존
자료도 CPU_MIN의 새 지식 후보이지 봉인 규칙을 즉시 바꿀 권한이 아니다.
반장은 세계의 B 연구자와 다르며, 물리·반올림·정밀도·P2에 개입할 수 없다.

로컬 시험·계산 및 미승인 Vast 실행은 금지한다. 이 작업에서는 파일 읽기·작성·Git·봉인 해시만 수행한다.
프로토콜과 예산을 구현 전에 별도 local commit으로 봉인한다. 시험·오프라인 재현은 승인된 원격 자원에서만 실행한다.

## Decision

`UNKNOWN → CANDIDATE → VERIFIED`는 경험의 상태다. correctness, 규칙 준수, 비용 정보,
측정 유효성, 수식 독립성은 별도 축으로 기록한다. 모르는 항목은 null과 이유를 남긴다.
실패·거부는 CANDIDATE에 영수증을 추가하며, 과거 관측·영수증을 삭제하거나 덮어쓰지 않는다.

초기 표본은 R1과 R7 각 5회, 35개 서비스 원본이다. 한 pass 요청만 처리해 서로 다른 p와
재시도 비용을 섞지 않는다. GPU 시작비가 제외된 기존 측정 조건을 보존한다.
새 실험은 0회이며 실제 계산을 다시 하지 않는다. 새 검사기는 원본 결과의 전체 기록을 대조하고
기존 pinned checker verdict를 계승한다. 새 물리 재계산·전 step 독립 인증이라고 주장하지 않는다.

규칙 관리자는 프로토콜·원본 해시·검사 영수증을 고정하고 적용할 프로필을 고른다.
수집기는 후보만 만든다. 별도 검사기는 수집기·선택기를 import하지 않고 원본부터 다시 판독해
영수증을 만든다. 선택기는 활성 프로필을 요청 시작 시 고정해 읽고 실행 방법만 추천한다.
V0는 오프라인 추천이며 V1 서비스에 연결하지 않는다. 다음 요청부터 읽는 snapshot 및
LEGACY_V1_PROFILE 복귀의 append-only 사건 기록을 작은 구현으로 제공한다.

환경 설정이 같아도 다른 장비·다른 세션의 성능이 같다는 보장은 없다. V0의 검증 경험은
원본 Vast 세션의 exact fingerprint/N/T/p에만 유효하다. 다른 세션에서 fallback하고 재교정을 제안한다.
GPU N14는 기존 지원 밖이므로 새 비용 경험이 있어도 후보 실행에 넣지 않는다.

시험할 가치는 보수적인 요청당 이득 하한 × 확인된 재사용 횟수에서 측정·검증 비용 상한을
뺀 값으로 제안한다. 단위는 목표에 맞는 wall/aggregate CPU ns다. 어느 값이 없으면
DEFER_INFORMATION_NEEDED다. 위험·기존 실행기 자격·돈·시간 예산은 별도 관문이다.
기존 관측 차이를 미래 이득 하한으로 자동 치환하지 않는다. 제안은 실행 권한이 아니다.

## Options Considered

| 선택 | 결과·비용 | 판단 |
|---|---|---|
| V1 규칙을 관측 직후 수정 | 간단하지만 평가와 학습이 섞이고 되돌릴 근거가 약함 | 제외 |
| 기존 검사기를 그대로 학습 승인자로 사용 | 싸지만 선택·승격 새 규칙을 독립 확인하지 못함 | 과거 정확성 근거로만 계승 |
| 후보 수집·별도 검증·버전 프로필 분리 | 코드·검사 비용 증가, 재현·복귀·미지식 기록 가능 | V0 채택 |

## Trade-off Analysis

V0의 VERIFIED는 HISTORICAL_SESSION_EXECUTION_COST_ONLY다. 광범위 성능 보장이나 물리 인증이 아니다.
5회 반복과 1.25 spread 제한은 봉인된 운영 관문이며 통계적 신뢰구간을 뜻하지 않는다.
자료가 좋은 구간만 몰래 골라내지 않고 35개 전체를 검사하며 오염·비정상 측정은 거부로 남긴다.

권한은 모듈·파일·검사 영수증의 pinned digest handoff로 구분한다. 같은 OS 사용자가 코드를
호출할 수 있어 실제 공격자에 대한 삼권분립 보안은 아직 없다. 별도 OS 계정/ACL/서명·운영
배포는 후속이다. 자기 이름만 verifier라고 적은 자료를 관리자가 자동 신뢰하지 않는다.

## Consequences

CPU_MIN도 새 GPU aggregate CPU 자료를 배울 수 있다. V1의 always-serial은 불변이고
새 프로필을 명시적으로 켠 경우만 비용 추천이 달라진다. 한 요청 중에는 프로필이 바뀌지 않는다.

RwForce 공유는 **INDEPENDENT_FORMULA_VERIFICATION_V0 / 미착수**로 남긴다. 별도 구현의
힘 식·모델 계수·domain·엄밀 구간 산술·어려운 입력·결함 주입을 검증해야 한다. 이번
모듈 분리가 해당 공유 결함을 해결하지 않는다. `REPLAY_VERIFIED`/`CERTIFIED` 승격 없음.

Vast 종료는 전체 ps 부하 검사를 제거한 새 소유권 기반 제어를 작성한다. 독점 인스턴스의
완료·실패·기한 초과에 정확한 ID만 stop하고 stopped/exited를 확인한다. 호출 성공만으로
종료 성공이라 하지 않는다. 종료 실패·게스트 kill에 대비한 외부 guardian과 실제 제어 시험은
아직 미검증이다. 과거 job.sh를 고치지 않으며 새 유료 계산은 이 관문을 통과해야 한다.

## Action Items

2. 수집·정보 공백·가치 제안·별도 검증·프로필 snapshot/복귀의 제한 구현.
3. 새 오프라인·결함 주입 시험과 종료 mock 시험 작성.
4. 코드 봉인 후 승인된 원격 서버에서만 시험·35개 원본 재판독. 새 물리 실행 없음.
5. 실제 Vast 종료 및 외부 guardian 검증은 별도 승인·증거 필요. 현재 유료 계산 차단.

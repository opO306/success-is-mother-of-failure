# MULTIATOM_PARALLEL_V1 — 원자 수가 늘면 한 궤적 안의 쌍(pair) 병렬이 언제부터 이득인가

상태: **결과 기록 (2026-10-06)**. checker **EVIDENCE OK**(노트북 실행, 데스크톱에서 독립 재검사·재분석 동일).
증거 수준 = 실행 + 독립 checker. 노트북 1대(Ryzen 5 4500U, 15W급)의 측정이다. formal 아님. 성능 승격 아님.
**새 시나리오 계열(FCC_N)이며 기존 2/3원자(A2_bound/A3_low/A3_high) 결과·인증 범위와 합치지 않는다.**
브랜치 `claude/resource-xrepro-multiatom-v1`. protocol `d3ba32a` → 정정1 `7823041`(사전 dry run 공개) → 코드 `8e655b6`
→ 정정2 `505c297`+`49c37c0`(실행 기기 변경) → 정정3 `a88002d`+`9dc9c2d`(CPU 측정 방식) → 노트북 원본 `582b529`.

## 0. 한 줄 결론

물리를 하나도 바꾸지 않고(모든 쌍, 컷오프 없음, 같은 힘·적분·정밀도) 한 궤적의 쌍 힘 계산을 작업자 프로세스에 나눠 봤다.
**원자 3개(쌍 3개)부터 루프 시간이 줄고, 원자 6개부터는 시작 비용·CPU 증가를 감안해도 순이득이며, 원자 수가 커질수록 6개 작업자에서
약 3.9배까지 빨라졌다.** 결과는 직렬 저장소 루프와 **비트 단위로 같았다**(288/288 비교). 대신 같은 일에 CPU를 더 쓴다
(6작업자에서 +28〜32%, 원자 수가 작으면 훨씬 더). CPU만 아끼려면 끝까지 직렬(E2)이 최선이었다.

## 1. 무엇을 했나 (쉬운 말)

비유: 원자 N개는 서로 모두 줄(쌍)로 연결된 공들이다. 한 걸음마다 모든 줄의 당김(힘)을 계산해야 하는데 줄 수는 N(N−1)/2로 빨리 는다.
이번에는 줄 목록을 일꾼(작업자 프로세스) 여럿에게 나눠 주고, 각자 맡은 줄의 힘을 계산해 오면 반장(주 프로세스)이 **정해진 순서대로**
합산했다. 순서를 고정한 이유: 구간 산술의 반올림 때문에 더하는 순서가 바뀌면 끝 비트가 바뀔 수 있기 때문이다.

실제 의미:
- 세계: 2/3원자 실험과 같은 KDK(dt 40), Ar40 질량, Lang 2024 쌍 힘(지연 포함), 정밀도 p=128 구간 산술, 매 쌍 도메인 검사, A1 칸 판독.
- 시나리오 FCC_N(실행 전 봉인): 면심입방 격자 점을 원점에서 가까운 순으로 N개(최근접 7.07 bohr — 고체 아르곤 7.10과 비슷), 운동량은
  정해진 정수 패턴(−2…2)에서 평균을 빼 총운동량 0. 난수 없음. N ∈ {2,3,4,6,8,12,16,24,32,48}(쌍 1…1128).
- 비교 구성: SER_E1(현재 BASE 계산기 경로 그대로의 저장소 직렬 루프), SER_E2(R1+R2), PAR_W(W=1,2,3,4,6 작업자).
  각 실행은 새 프로세스, 코어 고정. 지평 T=100(전체 N)과 T=1000(N≤12). 3회 반복, 중앙값.
- 병렬 방식은 기존 기술의 "힘 분할(force decomposition)"이다(Plimpton 1995, 아래 §7). 새 발명이 아니다.

1.28로 늘었지만 통신 증가로 설명되지 않는 크기(클럭은 측정 안 했으므로 **추론**), ② W=6에서 주 프로세스와 6번째 작업자가 같은 논리 CPU
0번을 공유(노트북은 SMT 없음; 봉인된 배치) — N=48에서 송신 시간이 갑자기 3.7초(N=32 0.04초)로 뛴 것이 이 공유와 맞는 모양(**추론**).
B5의 "IPC/대기 ≥20%" 기준은 봉인 정의상 주 프로세스 직렬 시간·작업 불균형까지 포함하므로 순수 통신 병목이 아니다(정정1에서 공개).
순수 대기는 N=48에서 4%였다. 결론: 이 범위(N≤48)에서 RAM·통신은 병목이 아니었고, 남은 병목은 순서 고정 합산과 코어 공유·전력 한도다.

## 6. 질문별 답

1. **몇 원자부터 이기나**: 루프만 보면 N=3. 시작 비용까지 넣으면 100걸음 궤적은 N=4, 1000걸음은 N=3. CPU 증가를 감안한 순이득(B3)은
   100걸음 N=6, 1000걸음 N=3. 같은 결과가 run 2 S4(3원자, 1000걸음 2.2배·100걸음 손해)와도 맞는다.
2. **최적 작업자 수와 N**: N=2 → 직렬. N=3 → 3(쌍 수가 상한). N=4 → wall 기준 3(6은 루프는 빠르지만 시작 비용 때문에 전체로는 3이 나음).
   N≥6 → 사용 가능한 최대(6), 6에서 아직 포화되지 않았다. 효율(speedup/W)은 W=3 약 0.9, W=6 약 0.65.
3. **wall과 CPU 맞교환**: 병렬은 항상 CPU를 더 쓴다. W=6 CPU비는 N=2 5.9 → N=6 1.95 → N≥24 1.28–1.32. W=3은 N≥16에서 1.06–1.08로
   거의 공짜에 가깝고 2.7배 빠르다 — **CPU 효율 기준 절충점은 W=3–4**(노트북 기준).
4. **E2 약 8% 이득이 남나**: 남았다. 직렬 E2/E1 CPU비 0.916–0.950(5–8% 절감), N≥16에서 0.916–0.922(약 8%). 다만 E2는 직렬로만
   측정했고(병렬+E2 조합은 미측정), 노트북 한 대 값이다.
5. **resource-adaptive plan이 필요해지는 지점**: 생긴다. N≈4부터 목적(wall/CPU/둘의 곱)에 따라 최선 구성이 갈린다:
   CPU 최소는 언제나 직렬 E2, wall 최소는 N≥4에서 병렬, wall×CPU는 100걸음에서 N≤6 직렬 → N 8–16 W=4 → N≥24 W=6.
   지금의 BASE(직렬)는 "CPU 최소" 목적에서는 여전히 맞고, "시간이 중요하고 N≥4"에서는 아니다. 필요한 규칙은 (N, T, 코어 수, 목적)의
   단조로운 표 하나로 충분했다 — 학습기가 필요하다는 증거는 없다.
6. **T11을 시작할 정보 가치**: 현재 증거로는 **낮다**. 이번 결과는 Amdahl + 시작 비용 + 정수 분할 + 전력 한도로 거의 다 설명되고,
   선택 규칙이 단순하다. T11(Joint Genome)이 찾아낼 새 정보가 무엇인지 지금은 말할 수 없다. 정보 가치가 더 큰 다음 후보(추론):
   (a) 순서 고정 합산을 작업자 쪽으로 옮기는 설계(원자 소유 분할 — 쌍 계산 중복 또는 교환 비용과의 맞교환), (b) 깨끗한 데스크톱·
   다른 OS에서 같은 경계 재측정, (c) 병렬 + E2 조합.

## 7. 기존 기술과의 관계

- 이 방식은 분자동역학 병렬화의 표준 세 가지(원자 분할·힘 분할·공간 분할) 중 **힘 분할**이다
  ([Plimpton 1995, J. Comput. Phys.](https://www.scinapse.io/papers/2019465613)). 대규모 단거리 MD에서는 공간 분할이 주로 쓰이지만,
  그것은 컷오프(가까운 원자만 계산)를 전제한다. 이 세계는 모든 쌍을 계산하므로(물리 변경 금지) 공간 분할의 이점이 그대로 오지 않는다.
- 병렬 합산에서 비트 재현성을 지키려면 합산 순서를 고정해야 하고 그 비용이 크다는 것이 알려져 있다
  (예: [GROMACS 개발자 토론](https://mailman-1.sys.kth.se/pipermail/gromacs.org_gmx-developers/2014-November/008116.html),
  [GPU MD 알고리즘·성능](https://arxiv.org/pdf/2003.14061)). 이번 설계에서 그 비용은 주 프로세스의 순서 고정 합산(쌍당 약 23 µs)으로 나타났다.
- 반대 방향 근거: 위 문헌은 수백〜수억 원자 규모 결과이고, 수십 원자에서 Python 프로세스로 한 측정과 직접 비교할 수 없다.
  논문 전문은 읽지 않았고 초록·요약 수준만 확인했다.

## 8. 한계·미확인

- **기기 1대**(노트북, 15W 모바일 칩). 클럭·온도 미측정. 데스크톱은 외부 부하로 시간 측정 무효. 경계 N 값은 이 기기·p=128·이 지평에서의
  관측이며 다른 기기·p·T·시나리오로 일반화하지 않는다.

- CPU는 주기 계수/보정 주기율로 환산한 값이다. 데스크톱에서 두 방식이 일치함을 확인했지만, 노트북에서 두 방식이 다를 때 주기 쪽이
  맞다는 근거는 장난감 probe(바쁜 2.0초 → 주기 2.08초, 틱 0.03–0.09초)다. 주기율 보정은 한 코어에서 3회(2.3686–2.3687 GHz).
- 사전 공개: 봉인 전 비용 probe, N=8 T=20 smoke, N=2/3/8 T=10 dry run을 봤다(정정1). 규칙·N·p·T는 그 전에 정해져 있었다.

# V12.5 — 끊김 시험을 "작업 확인 후 끊기"로 수정 (2026-10-10, Claude 세션)

설계자 결정 원문: "1번으로 고쳐 ㄱㄱ" (1번 = 작업이 켜진 걸 확인한 뒤에 끊기). 원인 기록: [V12_4_PAID_RUN_FAILED_CLOSEOUT.md](V12_4_PAID_RUN_FAILED_CLOSEOUT.md).
상태: **구현·무료 확인 완료. 유료 재실행 미승인·미실행(3회 중단 규칙 상태라 별도 승인 필요).**

## 무엇이 문제였고 어떻게 바꿨나

- 문제: V12 끊김 시험은 "작업 시작 명령 → 고정 2.0초 뒤 SSH 클라이언트 강제 종료"(V12.2 끊김 시험은 8초). V12.4 서버는 SSH 1회에 6–7초가 걸려 명령이 서버에 닿기 전에 끊겼다.
- 수정(`revision_v12_5/disconnect_confirm.py`): 서버 쪽 스크립트가 출력하는 "작업 띄웠음" 보고(이 작업 번호·이 서버 번호·상태가 CLAIMED_UNKNOWN_PID/RUNNING 등)를 **최대 30초** 기다렸다가 **그 순간** 클라이언트를 끊는다. 보고가 없으면 원래와 똑같이 시간 초과 → 상태 조회만 → 재실행 없음. 서버 쪽 스크립트는 보고 후에도 세션을 붙잡고 있으므로(V12 10초, V12.2 40초) "세션이 살아 있는 동안 끊기"라는 시험 의미는 유지된다.
- 적용: V12 원래 끊김 시험(controller `guest_disconnect_launch.py` 호출) + V12.2 끊김 시험(`fresh_owned` Probe) 둘 다.
- 바뀌지 않은 것: 서버 쪽 스크립트, 작업 감시·회수·판정, A320 2판·검색 측정, 예산·승인 규칙, V12–V12.4 원본 파일.

## 갱신: Vast 없이 원격 PC에서 관문과 같은 실행 (설계자 요청)

설계자 원문: "근데 Vast 꼭 쓸거 야? 안써도 되면 로컬에서 최하영바보에서 테스트 ㄱㄱ".
실행기: `v12_4_remote_mock/local_gate_equivalent.py`(SHA `ad9e271a…`). 공식 관문 `offline.py main()`의 승인 이후 본문을
그대로 따름(CPU 1개, RLIMIT_CPU 120초, RLIMIT_AS 512MiB, 120초 제한, 자원 감시, 같은 pytest 명령, 같은 검색 측정, 봉인 재검사,
validate_status). **뺀 것(가짜로 만들지 않음): 유료 서버용 승인 표(ticket/armed)와 바깥 감시 장치 확인.**
환경: 원격 PC(최하영바보) WSL1 Ubuntu 24.04, Python 3.12.3, Vast와 같은 4개 패키지 버전.

| 원본 `be06c9a7…` | **STOP `TEST_GATE_STOP`** (319 통과 + 같은 1개 실패) — Vast V12.3과 같은 결과 |

원본 결과는 원격 PC `D:\v12_4_mock\gate_outputs`(목록 번호 `3b851419…`). 첫 실행에서 원본 쪽 "멈춤 기록 쓰기"가 제 실행기 버그(같은 항목 중복)로

이 결과를 A320 공식 완료로 인정할지는 **설계자 결정 사항**이다.

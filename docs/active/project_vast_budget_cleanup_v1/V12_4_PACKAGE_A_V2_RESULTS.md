## 갱신 (같은 날): 원격 PC Linux(WSL1) 실행

설계자 선택 "1번(원격 PC에 WSL 설치)"과 재부팅·로그인·BIOS 가상화 켜기 뒤 진행.
- 설치: WSL 3.0.1(Microsoft 공식 msi, 서명 유효) + Ubuntu 24.04.5(공식 배포 목록의 번호와 일치) → `D:\wsl\ubuntu2404`, **WSL1**(진짜 Linux 커널이 아니라 번역 방식). Python 3.12.3 + Vast와 같은 4개 고정 버전.
- WSL2용 Windows 기능은 "다음 재부팅 시 켜짐"으로 예약만 함(선택 사항).

## 무엇이 확인되지 않았나

- **2판 320개 전체가 Linux에서 통과하는지: 미확인.** 무료 Linux 환경(원격 PC·노트북 모두 WSL/Docker 없음)이 없다.
  간접 근거: 812개 파일은 V12.3 유료 실행 때와 바이트 동일(그때 Linux에서 319 통과), 고친 시험은 Windows에서 통과·원인은 플랫폼 무관한 순서 실수.
  그래도 "Linux 320/320"은 실제로 돌려 보기 전에는 주장하지 않는다.
- Vast 기계에서 검색 측정이 120초 한도 안에 끝나는지: 미확인(추정: V12.3 시험 75.14초 + 측정 약 9초 내외).
- 감시기 실제 사망·실제 SSH 단절 상황에서 2판 회수: 유료에서만 확인 가능.
- 원격 PC 결과는 Windows·다른 CPU에서의 모의 확인이며 공식 판정이 아니다.

## 별도 검토 기록

- **Codex 검토: 실행 불가.** 이 PC에 Codex CLI가 설치되어 있지 않아 codex-rescue 에이전트가 검토를 시작하지 못했다.
- 대체: 이 대화 맥락이 없는 새 Claude 검토자(읽기 전용, 동적 실행 금지, stdlib 해시 비교만). **같은 회사 모델이라 Codex보다 독립성이 약하다.** 독립 권한 인증이 아니다.
- 결과: 차단급 결함 0건. 확인 내용 — 두 zip의 차이가 정확히 2개 항목·부가정보 차이 0, 판정문 불변, code_seal 1줄 변경, 묶음 안 다른 곳이 두 번호를 고정하지 않음, 장부·고정값 일치, 원본 검사 항목 누락 없음, 원본·변조·임의 묶음이 통과하는 경로 없음, 연결 누락 없음(감시기 포함), 사전 점검이 승인 사용·공급자 호출보다 먼저, 실패 시 서버를 삭제하지 않고 멈추는 쪽(원본 V12와 같음), V12.4 봉인 40/40·V12 봉인 60/60 일치, 원본 변경 0.

# V12.2 서버 상태 조회 및 A320 실행 안정화 수정 지시서

**작성일:** 2026-10-10  
**기준:** V12 실제 실패 보고서 및 V12.1 수정 후보  
**목표:** 서버의 일시적인 응답 지연 때문에 작업이 불필요하게 중단되는 문제를 수정하고, 같은 서버에서 A320과 검색 검증을 안전하게 완료할 수 있도록 한다.

## 1. 현재 실패의 정확한 원인

이번 실패는 계산기나 A320 시험에서 발생하지 않았다.

서버 `55069864 / machine 37055`에서 다음 명령을 실행했으나 8초 안에 응답을 받지 못했다.

```text
vastai show instance 55069864
→ TimeoutExpired (8초)
```

관리 프로그램은 상태 조회 실패를 복구하지 못하고 작업을 중단했다.

실제 확인 결과:

- V11 시험 10개 통과
- 원격 관리 시험 228개 통과
- 관리 시험 원본 2,970개 회수 및 해시 확인
- 실제 접속 단절 시험 미실행
- A320 미실행
- 검색 성능 측정 미실행
- 서버는 실제 정지 상태로 보존

V11 시험 10개와 관리 시험 228개는 일부 중복되므로 238개의 고유 시험으로 합산하지 않는다.

**공급자 조회가 왜 8초를 넘겼는지는 미확정이다.**

그러나 일시적인 읽기 요청 실패에 대한 복구 경로가 부족했던 것은 확인된 구현 문제다.

## 2. 가장 중요한 수정 지시

**V12.1의 상태 조회 재시도 기능을 실제 A320 운송 코드까지 검토·연결하세요.**

현재 V12.1은 바깥쪽 관리 프로그램과 행정 시험의 조회만 보완한다.

원래 A320 운송 코드에 남아 있는 **12초 단일 조회 경로**는 별도로 검토해야 한다.

따라서 준비 단계만 고치고 전체 해결이라고 판단해서는 안 된다.

### 읽기 전용 상태 조회

다음 원칙을 적용한다.

1. 시간 초과나 일시적인 통신 실패는 정해진 시간 안에서 제한적으로 재조회한다.
2. 재조회는 최대 3회를 기본 후보로 하되, 기존 전체 종료 시각과 비용 한도를 절대 넘지 않는다.
3. 재조회마다 정확한 인스턴스 ID와 소유 정보를 대조한다.
4. 신원 불일치나 무결성 오류는 재시도하지 않고 즉시 중단한다.
5. 단순한 시간 초과를 서버 고장이나 시험 실패로 단정하지 않는다.

**관리 단계와 실제 A320 실행 단계에 같은 원칙이 적용되는지 확인한다.**

### 상태를 변경하는 명령

서버 생성, 재시작, 시험 실행, 종료, 삭제 명령은 단순 조회와 다르게 처리한다.

응답이 없다는 이유로 같은 명령을 무조건 다시 실행하지 않는다.

먼저 실제 상태를 확인하고, 중복 실행이나 잘못된 서버 조작이 발생하지 않도록 한다.

---

## 3. SSH 연결 종료에 대한 대응

V10에서 A320 도중 SSH 연결이 끊긴 문제가 있었다.

이 문제와 이번 Vast 상태 조회 시간 초과는 서로 다른 오류다.

두 문제를 하나의 원인으로 단정하지 않는다.

기존 V12 계획에 따라 다음 기능을 확인한다.

- 실제 시험 실행과 SSH 연결을 분리한다.
- 고유 작업 번호와 실제 프로세스 상태를 기록한다.
- SSH가 끊겨도 같은 서버에서 기존 작업이 실행 중인지 확인한다.
- 기존 작업이 살아 있으면 같은 A320을 중복 실행하지 않는다.
- 작업 종료가 확인되면 최종 결과를 회수한다.
- 프로그램 종료를 확인할 수 없다면 중요 원본을 회수 완료로 판단하지 않는다.

이번에 준비됐으나 실행하지 못한 **실제 SSH 접속 단절 시험**을 수행하여 위 동작을 검증한다.

## 4. 원본 회수와 삭제 안전장치 유지

V10에서 발생했던 부분 회수 후 서버 삭제 문제를 반복해서는 안 된다.

V11에 추가한 다음 조건을 유지한다.

**정상 완료 확인**

- 실제 작성 프로그램 종료 확인
- 최종 결과 파일 작성 완료 확인
- 원래 시험 항목과 판정 결과 확인
- 원격·로컬 개별 파일 해시 일치
- 필요한 모든 결과와 증거 확보

**실패 또는 연결 상실**

- 확보한 원본과 누락된 원본을 구분한다.
- 실행 중인 작성자가 있는지 확인한다.
- 작성 중 파일을 최종 원본이라고 기록하지 않는다.
- 중요한 원본이 미확인 상태면 자동 삭제를 차단한다.

단순히 ZIP 파일의 해시가 일치한다는 이유로 전체 원본 회수 완료를 선언하지 않는다.

서버 삭제는 중요한 작성자 종료와 최종 원본 검증이 끝난 후에만 진행한다. 미회수 중요 원본이 있으면 정지 보존하고 비용·손실 범위를 사용자에게 보고한다.

## 5. 현재 V12.1 후보 활용

기존에 준비한 V12.1 코드를 최대한 재사용한다.

이미 작성된 다음 기능을 불필요하게 다시 만들지 않는다.

- 읽기 전용 상태 조회의 제한적 재시도
- 기존 서버 소유 정보 검사
- 정지된 같은 서버의 안전한 재개
- 재개 전 준비 파일 재검증
- 미완성 시험 자료의 존재 확인
- 부모·감시 프로그램의 예산 정산 경로
- 승인된 종료 시각과 감시 기능 유지

수정이 필요한 공통 조회 함수와 실제 A 운송기의 호출 지점을 찾아 최소한으로 연결한다.

V12, V12.1의 원본과 봉인은 덮어쓰지 않는다.

새 변경은 별도 V12.2 후보로 구분한다.

새로운 감시 기관이나 중복 관리 시스템을 만들지 않는다.

## 6. 구현자가 자율적으로 해결할 수 있는 범위

다음 문제는 기존에 허용된 운영 문제 수정 권한에 포함된다.

- 상태 조회 시간 초과
- SSH 연결 준비와 재접속
- 파일 전달 실패
- 설치 환경 문제
- 시험 수집 문제
- 관리용 명령 인자 오류
- 실행 상태 확인
- 관련 관리 코드의 수정과 재검증

**이런 문제 때문에 매번 사용자에게 수정 허락을 새로 요청하지 마세요.**

승인된 서버 사용시간과 예산 안에서는 같은 서버에서 조사·수정·재검증할 수 있다.

다만 다음 경계는 유지한다.

- 계산기의 물리·수치 정확성 변경 금지
- 시험 판정 기준 완화 금지
- 원본 무결성 훼손 금지
- 잘못된 서버 조작 금지
- 중요한 미회수 연구 원본의 무단 삭제 금지
- 예산과 승인 종료 시각 초과 금지

운영상 재검증을 허용한다는 이유로 물리 계산을 자동 재실행해서는 안 된다.

## 7. 시험 순서

### 첫 번째: 수정된 관리 기능 검증

V12.1에 준비한 상태 조회 관련 신규 시험과 영향받는 기존 시험을 실행한다.

확인할 주요 반례:

- 상태 조회 1회 시간 초과 후 정상 응답
- 상태 조회가 반복적으로 시간 초과
- 조회 중 서버가 실제로 종료됨
- 잘못된 서버 신원 반환
- 조회 응답은 실패했지만 기존 작업은 계속 실행 중
- 서버 종료 명령의 응답이 유실됨
- 총 종료 시각이 임박한 상태에서 재조회가 지연됨

시험 수와 통과 수는 실제 실행 결과로 보고한다.

### 두 번째: 실제 접속 단절 검증

기존에 준비한 단절 시험을 수행한다.

SSH 연결을 종료한 후에도 실제 작성 프로그램 상태를 확인하고 결과를 안전하게 회수할 수 있는지 검증한다.

### 세 번째: A320

관리 검증이 통과하면 원래 승인된 A320 시험을 진행한다.

```text
A320: 320개
PASS: 320
FAIL: 0
ERROR: 0
SKIP: 0
```

기존 A320 시험 항목과 판정 기준은 변경하지 않는다.

완료 JUnit이 없으면 통과 수를 확정하지 않는다.

### 네 번째: 원래 검색 측정

A320이 통과하면 기존 봉인된 측정을 수행한다.

- 경험 100개: 31회
- 경험 1,000개: 31회
- 경험 10,000개: 31회

원래 계약대로 중앙값과 최댓값, 완료 증거를 검증한다.

별도의 보충 측정 93회를 추가하지 않는다.

**이미 통과한 B95 95개는 불필요하게 재실행하지 않는다.**

## 8. 같은 서버 재개와 시간·예산

현재 대상은 다음과 같다.

```text
인스턴스 ID: 55069864
machine ID: 37055
현재 상태: 정지 보존
```

기존 V12.1 후보는 최초 임대 시각을 기준으로 60분 연장을 제안했다.

고정 종료 시각은 다음과 같다.

**2026-10-10 04:12:57.932772 KST**

이 시간은 실제 시각이 지나도 자동으로 연장되지 않는다.

**수정과 검토를 마쳤을 때 남은 시간이 충분하지 않다면, 기존 60분 승인 후보를 억지로 사용하지 마세요.**

필요한 실제 실행·회수·종료 시간을 새로 계산해 사용자에게 현실적인 시간 연장을 요청하세요.

기존 30분 한도에서 60분으로 연장하는 조치는 아직 승인되지 않았다.

또한 현재 총예산은 $2이며, V12.1에 제안된 추가 보수 예약 $0.04는 아직 실행·확정되지 않았다.

- 기존 예약 약 $0.052382
- 추가 예약 후보 $0.04
- 제안된 전체 예약 약 $0.092382
- 마지막 장부 기준 총예산 잔여 약 $1.261141

모두 현재 관측과 장부 기준이며 최종 청구액은 아니다.

새 유료 재개 전 실제 서버·예약·공급자 비용을 다시 확인한다.

이번 지시는 **코드 수정과 검증 준비를 허용하는 지시서**다. 승인되지 않은 시간 연장이나 추가 유료 실행을 자동 승인하는 근거로 사용하지 않는다.

사용자가 유료 실행의 시간과 비용을 승인하면 그 범위 안에서 행정 오류 수정·재검증은 자율적으로 수행한다.

## 9. 필수 의문·영향·반례 검토

기존 `IMPLEMENTATION_CRITICAL_QUESTIONS_STANDARD_V1`의 A–H 기준을 적용한다.

| 항목 | 이번 작업에서 확인할 사항 |
|---|---|
| A. 목적 | 8초 조회 지연으로 전체 작업이 종료되는 문제 해결 |
| B. 가정 | 서버가 실행 중이면 공급자 상태 조회가 항상 빠르게 응답하는가? |
| C. 반례 | 조회는 실패했지만 원격 작업은 정상 진행 중인 경우 |
| D. 영향 | 관리 프로그램, A 운송기, 감시기, 회수, 삭제, 비용 정산 |
| E. 원인 | 단일 조회 시간 초과를 복구할 경로가 없었음 |
| F. 증거 | 실제 시간 초과 원본, 수정 전후 반례, 실제 원격 시험 결과 |
| G. 미확인 | 공급자 지연의 정확한 원인, 기존 12초 조회 경로의 실제 안정성 |
| H. 권한 | 기존 총 $2 예산, 로컬 동적 시험 금지, 새 시간 연장 별도 승인 |

중요한 수정은 직접 호출·간접 호출·예외·시작·종료 경로까지 확인한다.

실패 후에는 원인뿐 아니라 왜 기존 시험에서 발견하지 못했는지도 기록한다.

실제 코드와 원본을 읽는 별도 검토를 수행하되, 검토 문서만으로 실제 시험을 대체하지 않는다.

## 10. 완료 판정

이번 수정의 완료 조건은 다음과 같다.

1. 관리 조회의 일시적 시간 초과를 제한적으로 복구한다.
2. 동일한 문제가 실제 A 운송 경로에서 방치되지 않는다.
3. SSH 단절 후 원격 작업 상태를 확인할 수 있다.
4. 원본 작성 완료 전에 서버가 자동 삭제되지 않는다.
5. A320 실제 320개 시험을 검증한다.
6. 원래 검색 성능 측정을 완료한다.
7. 중요한 원본을 회수하고 해시를 확인한다.
8. 실제 서버 종료·삭제와 비용 정산을 확인한다.

### 최종 지시

상태 조회처럼 안전한 읽기 작업과 중복 실행이 위험한 명령을 구분하세요.

기존 V12.1을 최대한 재사용하고, 원래 A320 운송기에 남은 같은 유형의 문제까지 해결하세요.

관리 오류는 사용자가 허용한 시간과 예산 안에서 자율적으로 수정·재검증하세요.

**목표는 서버 관리 규칙을 더 늘리는 것이 아니라, A320과 원래 검색 측정을 안전하게 완료하는 것입니다.**

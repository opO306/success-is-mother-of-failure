# Exact Expression State Gate V0 — 결과

2026-10-05. **ALTERNATIVE NUMERIC WORLD SEMANTICS / SURVEY_ONLY.** C1-B1의 실행 최적화가 아니며 C1-B1을 대체하지 않는다.
봉인 `848ceaf`, 저장 형식 수정 `9dfd3f8`(측정·기준 변경 없음). 실행 1회 실패 후 2회째 완료, 약 42분.

## 판정 (봉인 규칙): **EXPRESSION_WALL**

상호작용이 있는 세 시나리오 모두 `expression_wall`과 `replay_dominates`가 켜졌다.
**두 실패가 3:3 동수였다.** 봉인 규칙은 "가장 많은 실패"를 고르는데, 동수일 때 어느 쪽을 고를지 정하지 않았다. 그래서 판정기의 목록 순서에 따라 EXPRESSION_WALL이 표시됐다. **실질 판정은 "EXPRESSION_WALL + REPLAY_DOMINATES"다.**

## 쉬운 결론

1. **식의 크기는 step에 비례해서 계속 커졌다.** 최적화기는 1.5〜2.2배 줄였을 뿐이다.
   10,000 step에서 3원자 상태 하나가 약 200만 단위(노드 + 연결)였다. 100만 step이면 수십 GB다.
2. **식으로 저장해도, 처음부터 다시 계산(replay)하는 것보다 빠르지 않았다.**
   같은 정밀도에서 식 평가 시간과 replay 시간은 거의 같았다(10,000 step: 266초 대 241초). 식은 메모리만 더 쓴다(약 300 MB).
3. **필요 정밀도는 늘었지만, 이번 범위에서는 봉인 기준(0.05 bit/step)을 넘지 않았다.**
   그런데 그 증가분의 대부분은 **구간 계산 방법 자체가 범위를 넓히는 효과**였다. 계의 실제 민감도 때문이 아니었다.
4. **자유 비행은 최적화기에서 상수 크기로 접혔다.** 닫힌 식이 있는 쉬운 경우만 이득이 확인됐다.

## 수치

| 시나리오 | 크기 증가/step (A → B) | 최적화 배율 | 인증 필요 비트 (10 / 100 / 1,000 / 10,000 step) | 실제 민감도 (log₂ 증폭, 1,000 / 10,000 step) | 10,000 step 조회: B(구축+평가) / replay |
|---|---|---|---|---|---|
| 자유 비행 | 9 → **0** | ∞ (상수 6) | 64 / 64 / 64 / 96 (A 경로) | 0 / – | 6.5 s / 0.3 s |
| Ar 2개 결합 | 113 → 55 | 2.05× | 96 / 128 / 128 / **384** | 1.6 / 2.4 | 112 s / 77 s |
| Ar 3개 저민감 | 294 → 135 | 2.18× | 96 / 96 / 96 / **192** | 0.0003 / 2.1 | 268 s / 202 s |
| Ar 3개 고민감 | 294 → 198 | **1.48×** (기준 2× 미달) | 96 / 128 / 192 / **512** | 1.7 / **21** | 311 s / 241 s |

- 상태 1단위당 메모리는 약 130〜150 byte다. B의 증가량을 100만 step으로 늘리면 8〜26 GB → `expression_wall`.
- 필요 비트 증가율은 0.026 / 0.0097 / 0.039 bit/step으로 모두 봉인 기준 0.05 아래다. 3원자 고민감이 가장 가깝다.
- 3원자 고민감은 실제 민감도가 1,000 step까지 약 2 bit였다가 10,000 step에 **21 bit**로 뛰었다. 혼돈의 시작으로 보인다. 그래도 인증에 필요한 비트(512)의 대부분은 구간 산술의 과대 추정이다.
- A·B·replay는 모든 결정된 checkpoint에서 같은 격자 칸을 냈다. 독립 판정기도 자체 replay로 10 / 100 / 1,000 step 12개를 모두 재확인했다.
- 식을 다 펼친 트리는 1,000 step에서 2⁵⁸⁶⁶ 규모였다. 예상대로 DAG 공유는 필수지만 그것만으로는 의미 있는 비교가 아니다.

## 먼저 공개할 것

- **봉인 규칙의 결함 1 — 자유 비행 판정:** 자유 비행 통과 조건이 "정밀도가 늘지 않음"인데, 정밀도는 경로 A(최적화 없음)로만 재도록 봉인했다.
  A에서는 덧셈 10,000번의 반올림 폭이 쌓여 64 → 96 bit가 됐다. B에서는 상태가 정확한 상수 하나라 증가가 없다.
  이 결함만 아니었다면 판정은 **CONDITIONAL**(쉬운 대조군만 통과)이었을 것이다. 상호작용 시나리오의 결론은 같다.
- **봉인 규칙의 결함 2:** 동수일 때 판정을 고르는 규칙이 없었다(위 판정 항목).
- **첫 실행 실패:** 참고용 트리 크기(4,300자리 이상의 정수)를 JSON으로 저장하지 못해 죽었고, 병렬 실행이 다른 시나리오까지 종료시켰다.
  저장 형식만 고쳐 다시 실행했다. 첫 실행 기록은 `runs/exact_expression_gate_v0_20261005_attempt1_crash`에 보존했다.
- **봉인 전 설계 변경 2건:** 크기를 노드에서 노드 + 연결로 바꿨고, 선형식 평탄화를 제한했다(protocol에 기록).
- **인증 비트는 이번 구간 방법의 비용이다.** 더 좋은 인증 방법(affine 산술, Taylor model 등)이면 줄어들 수 있다. 이번에는 시험하지 않았다.
- 10,000 step = 약 9.7 ps. 장시간 거동은 모른다. O(t²) 비용 가설은 이번 범위에서 확인도 반박도 되지 않았다
  (고정 정밀도에서 비용은 step에 선형, 정밀도 증가는 느림).
- 힘 평가기는 동결 Lang 식을 mpmath 구간 산술로 옮겨 쓴 것이다. 기준 구현과 대조 시험을 거쳤고, 신뢰 기반은 mpmath 구간 산술이다.

## 이 결과가 주는 방향

- "정확한 식을 세계 상태로" 그대로 쓰는 건 **메모리 쪽에서 먼저 막힌다.** replay보다 나은 점도 없었다.
- 이득이 확인된 건 닫힌 식으로 접히는 경우(자유 비행)뿐이다. 설계자가 말한 CONDITIONAL 방향, 즉 "안정적인 영역에서만 정확한 압축 표현"은
  **해석적으로 접히는 영역**(자유 비행, 상호작용이 사실상 없는 구간)에 한정될 가능성이 크다.
- 정밀도 쪽은 "계의 실제 민감도"와 "인증 방법의 과대 추정"이 분리돼 보였다. 앞으로 인증 비용을 줄이는 연구는 계 쪽이 아니라 **방법 쪽**(구간 산술의 개선)을 겨냥해야 한다.

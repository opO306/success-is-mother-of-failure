# C1-B1 실행 기반 정밀도 조사 (runtime stress survey) v1 — survey_only

**상태:** survey_only. 인증·coverage·D_valid·실행기 변경 없음. ④ 미동결·⑤ 미착수·R=20/④-4b NotCertified 유지.
**날짜:** 2026-09-28〜29. **코드:** `a_reference/c1b1_stress_survey.py`(계측), `c1b1_stress_campaign.py`(캠페인), `c1b1_stress_profile.py`(판정별 위치 분석·바깥 비행).
**증거:** `runs/c1b1_stress_remote_20260928/`(원격 결과 59파일, 원격 sha256 대조 59/59 일치), `runs/c1b1_stress_survey_20260928/`(첫 smoke).

## 1. 질문

설계자 질문(유일한 판정 질문): 실제 유효 궤적의 반올림 판정은 거의 전부 128〜256 bit에서 끝나는가?
512 / 1024 / … / 16384 bit가 실제 실행에서 얼마나 자주 필요한가? 답은 분포와, 높은 정밀도가 어디에 몰리는지다.

## 2. 방법

- 실행기(`c1b1_two_atom.py`)는 바꾸지 않는다. `_decide`에 넘기는 `value_at(M)`을 감싸 **요청된 M만 기록**하고 계산은 원래 함수에 그대로 맡긴다. 항상 복원(try/finally).
  입장 검사(`check_integrator_domain`)의 정밀도는 별도 계수기로 센다.
- 계측 on/off 결과 동일성: step별 raw 상태 동일(시험), 계측 부담 재측정 **1.002배**(새 spawn 프로세스·warm-up·교대 3회). 첫 smoke의 0.60은 캐시 warm-up 순서 효과로 **invalid-measurement**.
- 판정별 위치 분석(profile, 읽기 전용): 판정마다 최종 M, 충격량 축, 거리 R(0.5 bohr 구간), 128-bit 구간 폭 w128, 최종 구간 중점과 가장 가까운 반올림 경계의 거리 d를 **출력 ulp 단위의 정확한 log2**로 기록.
  계측을 켠 궤적이 비트 동일하고, 128-bit 판정은 경계가 128-bit 구간 밖·256-bit 판정은 안에 있다는 시험을 둔다.
- 통계 분리: D_valid `numerical_validated` / 그 밖의 계약 안(`unsupported`), 궤적 / hard-case 점, 범주별. 섞어서 평균 내지 않는다.

### 3.2 hard-case 61,936점(shell 15〜18, 단일 충격량)

전부 **256 bit**에서 판정, 512+ 0. 이 점들은 R ≈ 568〜1,388 bohr에 있고 128-bit 구간 폭이 출력 ulp의 2^3〜2^25배라 128 bit로는 원리적으로 판정할 수 없다.
256-bit 구간 폭 2^-134〜2^-132 ulp, 가장 가까운 경계 거리 2^-59 ulp.

| w128 (log2 ulp) | 폭이 예측하는 확률 | 실측 256 비율 |
|---|---|---|
| −7 | 0.78〜1.56% | 0.95% |
| −8 | 0.39〜0.78% | 0.60% |

R 5.5〜20 bohr에서 w128은 거의 일정(약 2^-8〜2^-7 ulp)하고 256 비율도 0.55〜0.68%로 평평하다.
**관측과 맞는 해석(증명 아님):** 정확한 값이 반올림 경계에 대해 특별한 곳에 몰려 있지 않아, 경계가 128-bit 구간에 들어올 확률이 구간 폭과 같다.
정면충돌이 높았던 이유는 축 차이(x 0.70%, y 0.59%)다. 최근접 경계 거리 최소 2^-27 ulp는 균일 분포에서 이 판정 수의 기대(약 2^-26)와 맞다.

### 3.4 바깥 비행 R 20 → R_J = 10,240 bohr (새 상태 공간)

3.1의 주행은 R=20으로 돌아오면 멈춰서 형식 증명이 열려 있는 pre-tail shell 0〜26(R 20〜10,240)에 **들어가지 않았다.** 대표 14개(e 1/2〜9 De, b 0〜3/2 Re, orbiting ±1e-6)를 R_J까지 비행시켰다.

| R (bohr) | 판정 | 256 비율 |
|---|---|---|
| 5〜20 | 182,084 | 0.62% |
| 20〜320 | 1,069,026 | 0.61〜0.76% |
| 320〜640 | 1,132,862 | 51.96% |
| 640〜10,240 | 33,979,770 | **100%** |

- 14개 모두 R_J 도달, 19,027,886 step, 판정 36,363,742, **512+ 0, 판정 불가 0**.
- w128은 R과 함께 2^-28〜2^74 ulp로 커진다. 256-bit 최종 구간 폭은 가장 넓을 때도 **2^-126 ulp**(R_J 근처).
- 가장 가까운 경계 거리 2^-25〜2^-27 ulp. 256-bit 폭 대비 여유 약 2^100 이상.
- 로컬 단일 충격량 지도(3,002점, x축과 기울기 3/7 방향)도 같은 구간 경계(320〜640 전환, 640 이상 항상 256)를 보인다.

## 4. 해석의 한계 (먼저 공개)

- **증명이 아니다.** 관측한 실행에서 512+가 0이었다는 것이다. "값이 경계에 대해 고르게 흩어진다"는 설명은 관측에 맞는 가설이며,
  고른 분포가 깨지는 유리수 구조(정확한 tie·지나친 근접)가 바로 기존 hard-case 탐색·rational tie 배제가 다룬 경우다.
- 바깥 비행은 14개 궤적이다. 방향·에너지 표본이 좁다. 16384-bit completeness의 대체가 아니다.
- R_J 밖(tail)은 w128 추세상 512가 필요해지는 영역이며 기존 tail 인증(최대 512 bit)과 일치한다. 이번 조사는 tail을 달리지 않았다.
- 512+ 확률의 크기 감각(판정당 약 2^-126〜2^-135)은 폭 기반 휴리스틱이다. 공식 보증으로 쓰지 않는다.
- 이번 결과는 인증 region·coverage를 바꾸지 않는다(14/64·gap 81 유지).

## 5. 운영 기록 (실패를 지우지 않음)

- 캠페인 폴더에 분석 파일을 쓰다가 실행 중 캠페인의 합계 함수가 그 파일을 읽어 `KeyError: 'aggregate'`로 종료. 마지막 묶음 파일은 이미 저장된 뒤라 **데이터 손실 0**(40묶음 모두 존재). 합계는 수정 코드로 재계산.
- 원격 bundle 전송 1회가 0바이트로 도착 → 재전송으로 해결(원인 미조사).
- 바깥 비행 완료(2026-09-28 12:23 UTC) 뒤 노드를 끄지 않아 **약 12시간 유휴 과금(약 $4)**. 로컬 감시가 세션과 함께 끊기고 명령 도구가 분류기 오류로 막혔을 때 노드가 켜져 있다는 사실을 보고하지 않은 운영 실패다.
  이후 결과 회수는 "켜기→받기→무조건 끄기(trap, 20분 강제 제한)" 한 스크립트로 수행했다.

# ADAPTIVE_EXECUTION_REAL_LEARNING_PILOT_V0
## 실측 A: 반장의 첫 번째 실제 경험 학습 시험 계획서

**작업 유형:** 기존 구현을 사용한 실제 CPU 계산 및 학습 검증  
**기준 Git 커밋:** `11272b13`  
**기존 검증:** 오프라인 관련 시험 122개 통과  
**실험 단계:** A만 수행, B는 별도 승인 전까지 금지

### 1. 이번 실험의 목적

이번에는 합성 데이터가 아니라 **실제 계산으로 얻은 경험을 반장에게 가르치는 첫 번째 시험**을 진행합니다.

핵심 질문은 다음과 같습니다.

> 반장이 새로운 문제에서 안전한 방법을 선택한 뒤, 실제 경험을 배우고, 검증된 지식을 활용해 다음 계산을 더 효율적으로 수행할 수 있는가?

N=14에서 이전에 직렬을 골랐던 행동은 오류로 취급하지 않습니다.

당시 반장은 봉인된 규칙을 지켰고 계산 결과도 정확했습니다. 이번에는 부족했던 성능 정보를 새롭게 학습하는 과정을 검증합니다.

**반장을 수정하는 것이 아니라, 반장에게 가르치는 시험입니다.**

### 2. 실험 범위

이번에는 아래 하나만 실행합니다.

| 항목 | 조건 |
|---|---|
| 원자 수 N | 14 |
| 계산 걸음 T | 1000 |
| 시작 정밀도 p | 163 |
| 목표 | WALL_MIN, 전체 실행시간 최소 |
| 비교 실행기 | CPU 직렬, CPU W6 |
| 반복 횟수 | 각 5회 |
| 학습 후 실행 | 별도 실제 요청 1회 |
| GPU 호출 | 0회 |
| 사용 환경 | 별도 승인한 단일 Vast 호스트 |

이전 호스트에서 N14의 직렬 실행은 약 106.9초, W6는 약 21.5초였습니다.

이 수치는 실험 설계 참고 자료이지, 새로운 호스트에서도 같은 결과가 나온다는 보장이 아닙니다.

**N14를 GPU에 전달하지 마세요.**

GPU의 해당 N 범위는 기존 검증 대상이 아닙니다. 성능 학습으로 GPU 정확성 승인 범위를 확대해서도 안 됩니다.

### 4. 서버 준비와 승인 절차

현재 확인된 Vast 52763685의 이전 표시 요금은 약 $0.270/h로 실측 상한을 초과합니다. 이전 오프라인 시험에 사용한 가격 예외는 이번 실측에 적용하지 않습니다.

다음 조건을 만족하는 서버 후보를 제시하세요.

- 시간당 요금 $0.25 이하
- 공식 총 예산 상한 $0.25
- 전체 할당 최대 60분
- 실제 계산 마감은 할당 시작으로부터 최대 54분
- 결과 회수·인계 3분과 정지 확인 3분 별도 확보
- 실제 CPU W6 배치가 가능한 물리 코어와 CPU 할당량
- 기존 수치 환경과 CPU 실행기의 정확성 조건 충족
- 외부 감시기 설치 및 독점 종료 권한 확인

서버 번호, machine ID, 국가, CPU 모델, 실제 할당 코어, 메모리, 가격, 실행 예상시간을 보고하세요.

**이 문서는 실측 작업의 추진 지시이지만, 특정 유료 인스턴스의 시작·임대 승인서는 아닙니다.**

정확한 서버와 현재 가격을 설계자에게 보고하고 해당 서버에 대한 명시적 승인을 받은 후 실행하세요.

새 서버 임대, 기존 서버 재시작, 비용 상한 확대를 임의로 진행하지 마세요.

### 5. 실측 전에 확인할 사항

이전 오프라인 시험의 122개 통과 결과와 소스 봉인을 확인합니다.

첫 오프라인 시험에서 누락됐던 과거 replay 파일 두 개를 포함해, 전달 파일이 완전한지 사전에 검사합니다.

특히 다음 사항을 점검합니다.

1. 전달 ZIP과 원본 파일 해시가 일치하는가?
2. 보호된 계산 코드와 물리 수식이 변경되지 않았는가?
3. CPU 직렬과 W6 배치가 실제 호스트에서 가능한가?
4. 기존 환경·수치 라이브러리 조건이 충족되는가?
5. 시작 p163의 정확한 요청 형식이 유지되는가?
6. 독립 재계산 작업을 실행할 수 있는가?
7. 실제 비용 수집에서 모든 자식 프로세스의 CPU 시간이 계상되는가?
8. 외부 종료 감시기가 서버 밖에서 먼저 작동하는가?

새로운 계산을 시작하기 전에 실행 코드 해시를 확정합니다.

### 6. 외부 감시기 및 시간 관리

이전에는 계산 결과를 회수하기 전에 종료 기한이 도래해 서버를 다시 켜야 했습니다.

이번에는 그 문제를 반복하지 마세요.

작업 순서를 다음과 같이 정합니다.

**서버 승인 → 외부 감시기 ARMED → 파일 전달·확인 → 실측 → 독립 검증 → 경험 승인·학습 후 실행 → 결과 회수·해시 확인 → COMPLETED → 실제 정지 확인**

감시기의 DEADLINE은 강제 안전장치로 유지하지만, 정상적인 COMPLETED 종료는 가능한 한 결과 회수 후 수행합니다.

다만 안전 기한을 넘기면서까지 결과 회수를 계속하는 것은 금지합니다.

시간이 부족해지면 즉시 추가 계산을 중단하고 가능한 증거만 회수한 뒤 서버를 정지하세요.

`intended=stopped`만으로 정지 성공이라 하지 않습니다. 실제 `actual=exited` 또는 `actual=stopped`를 확인합니다.

정지 확인이 실패하면 원본을 보존하고 경고·수동 확인 대상으로 기록합니다.

### 7. 실제 계산 순서

**단계 A-1: 학습 전 판단**

새 세션을 생성하고 환경·부팅 식별자·초기 상태·실행 코드·기존 프로필을 기록합니다.

기존 V1의 성능표 없는 판단을 확인합니다.

반장은 현재 지식으로 CPU 직렬을 선택할 것으로 예상되지만, 실제 선택 기록을 기준으로 판단합니다.

과거 세션의 N14 비용표를 새 세션에 미리 주입하지 마세요.

**단계 A-2: 실제 비교 측정**

CPU 직렬 5회, CPU W6 5회를 실행합니다.

실행 순서를 교대로 변경합니다.

- 첫 반복: 직렬 → W6
- 다음 반복: W6 → 직렬
- 이후 같은 방식으로 번갈아 수행

첫 번째 직렬 실행은 학습 전 실제 요청으로 기록하고, 비용 집계에서 이중 계산하지 않습니다.

각 실행은 동일한 초기 상태에서 시작합니다.

모든 실행의 벽시계 시간, 누적 CPU 사용시간, 배치, 정밀도, 결과, 환경 부하를 기록합니다.

반복 간 최대·최소 비용 비율은 기존 봉인 기준 1.25를 유지합니다.

**단계 A-3: 정확성 확인**

새로운 `(N14, T1000, p163)` 조건에 대해 기존 독립 재계산기를 실행합니다.

각 서비스 결과와 다음 항목을 비교합니다.

- 결과 판정
- 완료 걸음 수
- 정지 조건과 정지 시점
- 계산 결과의 구간 끝점
- 요청 정밀도와 실제 실행 정밀도
- 최초 초기 상태 및 재시도 규칙

결과 불일치가 발생하면 즉시 중단합니다.

예상과 달리 p163에서 추가 정밀도 재시도가 발생하면 기존 P2는 그대로 따르되, 이번 **p163 단일 정밀도 비용 프로필 승격은 보류**합니다.

기존 `RwForce` 함수 공유는 여전히 미해결임을 기록합니다.

**단계 A-4: 실제 경험 수집과 검증**

측정 결과를 `UNKNOWN → CANDIDATE`로 수집합니다.

실행 담당은 자기 경험을 스스로 VERIFIED로 승격할 수 없습니다.

별도 검사관이 원본 서비스 파일부터 재확인하고 실제 세션 비용 영수증 `REAL_SESSION_COST_CHECKED`를 생성하도록 합니다.

합성 시험 영수증의 상태만 변경해서 사용하지 마세요.

관리자는 검사관 서명, 원본 해시, 정확한 세션, 승인 목표 WALL_MIN을 검증합니다.

통과한 경험만 해당 세션에 한정된 `RESEARCH_ONLY` 프로필로 등록합니다.

**단계 A-5: 반장의 실제 학습 확인**

관리자 승인 후 새로운 요청을 시작합니다.

이번에는 반장이 검증된 성능 자료를 보고 CPU 직렬과 W6 중 하나를 선택해야 합니다.

선택 이유와 프로필 버전을 기록합니다.

새로 선택한 방법으로 실제 N14 계산을 한 번 더 수행하고, 학습 전 직렬 결과와 정확성을 대조합니다.

중요한 판정 기준은 다음과 같습니다.

- 검증 전에는 기존 지식으로 판단했는가?
- 검증되지 않은 경험은 사용하지 않았는가?
- 승인 후 다음 요청에서 선택이 바뀌었는가?
- 선택한 계산이 실제로 완료됐는가?
- 계산 결과가 동일한가?
- 실제 실행시간은 개선됐는가?

만약 이 호스트에서 W6가 더 빠르지 않다면 억지로 W6를 선택하게 만들지 않습니다.

**실제 증거가 알려 주는 방향으로 학습해야 합니다.**

**단계 A-6: 복귀**

시험이 끝나면 서명된 관리자 승인으로 LEGACY 프로필에 복귀합니다.

새 요청이 기존 프로필을 사용하고, 앞서 시작된 요청의 프로필은 변경되지 않는지 확인합니다.

복귀가 실패하면 새로운 실행을 중단합니다.

### 8. 실제 학습의 경제성 분석

이번 시험에서는 계산 속도 향상과 학습 비용 회수를 분리합니다.

다음을 각각 기록합니다.

- 서버 준비·대기 시간
- 직렬 기준 계산 비용
- W6 비교 측정 비용
- 독립 재계산 비용
- 검사관·관리자·서명 비용
- 학습 후 실제 요청 비용
- 복귀 비용
- 전체 할당 시간과 서버 가격
- 청구액 확인 여부

**한 번 학습한 뒤 다음 계산이 빨라졌더라도, 그 한 번으로 교육비를 전부 회수했다고 해석하지 마세요.**

실제 측정값으로 요청당 절약시간을 구하고, 전체 학습 비용을 회수하려면 같은 조건의 계산이 몇 번 더 필요한지 계산합니다.

예상 재사용 횟수를 사실처럼 가정하지 않습니다.

실제 회수하지 못한 경우 `COST_NOT_YET_RECOVERED`로 기록합니다.

향후 재사용에 따른 이득은 `UNCONFIRMED`로 구분합니다.

### 9. 실행 중 즉시 중단 조건

다음 중 하나가 발생하면 실측을 중단합니다.

- 수치 결과 불일치
- 원본 파일·코드 해시 불일치
- 잘못된 초기 상태 또는 정밀도
- GPU 실행 시도
- 잘못된 CPU 배치
- 실패한 계산 비용의 누락
- 검사관 서명 또는 관리자 승인 불일치
- 다른 세션의 성능 정보 혼입
- 원장 무결성 실패
- 복귀 실패
- 시간·메모리·비용 초과 위험
- 외부 감시기 중단 또는 종료 제어 권한 상실

실패한 결과는 삭제하지 않습니다.

실측 도중 자동으로 재시도하거나 다른 방법으로 실험을 확대하지 마세요.

### 10. 실험 B로 자동 진행 금지

이번 승인은 실험 A만을 대상으로 준비합니다.

실험 A가 완료됐더라도 다음 단계 B인 N12 CPU_MIN/GPU 실측은 자동 실행하지 않습니다.

A의 원본 결과, 학습 효과, 비용, 정확성 검증 결과를 먼저 보고하세요.

실험 B는 별도의 호스트·GPU 환경 확인과 비용 승인 후 진행합니다.

### 11. 최종 판정

결과를 다음과 같이 구분합니다.

**REAL_LEARNING_LOOP_VALIDATED**

실제 계산에서 경험 수집, 독립 검증, 새 프로필 승인, 다음 요청의 선택 개선, 계산 결과 일치, 복귀가 모두 확인된 경우.

**REAL_LEARNING_COST_USEFUL**

위 조건을 충족하고, 실제 관측된 재사용 이득이 학습에 사용된 전체 비용까지 초과한 경우.

**REAL_LEARNING_NOT_READY**

계산 정확성을 유지했지만 실제 선택 개선, 충분한 증거 또는 비용 조건 등을 확인하지 못한 경우.

**REAL_LEARNING_FAIL**

수치 불일치, 무단 실행, 잘못된 승인, 증거 손상 같은 중대한 위반이 확인된 경우.

실험이 성공해도 운영 배포 승인이나 완전 독립 수식 검증을 의미하지 않습니다.

### 12. 최종 보고서

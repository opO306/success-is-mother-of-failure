# A 일반 핵·전자 세계 최소 계약 V0 — 원문 보존

**이 파일은 설계자가 대화에 붙여 준 V0 원문을 그대로 보존한 것이다(2026-10-04).** 내용을 고치지 않는다.
현재 판은 [GENERAL_ATOMIC_ELECTRONIC_WORLD_CONTRACT_V0_1.md](../GENERAL_ATOMIC_ELECTRONIC_WORLD_CONTRACT_V0_1.md)를 본다.
원문의 코드 블록 안 목록은 줄바꿈만 정리했다.

---

General Atomic / Electronic World Minimum Contract V0
상태: DESIGN / CONTRACT DRAFT
목적: H₂ 같은 특정 분자를 만드는 계산기가 아니라, 분자 이름을 전혀 모르는 일반 핵·전자 세계 계산기의 최소 규칙을 고정한다.
현재 H₂는 앞으로 benchmark / 회귀 시험으로만 사용한다.
H₂가 실제 세계에서 생겨야 한다는 목표를 두지 않는다.

## 0. 가장 쉬운 한 줄
A가 해야 하는 일은: 핵과 전자와 필요한 물리 법칙을 계산하고, 무엇이 생기는지는 세계가 결정하게 하는 것이다.
A가 하면 안 되는 일은: H₂, 물, 결합, 반응, 막, 생명 같은 결과를 미리 세계에 넣는 것이다.

## 1. 최상위 원칙 — 현상을 코딩하지 않는다
세계 법칙에는 다음과 같은 이름표를 넣지 않는다.
```
H2 / water / molecule / bond / reaction / membrane / protein / neuron / life
```
이런 이름은 계산이 끝난 뒤 Observer가 붙이는 이름이다. 세계 계산기가 알아야 하는 것은 더 아래의 물리적 정보다.
```
어떤 핵이 있는가 / 핵은 어디 있는가 / 핵은 어떻게 움직이고 있는가
전자가 몇 개인가 / 전자는 현재 어떤 물리 상태인가 / 어떤 기본 법칙으로 서로 영향을 주는가
```

## 2. 세계 / 계산기 / 기록기 / 관측자를 분리한다
A를 최소 네 층으로 구분한다.

### 2.1 WORLD — 실제 세계 상태
다음 순간을 결정하는 실제 물리 상태다. 현재 후보:
```
핵의 종류 / 핵의 현재 상태 / 전자 수 / 실제 전자 상태 / 필요한 장 또는 다른 물리 상태
```
아직 확정되지 않은 항목은 뒤에서 따로 표시한다.

### 2.2 COMPUTATION — 계산 방법
WORLD를 컴퓨터가 계산하기 위한 내부 표현이다.
```
dense array / block representation / Tensor representation / interval / integer/rational representation
```
이 표현은 바뀔 수 있다. 계산 표현이 바뀐다고 세계의 물리가 바뀌면 안 된다.

### 2.3 EVIDENCE / HISTORY — 증거와 과거 기록
```
과거 trajectory / checkpoint / 오차 상한 / 계산 로그 / source hash / 법칙 fingerprint / 검증 결과 / 실패 기록
```
그러나 이것이 자동으로 현재 물리 상태의 일부가 되는 것은 아니다. 특히: 계산기의 오차는 세계의 물리 상태가 아니다.

### 2.4 OBSERVER — 이름 붙이는 층
Observer는 계산 결과를 보고 "결합처럼 보임 / 분자로 분류 가능 / 이온화로 분류 가능 / 반응 발생 / 막 비슷한 구조"라고 기록할 수 있다.
Observer의 판단이 다시 WORLD 계산을 바꾸면 안 된다. 방향은 `WORLD → Observer` 한쪽이다.

## 3. No Orphaned Physics — 억울하게 사라지는 물리를 만들지 않는다
이 계약에서 가장 중요한 규칙이다. 비용을 줄이기 위해 어떤 물리적 영향이나 가능한 경로를 근거 없이 삭제하지 않는다. 금지 예:
```
값이 작아 보임 → 0으로 처리
지금 별일 없어 보임 → 계산 중단
반응 가능성이 낮아 보임 → 경로 삭제
멀리 떨어져 있음 → 영향 없음으로 처리
계산하기 너무 비쌈 → 없는 물리로 취급
```
모두 금지다.

## 4. 직접 계산하지 않을 수는 있다
모든 영향을 반드시 같은 방법으로 직접 계산해야 한다는 뜻은 아니다. 단 다음 중 하나가 필요하다.
- A. 같은 결과임을 증명 (느린 계산 A, 빠른 계산 B, 모든 지원 입력에서 결과 동일)
- B. 실제 값을 반드시 포함하는 안전한 범위 (예: 실제 영향은 반드시 [0.0012, 0.0014] 안에 있음)
- C. 아래 물리로부터 검증된 상위 계산법. 단, 그 계산법이 무엇을 표현하지 못하는지도 명시해야 한다.

## 5. 안전한 범위는 "해결책"이 아니다
오차 범위나 상한을 들고 다닌다고 해서 문제가 해결된 것으로 보지 않는다. 작은 계산 1개 오차 ≤ 0.000001이어도 이런 계산이 백만 개 생기면 전체 불확실성이 커질 수 있다.
따라서 작은 세계에서 오차가 작았다는 이유로 큰 세계에서도 작다고 가정하지 않는다. 세계 크기, 입자 수, 시간, 상호작용 수가 증가하면 오차가 어떻게 증가하는지 별도로 조사한다.
오차가 너무 커져 결과를 결정할 수 없으면 `REFINE` 또는 `STOP` 한다.

## 6. 오차는 세계 상태가 아니다
```
WORLD: 실제 물리 상태
COMPUTER: 현재 계산값 + 이 계산이 실제 값과 얼마나 다를 수 있는지에 대한 증거
```
예: 계산값 = 100.01, 확실한 범위 = [100.00, 100.02]. 여기서 [100.00, 100.02]는 세계가 실제로 퍼져 있다는 뜻이 아니다. 컴퓨터가 아직 어디까지 아는지를 나타내는 증거다.

## 7. 오차 원인을 섞지 않는다
다음 오차는 따로 기록한다.
```
물리 모델 자체의 한계 / basis·표현 공간 한계 / 수치 계산 오차 / 압축 오차 / 시간 진행 오차 / 상위 유효 모델 오차
```
금지: "어차피 basis가 좀 틀리니까 압축도 좀 틀려도 됨." 기존 오차가 새 오차를 공짜로 허용하지 않는다.
필요하면 마지막에 전체 안전 범위를 계산하지만, 원인별 장부는 계속 따로 유지한다.

## 8. 핵 상태는 반드시 필요하지만 형식은 아직 미결이다
최소한 세계에는 핵에 대한 정보(종류 Z, 동위원소/질량, 위치, 운동 상태)가 필요하다.
핵을 고전적인 입자(위치·운동량)로 볼 것인가, 핵 자체도 양자 상태로 볼 것인가는 미결이다.
현재 계약: 아직 어느 쪽도 최종 승인하지 않는다. 정적 H₂ 시험은 핵을 고정했을 뿐, 실제 핵 운동 법칙을 승인한 것이 아니다.

## 9. 전자 수는 세계가 알아야 한다
Electronic Sector Panel에서 같은 핵 배치라도 전자 1개 / 전자 2개가 서로 다른 문제라는 것을 확인했다. 따라서 `N_e = 전자 수`는 세계의 기본 정보 후보로 유지한다.

## 10. 총전하는 중복 저장하지 않는다
고립된 계에서 총전하 = 핵 전하 합 − 전자 수. 같은 정보를 N_e, Q 두 군데 독립적으로 저장해 서로 모순될 가능성을 만들지 않는다.
현재 isolated-world 계약에서는 `N_e = 기본 정보`, `Q = 계산해서 얻는 값`. 향후 전자 저장고·외부 세계 경계 등이 생기면 별도 재검토한다.

## 11. 전자 밀도만으로는 부족하다
두 전자 상태가 현재 전자 밀도는 같음에도 불구하고 시간이 지나자 미래 쌍극자 값이 달라짐을 확인했다.
따라서 전자 밀도만을 WORLD의 전체 전자 상태로 사용하지 않는다. 밀도는 Observer 정보나 계산 보조 정보가 될 수 있다.

## 12. 실제 전자 상태가 필요하다
현재 가장 보수적인 후보는 `핵 상태 + 전자 수 + 실제 electronic quantum state + 물리 법칙`이다.
전자 상태를 어떤 자료형(dense wavefunction / tensor representation / 다른 동등한 표현)으로 저장할지는 미결이다. 필요한 것은 표현 형식이 아니라 물리적 정보를 잃지 않는 것이다.

## 13. spin / sector 이름도 세계에 함부로 박지 않는다
static pilot에서는 singlet / triplet 구분이 필요했다. 하지만 최종 WORLD에 `sector = singlet`이라는 이름표를 반드시 저장해야 한다는 뜻은 아니다.
실제 full electronic state에서 그 성질을 알아낼 수 있다면 sector는 계산 공간 선택 정보 또는 Observer/derived 정보가 될 수 있다. 최종 저장 방식은 미결이다.

## 14. 과거 전체는 세계 상태에 넣지 않는다
현재 닫힌 전자계에서는 현재 완전한 상태 + 현재 법칙이 있으면 이후를 계산할 수 있었다.
```
CURRENT STATE → 물리 계산
HISTORY → 기록 / replay / audit
```
과거 trajectory를 저장하지 말라는 뜻이 아니다. 단, 과거 전체를 다음 물리 계산의 숨은 입력으로 만들지 않는다.

## 15. 핵이 실제로 움직이는 문제는 아직 미해결이다
지금까지 H₂는 사실상 핵을 특정 위치에 세워두고 사진을 찍은 시험이었다. 핵이 접근 → 충돌 → 전자 상태 변화 → 핵이 다시 이동하는 실제 동적 세계를 검증하지 않았다.
따라서 다음 일반 계산기 설계에서 반드시 "핵은 어떻게 움직이는가?"를 별도 Gate로 결정해야 한다.

## 16. 싼 핵 운동 모델이라는 이유만으로 선택하지 않는다
판정 순서: 어떤 물리를 표현하는가? → 어떤 물리를 버리는가? → 버린 물리가 현재 세계 범위에서 실제로 필요한가? → 그 뒤 계산비 비교. 비용은 마지막이다.

## 17. 에너지가 빠져나갈 길을 반드시 조사한다
원자들이 충돌해서 안정적인 구조가 생기려면 남는 에너지가 다른 곳(다른 입자, 다른 자유도, 전자 상태, 전자기 복사)으로 이동해야 할 수 있다. 세계에서 어떤 에너지 이동 경로를 지원하는지 명시해야 한다.
빛을 구현하지 않은 세계에서 어떤 구조가 형성되지 않았다면 "현실에서도 형성 안 됨"이라고 결론내리면 안 된다. 정확한 판정: `해당 에너지 방출 경로가 현재 WORLD에서 UNSUPPORTED`.

## 18. 전자기장 / 빛은 아직 미결이다
현재까지의 정적 전자구조 pilot은 실제 빛의 방출·흡수를 계산하지 않았다. 전자기장을 WORLD의 기본 상태로 넣을 것인가, 어떤 수준으로 넣을 것인가는 별도 설계자 결정 사항이다. 빛을 빼고도 모든 화학을 지원한다고 주장하지 않는다.

## 19. 계산용 전자 공간이 물리를 가두면 안 된다
finite basis는 전자가 움직일 수 있는 컴퓨터상의 "그릇"이다. 그 그릇이 아주 멀리 퍼지는 전자, 원자에서 떨어져 나가는 전자, 강한 장에서 변형되는 상태를 표현하지 못할 수 있다.
따라서 계산 표현이 지원하지 않는 상태를 물리적으로 불가능한 상태라고 부르지 않는다.

## 20. 표현 범위를 벗어나면 FAIL-CLOSED
"현재 계산 표현으로는 이 상태를 신뢰할 수 없음"이 감지되면 계산을 계속하면서 조용히 근사하지 않는다. 허용: 더 넓은 표현으로 전환, 또는 STOP / UNSUPPORTED.

## 21. "표현할 수 없음"과 "현실에 없음"을 구분한다
```
NOT OBSERVED  현실 가능성은 열려 있지만 이번 실행에서 안 나타남
UNSUPPORTED   현재 계산기가 그 현상을 표현할 수 없음
REFUSED       계산할 자원이 부족하거나 검증을 끝내지 못함
INVALID       물리/수학적으로 잘못됨
```
이 네 가지를 섞지 않는다.

## 22. 계산 방법 때문에 현상을 막았는지 항상 확인한다
새 계산법을 넣을 때 반드시 묻는다: 이 방법이 현실에서 가능한 어떤 상태나 경로를 처음부터 없애지는 않는가?
```
빛 없음 → 방사 경로 차단 가능
좁은 basis → 이온화 차단 가능
고정된 bond → 새로운 결합 차단
항상 ground state 선택 → excited-state history 차단 가능
평균 힘만 사용 → 갈라지는 핵 경로를 하나로 합칠 가능성
```
이런 경우를 숨기지 않는다.

## 23. 계산 속도를 이유로 세계 물리를 바꾸지 않는다
금지: 너무 느림 → 전자 상태 제거 / excited state 제거 / 빛 제거 / 작은 coupling 삭제.
먼저 같은 물리를 더 싸게 계산할 방법을 찾는다. 정말 불가능하면 지원 범위를 줄이는 문제는 설계자 판단으로 올린다.

## 24. Hotline의 위치
Hotline은 중요한 사건 탐지기가 아니다. 금지: 결합 같아 보임 → HOT / 생명 같아 보임 → HOT / 특이한 구조 → HOT.
Hotline이 있다면 역할은: 현재 계산 표현으로는 모든 물리 영향을 안전하게 보존한다고 증명할 수 없을 때 더 자세한 계산을 요청하는 것이다. Hotline은 다른 계산 삭제, 다른 영역 정지 권한이 없다.

## 25. Hotline이 계속 울리면 계산법 실패다
세계가 커졌을 때 대부분 영역에서 계속 REFINE이 필요하다면 Hotline을 더 복잡하게 만드는 것이 아니라 현재 계산 구조가 확장성에 실패했다고 판단한다.

## 26. 정확한 분수와 실제 물리를 구분한다
현실 물리식에는 sqrt, exp, sin, 복잡한 양자 시간 진화처럼 정확한 유리수 하나로 바로 표현되지 않는 값이 있다.
따라서 실제 세계 값 자체를 억지로 분수로 바꾸지 않는다. 대신 "정확한 실제 값은 모르지만 반드시 이 두 수 사이에 있다"(예: 0.12345670 < 진짜 값 < 0.12345672)처럼 계산하고, 이 경계를 exact integer/rational로 검증할 수 있다.

## 27. 결과가 하나로 결정되지 않으면 계속 계산한다
예: 결과 경계 = 100, 현재 계산 99.99 ~ 100.01이면 어느 쪽인지 모른다. 따라서 진행 금지 → 더 정밀하게 계산 → 그래도 안 됨 → STOP. 임의로 한쪽을 선택하지 않는다.

## 28. 작은 세계에서 잘됐다고 큰 세계에 적용하지 않는다
핵 2개, 전자 2개, 시간 10 step에서 잘됐다고 핵 10,000개, 전자 수만 개, 긴 시간에서도 된다고 주장하지 않는다.
확인 대상: 상태 크기 증가 / CPU 증가 / RAM 증가 / 저장량 증가 / 오차 증가 / 검증 비용 증가.

## 29. H₂의 새로운 역할
H₂는 앞으로 benchmark / regression / counterexample / numerical diagnostic 용도로만 유지한다. H₂를 실제 WORLD의 목표로 삼지 않는다. 새 계산기가 H₂에 최적화되지 않게 한다.

## 30. 작은 일반 세계의 조건
금지: 분자 이름 / bond graph / reaction table / H2 생성 명령 / 안정구조 강제.
허용 입력: 핵 종류 / 초기 핵 상태 / 전자 수 / 초기 전자 상태 / 승인된 기본 법칙 / 승인된 boundary.
그 뒤 무엇이 생기는지는 계산 결과다.

## 31. 첫 일반 세계에서 확인할 것
처음부터 생명이나 거대한 화학계를 만들지 않는다. 작은 세계에서 먼저 확인한다.
```
핵과 전자가 실제로 시간에 따라 움직이는가?
에너지/운동량 장부는 맞는가?
전자 상태가 정상적으로 변하는가?
현재 표현 범위를 벗어나면 잡아내는가?
지원되지 않는 현상을 없는 현상으로 잘못 보고하지 않는가?
특정 분자 이름 없이 실행 가능한가?
```

## 32. 첫 일반 세계의 성공 조건
성공은 "H2가 생김"이 아니다. 성공은: 결과를 강제하지 않았고, 승인된 물리적 가능성을 계산 방식이 몰래 제거하지 않은 상태에서 세계를 실행할 수 있음이다.
결과가 산란 / 포획 / 일시적 구조 / 이온화 / 아무 구조도 없음 무엇이든 유효할 수 있다.

## 33. 실패 조건
다음은 근본 실패다.
```
필요한 물리 경로를 계산 편의로 삭제
표현 불가능한 현상을 "발생 안 함"으로 보고
계산 불확실성을 세계 상태인 것처럼 취급
결과가 마음에 들지 않아 상태 보정
결과를 만들려고 초기조건/법칙 조정
Observer 이름표가 세계 물리에 되먹임
지원하지 않는 영역에서 조용히 외삽
비용이 커졌다고 정확성 목표를 몰래 낮춤
```

## 34. 현재 확정된 것
```
분자 ID는 기본 세계 상태가 아니다.
bond ID는 기본 세계 상태가 아니다.
reaction ID는 기본 세계 상태가 아니다.
핵 정보만으로 전자 문제를 정할 수 없다.
전자 수 정보가 필요하다.
전자 밀도만으로 동적 전자 상태를 충분히 표현할 수 없다.
과거 전체 trajectory를 현재 물리 상태로 넣을 필요성은 확인되지 않았다.
H₂ static pilot은 benchmark이며 foundation 자체가 아니다.
```

## 35. 아직 확정하지 않은 것
```
핵을 고전적으로 계산할지 양자적으로 계산할지
전자기장/빛을 어디까지 WORLD에 포함할지
실제 전자 상태의 최종 representation
전자와 핵을 함께 어떻게 시간 진행할지
이온화/멀리 퍼지는 전자를 지원하는 계산 공간
spin을 WORLD에서 어떤 방식으로 표현할지
전자-핵-빛을 포함한 에너지 장부
큰 세계에서 사용할 상위 유효 모델의 승인 조건
```
이 항목을 구현자가 임의로 확정하지 않는다.

## 36. 다음 Gate
바로 대형 코드를 작성하지 않는다. 다음 Gate의 목적은 "일반 핵·전자 세계를 움직이기 위해 반드시 결정해야 하는 물리 선택"을 하나씩 닫는 것이다. 우선순위 후보:
```
1. Nuclear State / Dynamics Gate
2. Electromagnetic / Energy-Exit Gate
3. Electronic Representation Domain Gate
4. Coupled Electron–Nuclear Evolution Gate
```
순서는 실제 의존성을 검토한 뒤 정한다.

## 37. 최종 원칙
A는 H₂를 만들지 않는다. A는 분자를 만들지 않는다. A는 생명을 만들지 않는다.
A는 현실에서 허용되는 기본 물리적 자유도와 법칙을 가능한 한 보존해서 계산한다. 그리고 무엇이 나타나는지는 세계가 결정한다.
계산량 때문에 어떤 가능성을 제거해야 한다면, 그것은 최적화가 아니라 지원 범위 변경이며 설계자 판단 대상이다.

## 38. 계약 상태

이 문서 자체로 핵 dynamics 승인, 전자기장 승인, production foundation 승인이 이루어진 것은 아니다. 각 미결 항목은 별도 Gate를 통과해야 한다.

# ④-4c-9 — shell 16 hard-case 탐색 전수 조사 v1

**2026-09-28. 상태: survey_only.** 인증서를 만들지 않았고 Certified 판정도 없다. coverage는 **13/64·gap 82** 그대로다.

> **설계자 판정 — ④-4c-9**
> shell 16은 인증에 앞서 survey_only 전수 조사를 수행한다. 목적은 hazard 탐색, checker 교차검증, 후보 밀도 및 실제 계산 비용 측정이다. 이 단계의 결과는 coverage 또는 certification status를 변경하지 않는다. shell 16 인증 여부와 shell 15 진입 여부는 본 실측 결과 이후 별도로 결정한다.

> **설계자 판정 — ④-4c-10 (본 조사 결과 판독)**
> shell 16 survey에서 관측된 후보 밀도 증가는 보간 오차 δ 증가와 일관된 비용·탐색 현상으로 해석한다. **이 해석은 향후 비용 추정에만 사용하며 certification 또는 soundness의 증거로 사용하지 않는다.**
> shell 16은 hazard 0, checker 1024/1024 일치, brute-force 누락 0, 구조적 불일치 없음, 병렬 효율 유지, 메모리 문제 없음, 예측 비용과 실측 비용의 일치가 확인되었으므로 기존 hard-case certificate 계약으로의 승격을 승인한다.
> shell 15는 승인하지 않는다. shell 16 certificate와 fresh coverage, 실제 인증 비용을 확인한 뒤 별도로 판단한다.
>
> 즉: **δ 증가 → 후보 밀도 증가는 현재 설명 가능한 관측 패턴이며, 후보 밀도 증가가 항상 이 법칙을 따른다는 증명이 아니다.** shell 16 인증 결과는 [④-4c-10 문서](C1B1_HARD_CASE_CERTIFICATE_SHELL16_V1.md)를 본다.

## 실행

- 원격 노드: AMD Ryzen 9 5950X, 물리 16코어·32스레드, 작업자 32. 01:54:53 시작, 02:14:39 종료(서버 시각).
- 생성기·checker·정책(quadratic, L=2^34, superblock 1024)은 shell 18·17과 같다. 작업 함수는 shell 17 조사 driver의 것을 그대로 불렀고, 그 driver는 수정하지 않았다.
- **같은 기계 기준선:** shell 17 조사를 같은 기계·같은 작업자 수로 다시 돌렸다. 기존 shell 17 조사는 로컬 6코어에서 쟀기 때문에, 이 기준선이 있어야 증가율과 교차당 비용을 같은 조건에서 비교할 수 있다.
  - 재실행한 shell 17의 superblock 1024행은 기존 fixture와 **완전히 같다**(리눅스↔Windows 재현 확인도 겸함).

- 후보 수는 교차 수가 아니라 **블록 보간 오차 δ에 비례하는 기존 휴리스틱**을 거의 일정한 비율로 따라간다.
- shell이 내려갈수록 도함수가 커져 δ가 shell마다 약 8배(2^-49→2^-45→2^-42) 커진다. 그래서 교차당 후보 비율이 올라간다.

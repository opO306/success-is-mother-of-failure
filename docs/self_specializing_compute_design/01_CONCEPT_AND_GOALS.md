# 01. 개념과 목표

## 1. 문제 정의

일반적인 프로그램은 사람이 정한 계산 방법을 반복해서 실행한다.

예:

```text
입력 x
  ↓
복잡한 계산 F(x)
  ↓
결과 y
```

하지만 실제 사용 환경에서는 다음과 같은 비효율이 생길 수 있다.

- 같은 계산 패턴이 매우 자주 반복된다.
- 전체 계산식은 복잡하지만 내부에 독립적인 부분이 많다.
- 일부 중간 결과가 반복 계산된다.
- 특정 입력 범위에서는 계산을 더 단순하게 만들 수 있다.
- CPU에서는 비효율적이지만 GPU에서는 잘 맞는 부분이 있다.
- 반대로 분기 중심 계산은 GPU보다 CPU가 유리할 수 있다.
- 특정 함수는 LUT 또는 전용 회로로 만드는 편이 더 빠를 수 있다.

현재의 컴파일러도 이런 문제를 상당 부분 해결하지만, 보통은 미리 정의된 변환 규칙과 비용 모델에 의존한다.

이 설계가 목표로 하는 것은 더 공격적이다.

> 실제 실행되는 계산을 관찰하고, 계산 방법 자체를 자동으로 재설계한 뒤, 원래 계산과 동등함을 검증하고, 더 효율적이면 채택한다.

---

## 2. 시스템의 최상위 목표

### 목표 G1 — 정확성을 유지한 자동 계산 개선

원래 계산:

```text
F(x)
```

후보 계산:

```text
G(x)
```

최적화 시스템은 G를 찾을 수 있지만, 실제 채택 조건은 반드시 별도 검증을 통과해야 한다.

개념적으로:

```text
모든 허용 입력 x에 대해
F(x)와 G(x)가 요구한 동등성 기준을 만족
```

해야 한다.

---

### 목표 G2 — 전체 식이 아니라 계층적 계산 구조를 최적화

긴 계산을 다음처럼 본다.

```text
F
├─ A
├─ B
│  ├─ B1
│  └─ B2
└─ C
```

각 부분은 서로 다른 최적화 전략을 사용할 수 있다.

예:

- A: 식 단순화
- B1: SIMD
- B2: GPU
- C: LUT
- 전체 F: 병렬 스케줄링

---

### 목표 G3 — 최적화 종류를 하나로 제한하지 않음

시스템이 탐색할 수 있는 개선은 다음을 포함한다.

- 연산 수 감소
- 공통 부분식 제거
- 상수 접기
- 계산 순서 변경
- 병렬화
- 벡터화
- 캐싱
- 메모리 배치 변경
- LUT 변환
- 입력 범위별 특화
- CPU/GPU 간 배치
- 장기적으로 FPGA/재구성 회로 합성

---

### 목표 G4 — 실행 환경에 따라 특화

"보편적으로 가장 좋은 코드"보다 다음을 중요하게 본다.

> 현재 하드웨어와 실제 입력 분포에서 가장 좋은 검증된 구현

같은 함수라도:

```text
노트북 CPU
RTX GPU
서버 CPU
FPGA
```

에서 최적 구현은 다를 수 있다.

## 3. 비목표

초기 버전에서는 다음을 목표로 하지 않는다.

- 새로운 CPU ISA 설계
- ASIC 제작
- 임의의 거대한 프로그램 전체 자동 최적화
- 근사 신경망으로 원본 함수를 대체
- 검증 없이 벤치마크만 보고 최적화 채택
- 모든 종류의 부동소수점 변환 허용

첫 버전은 **작고 명확한 계산 블록**만 대상으로 한다.

## 4. 핵심 구분

### 4.1 공식이 짧다 ≠ 실행이 빠르다

예:

```text
A + B + C + D
```

각 부분이 10 연산이고 더 줄일 수 없더라도,

```text
순차 실행: A → B → C → D
```

보다

```text
A ┐
B ├ 동시에 계산
C ┤
D ┘
```

가 더 빨리 끝날 수 있다.

즉:

- **work**: 총 작업량
- **latency**: 끝날 때까지 걸리는 시간

을 분리해야 한다.

---

### 4.2 수학적으로 같다 ≠ 컴퓨터에서 같은 결과다

예를 들어 실수 수학에서는:

```text
(a + b) + c = a + (b + c)
```

이지만 IEEE-754 부동소수점에서는 반올림 순서 때문에 결과 비트가 달라질 수 있다.

따라서 시스템은 어떤 의미의 "같다"를 요구할지 먼저 정해야 한다.

이 문제는 `03_EQUIVALENCE_AND_VERIFICATION.md`에서 다룬다.

## 5. 최종 형태

장기적인 최종 그림은 다음과 같다.

```text
              ┌─────────────────┐
              │ 원본 프로그램    │
              └────────┬────────┘
                       ↓
              ┌─────────────────┐
              │ 실행 프로파일러  │
              └────────┬────────┘
                       ↓
              ┌─────────────────┐
              │ 계산 그래프 IR   │
              └────────┬────────┘
                       ↓
       ┌───────────────┼────────────────┐
       ↓               ↓                ↓
   식 최적화       병렬/메모리 최적화    하드웨어 매핑
       ↓               ↓                ↓
       └───────────────┼────────────────┘
                       ↓
              ┌─────────────────┐
              │ 후보 구현 생성   │
              └────────┬────────┘
                       ↓
              ┌─────────────────┐
              │ 독립 검증기      │
              └────────┬────────┘
                       ↓
              ┌─────────────────┐
              │ 비용 측정/선택   │
              └────────┬────────┘
                       ↓
                 검증된 구현 채택
```

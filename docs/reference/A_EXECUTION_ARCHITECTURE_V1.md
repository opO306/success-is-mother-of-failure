# A 실행 아키텍처 v1 — 물리와 실행 기술의 분리 (상위 원칙 초안)

**문서 분류: 공통 참조 원칙·검증 기준.** 승인·초안·구현·보류의 범위는 본문 판정을 그대로 따른다. 이 폴더 배치는 새 승인이나 동결이 아니다.
현재 상태는 [CURRENT_STATE.md](../../CURRENT_STATE.md)를 본다.


**상태:** **승인 (2026-09-24), X1~X5.** 설계자·sol 논의(외부 LLM 제안 검토 포함)를 구현자 의견과 함께 정리. RULES 반영.
**한 줄:** 세계는 물질과 관계로 구성하고, 칸·묶음·GPU·캐시·해상도 전환은 **세계를 빨리 계산하는 기술로만** 존재한다.
계산 방법이 바뀌었다고 세계의 물리가 바뀌면 안 된다.

---

## 1. 두 영역

```
물리 (세계의 법칙)                     실행 (계산 기술)
─────────────────────                 ─────────────────────────────
미시 요소, 결합, 구조                   공간 색인 (grid / hash / tree / BVH / 동적 묶음)
위치·운동량·시간·접촉                    CPU / GPU 분업, 스케줄링
                                       캐시, 정확한 요약(강체 한 몸 계산)
                                       다중 해상도 (장기)
                                       외부 분석기의 최적화 제안
```

**규칙:** 실행 쪽 어떤 것도 물리적 결과를 **결정**하지 않는다. "녹았다", "쪼개졌다" 같은 말은 상태를 본 **관찰자의
해석**이지 CPU가 내리는 판정이 아니다(헌법 제18조와 같은 원리 — 해석이 세계에 되먹이지 않는다).

---

## 2. 구현자 의견 1 — 기준 실행기를 영원히 남긴다 (이 아키텍처의 집행 장치)

"결과가 같아야 한다"를 말로만 두면 언젠가 깨진다. 그래서:

> **기준 실행기(reference executor)** — 색인 없음(모두 서로 검사), 캐시 없음, 요약 없음, 단일 스레드, 유리수 그대로.
> 느리지만 명백히 법칙 그대로인 구현을 **삭제하지 않고 유지**한다.

모든 최적화는 (1) 끌 수 있어야 하고 (2) 작은 세계들에서 기준 실행기와 **같은 세계 결과**를 내야 채택된다(차등 검사).

**같음의 정의 (설계자 결정):** 메모리 표현의 비트가 아니라, **정규화한 세계 상태 + 정규화한 사건 이력 + 인과 결과**를
직렬화한 것이 정확히 같아야 한다. Python과 CUDA는 내부 자료 배치가 다를 수 있다 — 구현 표현이 아니라 **세계의 의미가
완전히 같아야** 한다. 정확한 분수를 쓰므로 이것을 강하게 보장할 수 있다. 지금 CPU/GPU 동등성 테스트가 이미 이 방식이다 — 그것을 모든 최적화로 넓힌다.

## 3. 캐시 — 정확히 같은 계산만

**금지:** "순도 80%·1200도·10초 → 결과 저장 → 다음에 재사용" 같은 **겉보기 조건 캐시.** 평균 순도·평균 온도가
같아도 내부 균열·결정 배열·불순물 위치·충격 이력이 다르면 결과가 다르다. 숨은 미시 상태를 지우는 것이고
헌법 제2조(과정 보존)와 충돌한다.

**허용:** 완전히 같은 물리 입력이면 같은 결과를 재사용: `hash(정확한 국소 상태 + 경계 입력 + 법칙 버전)`.

**구현자 의견 2 — "경계"의 정확한 범위:** 국소 상태만 해시하면 틀린다. 시간 T 동안 한 영역의 결과에 영향을 줄 수 있는
것 전체 — **인과 영향 반경(causal influence radius)** — 을 담아야 한다. 지금 물리는 이동뿐이라 최대 속도 × T와 같지만,
열 전달·힘·파동이 생기면 계산법이 달라진다. 이름을 이동 반경이 아니라 인과 영향 반경으로 두는 이유다. 지역성(최대 이동 거리)이 명세로 선언돼 있어야 이 범위가
유한하고, 그래야 정확한 캐시가 가능하다. 캐시 키는 그 범위 전체를 담아야 한다. 이것도 2절의 차등 검사로 확인한다.

## 4. 다중 해상도 — 지금은 정확한 요약만 (v5 2판 S8, 승인됨)

장기 그림(sol): MACRO(물체) ↔ MESO(결정립) ↔ MICRO(원자)가 서로 다른 세계가 아니라 **같은 물리 상태의 다른 계산 표현**.
평온한 곳은 거칠게, 사건이 나는 곳(망치로 친 곳)만 세밀하게.

**구현자 의견 3 — 망치 예시는 지금 허용 범위 밖이다.** "내부 응력 요약"으로 계산하다가 균열 지역만 펼치는 것은
**손실 요약**이다. 펼칠 때 미시 상태를 지어내야 하고, 결과가 "언제 펼쳤나"(계산 편의)에 달라진다. 그래서 단계를 둔다.

| 단계 | 허용되는 것 | 조건 |
|---|---|---|
| 지금 | 정확한 요약 — 강체 한 몸 계산, 정확한 캐시. **실제 구성요소는 항상 남아 있다** | 기준 실행기와 정규화한 결과 동일 |
| 나중 | 요약 경로를 **추가**하되 실제 구성요소도 유지 (요약은 빠른 길일 뿐) | 기준 실행기와 동일 |
| 장기 | 손실 요약(구성요소를 실제로 버림) | "어떤 정보를 버려도 물리 결과가 달라지지 않는가"를 **실험으로 증명**한 경우만 — 신체 계약 7절의 아래로 내려가는 원칙 검증 |

## 5. CPU / GPU

| | 역할 | 금지 |
|---|---|---|
| GPU | 대량 병렬 계산 (지금은 환경 field) | 결과를 바꾸는 부동소수점 |
| CPU | 작업 분배·스케줄링·검증·사건 기반 입자 계산(v5) | **물리적 결과 판정** ("이제 녹았다") |

v5의 사건 기반 유리수 계산은 GPU에 맞지 않는다([A_MICRO_V5_KINEMATICS_TIME_V1.md](../history/A_MICRO_V5_KINEMATICS_TIME_V1.md) 4절). GPU를 쓰는 것이
목표가 아니라, 같은 결과를 더 빨리 내는 것이 목표다.

## 6. 외부 분석기 — 제안만, 물리 변경 권한 없음

```
실행 기록 → 분석기 → "여기 비효율적", "이 영역은 강체로 묶을 수 있어 보임", "이 캐시 패턴 사용 가능"
         → 제안서
         → 기준 실행기와 차등 검사 통과
         → 설계자 승인
         → 채택
```

**금지:** 분석기가 세계 코드를 자동으로 고치고 계속 실행하는 것. 어느 순간 최적화가 법칙을 바꿨는지 알 수 없게 된다.
(B가 A를 고치지 못하는 것과 같은 원리 — 실행 최적화도 세계를 몰래 바꾸면 안 된다.)

## 7. 기록

원본 상태 변화와 함께 **어떤 최적화 경로(색인·캐시 적중·요약)가 쓰였는지**도 기록한다(설계자·감사 전용). 결과가
이상할 때 "최적화 때문인가"를 가려낼 수 있어야 한다.
